# 历史观测变化整理（试验性）

`summarize_changes` 将各 Pod 的 CPU 使用率及链路 P95 前后变化分别排列，并保留正负方向、缺失值和样本数量。排序只是为人工或模型阅读提供辅助，不是故障定位排名，也不证明相关性或因果关系；低采样数和请求构成变化会影响结论。

输入只包含观测摘要，不接收或读取故障真值。使用历史事故时间划分窗口属于回放设计，不能作为在线检测时间。独立的评估程序必须在输出冻结后核对标签，并分别报告对象和服务层级的匹配。

该模块当前尚未接入诊断主流程。已知样本开发回放中，添加变化摘要后首位对象与标签一致；另一日期的独立单例未命中，不能据此宣称准确率提升。部署使用前仍需多样本、不同数据源和缺失数据条件下的独立验证。

`build_windows` 根据各模态独立的可用时间裁剪基线，保留覆盖时长，不能将时间范围视作数据完整性的证明。`assess_cpu_claim` 对结构化 CPU 变化或饱和声明检查样本数及调用方提供的阈值；缺少基线、样本或可信阈值时返回证据不足。`audit_primary_cpu_claims` 仅以有限规则审计首位对象的常见明确表述，可能漏检或误检，始终不授权自动动作；它不改变模型原文，也未接入生产门禁。

`compact_domains` 对该回放使用的窗口聚合格式进行结构化打包，以明确的字段顺序保留每个对象的数值、样本数、缺失值及质量记录。遇到未知字段或非有限数值时拒绝打包，避免静默丢失数据；调用者需另外传递时间窗口及其他顶层元数据。它只整理已聚合数据，不替代原始遥测；预算仍不足时仍须标记截断。该方法尚未接入生产诊断，模型效果需独立验证。

`assess_workload_surge` 仅在前后采样充足且调用方提供有依据的增长比例时比较负载速率，缺少条件时返回证据不足。`audit_primary_workload_claim` 只识别有限的请求激增表述，始终要求复核，不能证明过载或因果关系，也不能授权操作；该审计尚未接入生产门禁。

`audit_exclusion_claims` 对有限的明确排除机制表述提示复核；它不核验证据引用，也不能证明或否定所排除的机制。否定形式和未覆盖的表述仍可能漏检，不能以此授权操作。

`summarize_trace_spans` 从有界的原始 Span 记录提取按对象和操作划分的时延分位数，并按同一 Trace 中唯一的父子 Span ID 汇总观察到的对象关系；时延由纳秒起止时间计算。重复身份、缺失父 Span、无效记录和窗口长度均单独计数；父子关系不是已验证服务依赖，时延变化也不能直接证明根因。该汇总目前仅用于历史数据开发分析。
