# 告警压缩：事实、审核和诊断的边界

告警压缩先回答“本次读取的告警如何组织、哪些观测值得继续调查”。条数减少不等于语义正确、共同根因成立或故障已经恢复。系统分别记录原始输入、分组、候选关联、证据检查、模型审核和诊断结果；候选关系不直接变成告警抑制规则。

## 完整链路与当前契约

| 环节 | 当前实现与检查 | 仍需区分的边界 |
| --- | --- | --- |
| 采集与导入 | 实时 Prometheus/Kubernetes 并行采集，记录失败、截断与范围；导入最多 10,000 条，不能冒充实时扫描 | 保留全部输入记录不等于观测源已返回全部告警；不完整扫描不能判断业务恢复 |
| 对象与时间 | 按集群、命名空间、对象类型/名称、状态、观测维度和有界时间窗分组；显式目标 UID 隔离资源重建实例 | UID 来自告警记录，仍须实时核验；没有 UID 不能推断唯一实例 |
| 符号压缩 | 保留原文、严重级别变化及数值极值，限定掩码不吞掉已知状态码、版本、目标与否定词 | 模板相同不证明因果相同；规则边界由测试覆盖，不能泛化为自然语言等价证明 |
| 测量合并 | 仅在已有实时指标、嵌套阈值、同一失败 Span 或请求窗口的限定条件成立时归并 | 保留各测量，不将多个指标强造为一条时间序列；同一观测不证明根因 |
| 候选检索 | 有界局部/向量检索，保留截断和候选覆盖范围 | 未召回不表示无关；检索相似度不是根因概率 |
| 关联审核 | 有限模型预算、明确引用两端原始告警，记录响应完成状态及失败、待审候选 | 角色模型可以出错；没有完成审核的候选不能被当作“已判无关” |
| 结构、时间与统计检查 | 已有 SCAG 结合实际证据限定关联；不同/冲突资源实例不能仅按同名得到结构通过 | 检查通过仍不是因果证明；拓扑按名称建立时尤其需要实例限定 |
| 作业与恢复 | SQLite 作业、批次检查点、预留预算、单 worker 锁、原子结果发布；恢复复用已准备快照和原预算 | 预算预留不等于真实账单；旧版本无 token 回执时不补造费用 |
| 人工调整 | 拆分/合并要求原因、版本一致、同集群/命名空间和时间窗；保护实例边界 | 编辑后的新分区没有继承旧关系审核资格，需要重新扫描和审核 |
| 原文回查 | 同一扫描/分组/revision 分页读取完整原文，提供快照指纹；过期 revision 返回 409 | 不是历史任意版本永久存储；诊断保存启动时证据快照 |
| 诊断交接 | 证据包保留范围、目标 UID、样本、极值与遗漏说明；有界提示传递完整字段，不切断 JSON | 告警分组不是已确认根因；仍受独立诊断审核和动作门禁约束 |
| 页面与历史 | 分别显示结构校验、资源 UID、审核失败/待审、编辑失效、原文与诊断入口 | 旧记录缺少凭据时明确未记录，不补造过去已经通过的结论 |

## 资源重建与身份冲突

标准化输入从显式 `entity_uid`、`object_uid`、对应类型的 `pod_uid` 等字段，以及匹配目标类型、名称、命名空间的 Kubernetes Event `involvedObject`/`regarding` 中读取 UID。Event 自身的 `metadata.uid` 表示事件记录身份，不能当作 Pod UID。旧实例、新实例、UID 已知与未知分别保留；同一记录提供冲突 UID 时保留为单独观测，不让整个扫描失败，也不自动选一个 UID。

相同名称、不同 UID 的自动阈值/Trace/窗口合并会被挡住，人工合并同一对象不同实例同样被拒绝。明确跨对象的人工事件组织仍可在原范围和时间门槛内进行，但不会产生一个虚假的统一 UID。频率签名、非 Event 生命周期身份和证据包同样保留实例差异。已报告 UID 仍不是当前集群真值，诊断和执行前必须按原有流程取证。

## 分区完整性凭据

`integrity.schema=alert-partition-integrity/v1` 记录当前输入及分区的结构检查：每条原始记录恰好归属一组，索引为有效整数，成员 ID/数量一致，组 ID 唯一，代表记录属于该组，集群/命名空间一致，最高严重级别未降低，计数没有遗漏或重复。同步创建和异步发布都要通过检查，非法结果不能替换已保存的证据。

`raw_sha256` 表示标准化原文快照的内容指纹，`partition_sha256` 表示当前成员组织。人工拆分后原文指纹不变、分区指纹变化；这可以复核本次处理是否改变记录，不是外部签名、源端完整性证明或语义准确率。原文分页仍另有带 scan/group/revision 的快照指纹。

## 模型失败、预算与人工编辑

模型服务返回 401/402/403/404 时，当前审核停止后续批次，先保存本批失败检查点，其余候选明确待审。只保存固定类别、HTTP 状态码与异常类型，不持久化外部异常正文。服务恢复后，显式手动续跑可在同一作业剩余预算和期限内重试，不能重置已经预留的调用、输入或输出额度；预算不足时继续提供原始事实和待审清单。这个策略覆盖本轮的配置类 HTTP 拒绝，不是平台级健康监测或自动切换模型。

人工编辑把 `semantic.status` 置为 `invalidated_by_edit`、`coverage_complete=false`，移除不再适用于当前成员的批次审核。旧状态和累计调用数只作为前一版本摘要保留，原作业的预算与检查点记录仍可审计。页面不再为已编辑分区展示“重试旧审核”入口；后端原有检查也拒绝旧作业覆盖人工调整。已保存的 RCA 快照不被这次编辑改写。

## 编辑与恢复的版本契约

Web API 的告警作业绑定其实际结果存储。`GET /api/alerts/compression-jobs/{job_id}` 对已经发布的结果读取当前原子扫描快照：`review_revision` 为作业已发布的审核版本，`result_revision` 为当前分组版本；`review_applies_to_result` 表示两者仍适用。人工编辑后返回 `result_state=edited`、`can_resume=false`、`resume_blocked_reason=result_edited`，不把旧版成功/失败数量算作当前分组审核结果。结果缺失、损坏或版本无法一致核验时也阻断恢复，并区分 `result_unavailable` 和 `result_revision_changed`，不能用预算尚未耗尽掩盖版本问题。

该状态直接由当前扫描推导，不依赖另一份必须与编辑同时写入的 SQL 失效标志，因此重启或编辑后进程退出不会恢复旧审核资格。预算累计不重置；在途返回的批次记录仍按原作业保存，不能成为当前分组的审核依据。独立使用 `AlertJobs` 时，应传入相同 `CompressionStore` 作为 `output`；实际 Web 工厂已经配置此绑定，处理作业时也会绑定并拒绝不同结果存储。

恢复操作与人工编辑使用同一扫描文件锁，按“文件锁 → SQL 事务”的顺序判断版本并入队。编辑已经提交时，恢复返回 HTTP 409；恢复先入队、随后发生编辑时，worker 的检查和既有发布版本保护共同阻止覆盖新分组。审核调用在途时不能声称该请求已被取消：它返回后仍保存原版本检查点和调用记账，在下一批前检查编辑状态，取消旧作业的后续处理。原文和人工调整保留，后续批次不再发起。

页面明确标注前版本审核记录，刷新后不自动恢复旧审核。即使旧 worker 状态是 cancelled，仍能打开当前人工修改后的分组和证据包入口。该保证限于绑定的单扫描版本、当前单 worker/共享文件锁部署，不等于跨服务器分布式事务或外部模型调用撤销。2026-10-22 的并发、API、重启和页面验证见[编辑恢复验收](../outputs/alert-edit-resume-20261022/verification.md)。
