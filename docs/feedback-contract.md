# 专家反馈消费与规则版本契约

本轮实现对应 2026-10-22 反馈/记忆调研后的首个修复切片，代码尚未提交或部署到生产。目标是让反馈被准确消费，不把保存反馈或模型比较直接称为独立验证的诊断收益。更广的作用域、候选晋升和效果评估方案见[专项研究](research/feedback-memory-loop-20261022.md)。

## 当前行为

监督学习必须先拿到严格布尔 `correct`，并验证完整规则数组，才允许写第一条规则。字符串 `"false"`、缺失标签、非有限置信度、空条件/结论等无效输出不写规则、不计票。返回的 correctness 明确标记为 `model_comparison_to_expert_text`，并非人工直接签署的独立真值。

专家反馈必须匹配到原 pipeline trace 的实际诊断内容。未找到原记录、记录不可核验或显式指定的诊断版本失配时，只保存被阻断的反馈，不调用学习；这些记录也不进入下次诊断的近期专家反馈上下文。trace 的保留范围仍有限，Web 历史里能看到的旧事故不保证 trace 还在；此时保守阻断，不用占位诊断生成知识。

HITL 的 needs_more_evidence 不触发学习。approve/reject 可以在有明确专家文本、可匹配原记录和持久反馈通道时提交监督反馈；纯 approve 无文本不会学习，reject 不代表纠正答案必然错误。关闭的审核重复提交相同决策和文本时返回原结果；改写已关闭内容返回 HTTP409。当前没有在此入口自动重开审核或修订既有反馈。

## 持久反馈收据

`POST /api/knowledge/feedback` 保留 `incident_id`、`expert_diagnosis`、`comment`，新增可选字段：

| 字段 | 含义 |
| --- | --- |
| `event_id` | 调用者的稳定重试键，1–128 个字母、数字或 `_.:-`；同键改写学习内容返回409 |
| `diagnosis_revision` | 预期的诊断核心内容哈希；失配时返回已保存的 blocked_stale_diagnosis 收据，学习为零 |
| `rule_feedback` | 最多五条显式有用性判定，每条为 `rule_id`、原 `revision`、严格布尔 `useful` |

没有 event_id 的旧客户端使用规范化学习请求的稳定哈希去重，comment 变化不构成新的学习请求。显式事件与 HITL 内部事件使用不同命名空间。诊断变化后应明确提交新版反馈，不能把重试隐式升级为新一轮学习。

收据保存 feedback ID、请求哈希、诊断核心 revision、完整 trace 快照 SHA256、处理状态、模型对照标签来源、生成规则 ID 和逐规则投票结果。核心 revision 包含根因、论据、类型、目标、范围及显式支持引用，排除审核创建后才追加的完成遥测；完整 trace 哈希另行保留。服务端会快照提交时的诊断；可选 revision 允许调用者约束所针对的内容，旧客户端未提供时不能声称已经校验其之前在页面上看到的版本。

收据在学习或投票前原子落盘。模型调用不持有整份反馈账本的文件锁，读取状态不必等模型完成；完成时重新加载并按事件合并，避免覆盖其他反馈。相同事件的并发请求只消费一次。若处理或完成落盘中断，持久 claim 使同事件不自动重试，结果标为 outcome_unknown，未知规则/投票数量为 null，不伪装成零副作用。

这提供共享目录上的进程锁与保守重试语义，不是 Chroma、JSON、模型调用之间的分布式事务。未知结果需要另行核对；当前不自动补偿、撤销或恢复未知处理。已有旧反馈不会被批量迁移、重学或重投票，旧随机 ID 记录不因此自动获得新事件的重试保证。

## 规则投票与实际贡献

整案模型 correct 不再给全部召回规则投相同票。没有显式 rule_feedback 时，规则投票数为零，不能解释为此次没有召回规则。

新 RCA 保存 `recalled_rule_refs`，包含实际放入上下文的规则 ID 和内容 revision。显式规则判定必须先匹配这些原始引用，再在规则编辑共用锁内核对当前版本及 active 状态。旧 trace 没有引用、新内容已编辑、规则已停用或删除时，不把票转移到当前内容。一次用途投票不会再增加一次 usage_count；曝光、专家有用性和经对照测得的诊断贡献是不同信号。

`used_rule_ids` 暂时保留兼容，新增 `rule_usage_semantics=context_exposure_not_causal_contribution`，不能据这个旧字段证明因果贡献。旧演化计数的名称尚未全部迁移。本轮没有声称已经建立逐规则反事实收益归因。

JSON 规则新增和计数更新改为在规则锁内重新读取并原子保存；新增事故单独保存事故文件，不重写可能已变化的规则。Chroma 的重复规则提取也不覆盖同 ID 的已有人工编辑或票数。仍不能将这些局部修复概括成所有知识写入和管理入口均已完成事务化。

诊断统计按唯一 incident 去重，并说明标签来自模型对专家文本的比较、`independent_truth_verified=false`。它与业务恢复统计继续分离；同一事故的多次意见不作为多起独立事故。统计去重也不等于已实现反馈修订和撤销账本。

## 页面与接口边界

页面分别展示未匹配原诊断、诊断已变化、标签无效、处理中、结果待核对、模型对照完成和原收据重放，不再统一显示“学习成功”。收据重放不再次调用模型。HTTP409 表示事件或规则引用冲突，422 表示请求结构无效，503 表示本次反馈写入路径的存储不可用；保存了被阻断的反馈可以返回200，但不代表学习已执行。

反馈消费首轮没有实现全局记忆 scope/time 硬过滤、候选知识评测后晋升、撤销派生物传播、完整主体授权或跨事故效果改进证明。后续第二切片已为诊断消费者接入[范围与时间准入](memory-admission.md)，具体覆盖和兼容边界以该文档为准。通过现有门禁的自动/监督规则仍沿用原有激活方式；候选评测、撤销及收益证明仍待实现，不得把局部修复宣传成完整的可信自学习平台。

## 验证记录

后续第三切片已增加[候选隔离与人工版本审核](memory-candidates.md)。新提取和编辑后的规则进入候选，原始专家反馈不直接回注；实际新增按写入收据计数。人工审核启用并非独立评测晋升，撤销传播与收益验证仍未完成。

原始最小反例在远端为 **13 failed / 0.96s**，修复后通过。最终远端专项 **37 passed / 5 warnings / 1.32s**，关联 **116 passed / 5 warnings / 11.56s**，完整项目 **1904 passed / 7 warnings / 245.86s**；210 个运行时文件和114个测试文件在测试前后哈希一致，JavaScript 语法检查通过。模型与取证为受控数据，不计为真实事故准确率样本。

验收证据位于 `outputs/feedback-contract-20261022/` 及远端同名发布目录；实际 Chroma 后端、真实 HTTP/浏览器与重启检查的最终状态以该目录 verification.md 为准。生产服务没有被本轮候选替换。
