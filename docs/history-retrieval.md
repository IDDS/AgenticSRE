# 诊断历史检索的等待预算与降级语义

历史规则和相似事故只用于产生候选假设，不能成为当前事故已经发生的证明。多智能体与 Agent+Skill 的向量历史读取均使用 `memory.retrieval_timeout_s`，默认 5 秒；有效预算限定在 0–30 秒内，非法值使用 5 秒，多智能体还取模型总预算的剩余时间上限。等待额度包含取得读取资格、初始化历史库和读取两个集合。禁用记忆或未请求上下文阶段时不创建历史库。

一次多智能体诊断只生成一份历史读取快照，供上下文组装和假设生成复用；不会为两个消费者重复嵌入检索。Agent+Skill 保留既有规则、事故和近期运行的集群过滤规则。空集合仍先判空，避免无用嵌入；成功返回零项只说明没有返回匹配项，不能据此宣称库为空。

| 状态 | 含义 |
| --- | --- |
| `complete` | 两个集合均完成读取，包括合法空结果 |
| `partial` | 一个集合完成，另一集合异常或超时；保留已完成部分 |
| `unavailable` | 初始化、线程启动或两个集合读取失败 |
| `timed_out` | 等待预算耗尽，没有可采用的完整集合结果 |
| `busy` | 进程中已有历史读取未退出，本次在预算内未取得资格 |
| `disabled` / `not_requested` | 配置禁用 / 本次未请求 |
| `not_recorded` | 旧记录或自定义提供者未保存标准状态，不能倒推成功 |

元数据采用 `history-retrieval/v1`，包含各集合状态、返回数、等待预算和实际耗时，不包含原始异常或连接配置。错误用固定代码表示。事件、诊断返回、JSON 报告及 HTML 导出保留同一次读取的状态；历史回放和导出不重新查询历史库。页面切换清除旧状态，旧记录明确显示未保存。第三方提供者整体抛错时，Skill 不再发出“成功检索”事件。

底层原生调用或网络调用可能无法在线程内取消。实现限制的是诊断调用者等待时间及进程内在途读取数量：每个进程最多一个 daemon 读取任务，超时后该任务真实退出才释放资格；后续请求不会无限创建检索线程。超时晚返回的结果不能进入本次诊断或覆盖其快照。部分可用、超时或失败时，不把该历史库交给自动学习写入。正常读取后的学习仍受原质量门禁约束。

这不是所有上下文 I/O 的统一截止时间。专家反馈、领域提示、追踪、恢复统计和知识管理 API 的其他磁盘读取仍按原路径执行；任意自定义上下文提供者也没有被强制取消。daemon 不提供进程隔离，不能据此承诺底层 I/O 已终止。历史不可用不表示当前故障不存在，实时取证及独立审核不因降级而省略。
