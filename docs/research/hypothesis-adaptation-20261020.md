# 假设生成与诊断流程调整：研究和实施契约

本研究面向 AgenticSRE 使用者及技术评审，决策目标是让候选根因、证据修订和下一步调查可核验。范围为当前代码和 2026-10-20 可访问的一手资料；现有业务门禁继续执行。本阶段不以模型自评分证明准确率提升，不在生产环境试验未知变更，也不把单次调查调整称为模型训练或跨事故最优策略学习。

## 任务问题与判定标准

1. 初始候选来自模型、历史还是症状规则，能否分开显示？成功标准为明确标注来源，并保留初始排序和可反驳条件。
2. 假设的升降、确认、排除和新分支能否回查实际观测？成功标准为引用已保存的观测 ID；缺失、矛盾或伪造引用不能推动提前停止。
3. 重复采集、采集失败与反证是否区分？成功标准为仅采集时间/resourceVersion 改变不被视为新增差异观测；失败不自动成为反证。
4. 后续调查是否真正使用前轮结果？成功标准为根据缺口、已尝试来源和验证条件重新选择只读 Agent；保持总轮数和模型时间预算。
5. 两模式是否如实表达各自能力？多智能体支持有界重规划；Agent+Skill 在既有裁决调用中复核候选，不额外冒充已实现多轮 Skill 重规划或独立 Judge。
6. 效果如何证伪？若固定输入和预算下错误对象引用、错误确认、费用或超时上升，即否定当前实现的收益主张。没有独立真值和重复对照时，仅报告行为契约和实测覆盖。

## 实施与质量门

`diagnostic_strategy.py` 负责公平取证目录、语义差异指纹、有界调查决策和只读历史视图；`HypothesisAgent` 负责候选及引用更新；`PlanningAgent` 收到前轮反馈并比较前两名可区分机制。最终 Judge、模型完整性、审批和恢复验证仍各自负责，不由策略停止信号替代。

初始置信度与每轮排序分数是工程排序建议；引用解析不证明逻辑蕴含。新增差异观测数不是熵、统计独立样本数或“信息增益 bit”。跨事故策略学习明确标为未完成。Agent+Skill 复用原有裁决响应中的候选复核，不通过新增隐式调用突破专项 Skill 的取证边界。

## 结论与置信程度

**高置信判断**：当前主入口能把候选来源、有效观测引用、宿主调查决策和独立审核区分保存。依据是实际代码身份一致性、35 项新增行为契约及四次真实诊断的页面/API 对照。它只支持这些已覆盖行为，不支持“所有引用语义都正确”或“所有故障均可诊断”。

**中等置信判断**：单事故内反馈与来源切换可以避免部分无据确认和机械重复。证据包括完整控制流反例测试，以及真实预验收中模型漏 ID 时更新确实被拒绝；统一输出结构后，最终四次诊断均返回可解析引用。尚无固定样本和预算的重复对照，因此不量化准确率、成本或耗时优势。

**证据不足**：跨事故自动策略学习已经带来收益。当前没有满足独立标签、留出故障集和策略晋升检验的实验，本阶段不作这一主张。下一阶段应将已审核轨迹构成离线对照集，比较相同输入与预算下的正确对象/机制、误确认、工具/模型调用成本、延迟和弃答率，再决定是否引入全局策略更新。

## 后续工程验证：逐假设独立角色复核

后续实现将竞争假设放入已有 Judge 调用，分别保存提出角色状态与复核判断；复核不能验证确认或排除时，按缺口进入一轮补证并保留处置阻断。最终远端 1,644 项回归通过，新增 29 项复核契约；四次新诊断的页面核对包含三次逐假设复核与八个按 run 去重观测引用。实际明细见[本轮验收](../../outputs/hypreview-20261020/verification.md)。这些是内部项目实验，不是论文给出的结果。

真实反例修正了“另一角色复核就能避免不当反驳”的过强前提：Judge 也曾用“事件未提及 PVC 信息、间接反驳卷机制”排除候选。工程实现保留原判断与理由，对这类明确的缺失/间接理由保守弃答，而非把引用存在误当作逻辑蕴含。最终调度场景仍有未解决分歧，补证后维持人工复核，报告的根因对象身份也未补造；镜像场景通过现有审核。行为门禁正确运行，不等于所有诊断都已经完成确认。

该复核仍可由同一模型担任，已知理由模式的规则也不能穷尽语义错误。因此，本阶段支持的结论是“能发现并阻断这类已覆盖的明确不当反驳”，不能上升为“所有假设已获得客观真值”。下一阶段优先补齐类型化可证伪检查、补证报告的对象身份契约，以及独立标签的固定评估集。

## 后续工程验证：真实声明与对象身份

本轮补齐前述两个工程缺口：从同一次 Pod API 读取投影出绑定 UID/resourceVersion 的声明检查，限定验证“CPU/memory 请求超出可分配资源”和“所引用 PVC/通用临时卷未绑定”两种机制；True 才能证伪，False/unknown 不直接支持确认或排除。宿主同时阻止无直接检查的排除，以及违背直接反证的确认。补证报告漏掉对象身份时拒绝整个改写并保留仍获证据支持的原报告，显式 null、对象重建和补证采集失败则保留身份缺口与审核阻断。

修改前两项确定失败的最小复现在最终版本通过；新增 60 项测试，远端完整回归 1,704 项通过。两故障族、两模式共四次新真实前端诊断通过过程、引用、报告和重启验收。调度案例现在有真实声明证据排除两个限定竞争机制，通过既有审核；两个多智能体根因 UID 与版本另用集群 API 独立核对一致。镜像案例仍将没有直接验证的竞争机制保留 uncertain。这些结果替代的是上一阶段该调度案例“缺声明、身份丢失”的实测状态，不撤回独立标签及固定对照集仍不足的研究结论。完整材料见[本轮验收](../../outputs/predicate-20261020/verification.md)。

## 后续工程验证：跨轮来源状态与冷启动反例

后续检查发现，重试选择仅查询本轮结果，会在中间一轮改查其他来源后遗忘此前失败。现在逐轮保存实际取证来源的尝试次数、最近结果与观测引用，候选明确请求仍有重试额度的失败来源时可以优先补证。自动失败重试最多一次；必要的生命周期/传播核查保留原流程约束，总轮数与模型预算继续生效。成功但无可引用观测与失败分开记录，两者均不自动构成反证。这是有状态的单事故调度控制，仍不是跨事故策略训练。

受控 `run_rca` 实验实际经过三轮：event 首次失败，metric/log 的成功没有擦除失败，第三轮按候选请求重试 event 并取得观测后再进入独立审核。模型和 collector 为受控替身；该实验直接验证控制流，不作为集群故障准确率样本。最终真实告警验收另运行两故障族、两模式共四次新诊断，均通过当前质量审核、页面/引用与持久化检查。

真实预检还发现空历史向量库会触发模型并发下载，诊断停留在上下文阶段。该批预检单独保存并中断，不计入通过样本；修复为明确空集合不提交向量查询。实际 Chroma 测试验证空集合嵌入函数调用为零，最终四次真实诊断也在无相应模型缓存、规则/事故集合均空的容器中完成上下文阶段。非空历史库缓存部署与有界检索超时仍需单独验证。

本阶段新增 26 项回归，远端最终全量 1,759 项通过（7 项 warnings）。另发现验收时镜像 Pod 资源版本与诊断采样不同，根因 UID 和限定声明仍相容；分别保留两个时刻的版本，不数值推断版本先后，也不把它当作执行时前置条件核验。完整材料与预检/受控/真实样本区分见[最终验收](../../outputs/retry-final-20261020/verification.md)。本阶段不主张通用准确率、成本或延迟收益已经得到对照证明。
