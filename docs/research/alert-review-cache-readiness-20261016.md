# 跨扫描告警审核复用：接入条件与现场核查（2026-10-16）

## 决定

继续保留同一作业的成功批次 checkpoint 复用；跨扫描审核缓存先补齐版本与事故身份，再测量可复用比例。本轮没有启用跨扫描缓存。直接按告警文本或 group ID 建缓存，会把模型、提示或事故轮次已经变化的结果误认为当前结论。

这项决定沿用[论文采用建议](alert-event-compression-literature-20261016.md)的分阶段路线。此次新增证据来自项目代码和生产持久任务的只读统计，没有新增论文复现或真实模型质量实验。

## 现场记录能说明什么

在 snail 的正式容器中，以 SQLite `mode=ro` 和 `PRAGMA query_only=ON` 读取 `/app/data/alert_compression/jobs`。审计只输出汇总数量，不导出原文、模型答复、配置或凭据。脚本和结果为 [cache-readiness-audit.py](../../outputs/alert-review-resume-20261016/cache-readiness-audit.py) 与 [cache-readiness.json](../../outputs/alert-review-resume-20261016/cache-readiness.json)。

| 当前持久任务样本 | 数量 |
|---|---:|
| 作业 / 已保存的准备快照 | 30 / 30 |
| 明确带 synthetic 来源的快照 | 1 |
| `source=import` / 其他或未标记来源的作业 | 1 / 29 |
| 完整准备快照与此前快照逐字段相同的重复记录 | 27 |
| 在前一相同快照之后 300 秒内出现的重复记录 | 0 |
| 成功的关系审核 checkpoint 批次 / 其中候选对 | 0 / 0 |
| 已保存显式审核版本契约的作业 | 0 |
| 准备快照带审核前生命周期投影 | 0 |

27 个重复记录不等于 27 次可省掉的模型调用：这批记录没有可复用的成功审核 checkpoint，且重复均未出现在上述 300 秒检查窗口内。300 秒只是此次观察窗口，不是已批准的缓存有效期。这是作业库样本，不代表同步扫描接口、全部历史告警结果或真实模型调用全集；也不能把“其他来源”全当成真实故障或合成故障。

此处比较的是完整准备快照，尚未分析跨快照的局部候选批次重复率。因此不能据此推断生产缓存命中率为 0，或宣称缓存没有价值。它说明当前样本不足以给出收益承诺，也不足以安全地回填缓存。

## 代码中的实际接入缺口

`AlertJobs.prepare` 保存审核前事实，`checkpoints` 保存同一作业的模型批次答复。这提供了可追溯原始输入的基础，但 checkpoint 没有固定模型部署版本、提示摘要和判定策略版本。[作业实现](../../agents/alert_jobs.py)

`LLMClient` 对象有模型名称、temperature 和最大输出值；模型名称可能是可更新的服务别名，不是不可变模型版本。当前作业 payload 没有固化这些信息。缓存标识不能包含密钥，也不能仅将同名模型当成同一版本。[客户端](../../tools/llm_client.py)

实时作业在关系审核之后才调用 `_finalize_alert_job`，将本次观测写入生命周期。episode 在观测已结束、再次触发时会递增。若缓存仅根据文本、资源名或旧 episode 判断，可能越过“恢复后再次故障”的边界；需要在审核前取得只读、带版本的生命周期投影，新 episode 未确定时不复用。[发布顺序](../../agents/alert_jobs.py)、[生命周期](../../agents/alert_lifecycle.py)、[实时作业适配](../../web_app/app.py)

原始告警 ID 由完整 raw 数据和输入位置产生，group ID 又依赖成员身份。同一批原文改变顺序后，旧引用未必仍有效。首次实现应只接受引用完全一致的证据快照；不能通过忽略 ID、时间戳或关键数值来制造命中率。若以后支持重排，需要额外验证来源身份与完整内容的一一映射。[归一化](../../agents/alert_compression.py)

现有模型一次看到多个候选对。某一对的答复可能受同批其他候选影响，因此首次可复用单位应是**完整、有序、等价的请求批次**；不能未经验证就把多对联合请求的输出拆成独立 pair 缓存。批次变化会降低命中率，但这属于必须如实测量的代价。

## 首次可接受的缓存契约

| 条件 | 必须保存并在读取时核对的内容 |
|---|---|
| 访问与实体作用域 | 部署/租户边界、集群、命名空间、实体类型及稳定身份；无明确隔离身份时不复用 |
| 事故轮次 | 只读生命周期版本、episode、事件状态；缺失或发生轮次变化即未命中 |
| 输入一致性 | 完整原始成员摘要、数值/单位/状态、模板和规则版本、实际有序 messages 摘要、完整批次组成 |
| 模型与策略一致性 | 显式模型部署 revision、提供方配置身份、temperature、输出限制、提示版本、解析/证据判定策略版本；配置身份使用非敏感标识 |
| 绝对有效期 | `created_at`、固定 `valid_until`、各来源证据时间；过期读取不能刷新有效期，未提供可信时间时不复用 |
| 结果可用性 | 成功解析并通过引用约束的原始审核答复；失败、超时及被截断/拒绝的答复不写缓存 |
| 当前证据再校验 | 命中后重新核对左右组引用、当前观测及现有 SCAG 规则；保留 `unverified`，缓存不赋予因果认证 |

空关系数组只表示当时没有提出关系，不能改写为“已证明无关”。是否缓存这种结果需要单独策略和漏关联评估。缓存命中还应明确列为 `reused_pairs`，与本次实际调用、失败、延期分开计数；供应商 token 和时间收益要另行采集，不能用输入字节数代替实际计费。

## 下一步可执行验收

先为新作业记录上述版本契约和证据快照，再以只记录命中、不改变模型调用路径的方式测量。观测阶段统计：符合契约的批次占比、完整批次重复、候选对局部重复、绝对有效期内命中、各类失效原因，以及记录/查找开销。旧记录不推断缺失字段，不自动导入可用缓存。

随后在独立 incident/campaign 切分数据上做成对回放：固定诊断后端与预算，比较不开缓存和开启等价批次缓存，覆盖换模型、换提示、改阈值、改数值、跨集群同名、恢复再触发、乱序、过期和多故障并发。报告审核关系覆盖、最终根因质量、真实 token、全部重试和延迟尾部；没有这些证据，不将复用率直接换算成诊断收益。

本轮已经具体修复的是同一作业内的输入额度利用和恢复可行性，见[恢复验证报告](../validation/alert-review-resume-20261016.md)。这与跨扫描缓存互补，但不能替代上述接入条件。

## 后续候选进展

后续候选已增加批次审核观测：保存有序请求、完整成员与运行条件的指纹，在不同作业之间统计同一测量窗口内的重复成功请求，空关系、引用拒绝、失败和未完成记录分别计数。它继续执行所有本来需要的模型审核，`reused_pairs=0`；审核前事故轮次、作用域版本、证据时效及供应商完成元数据仍待接入。因此此前生产只读样本统计保持历史含义，不能被候选测试数据替代。实现与远程验证见[审核观测验证报告](../validation/alert-review-observation-20261016.md)。

再后续候选接入了可信实时 worker 的审核前事故投影、来源时间校验及审核结束后的版本复核，覆盖同一请求跨 episode 隔离和审核期间失效。该阶段仍未启用缓存，作用域版本、供应商完成状态和真实收益验收尚待完成，详见[事故轮次与时效验证](../validation/alert-review-context-20261016.md)。以上候选均未替换此前生产统计所对应的版本。

最新候选继续接入供应商结束状态和按尝试持久化的用量回执，阻止截断、拒绝、过滤及未知结束状态被计为完整审核。缺失统计保留为未知，重试累加已知量，不能当作账单节省。访问范围核查发现现有认证及集群绑定尚无权威版本，仍保留该阻断项，详见[完成状态与用量验证](../validation/alert-review-provider-20261016.md)。这些改动尚未开启跨任务缓存或完成真实收益验收。
