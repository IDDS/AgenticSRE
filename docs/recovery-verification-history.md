# 按恢复验证标准隔离历史

历史恢复成功率用于自动执行门禁时，必须同时匹配动作、环境和恢复验证标准。HTTP 状态探测成功、JSON 内容断言成功与基础设施就绪分别代表不同条件，不能合并成当前方案的成功率。

## 验证标准指纹

`recovery_verification.verification_contract` 与真实探针共用配置解析器。输出 `verification_fingerprint`、`verification_contract_version`、`verification_level`、`verification_contract_complete`，不返回探测地址、JSON 路径或断言值。当前标准版本为 `recovery-verification/v1`，指纹格式为 `verification:v1:<SHA-256>`。

指纹覆盖精确集群/namespace/service、验证引擎版本、验证层次，以及实际使用的地址、HTTP 状态、采样数、间隔、超时、头部/完整响应时延、响应体上限和 JSON 断言。默认配置与等效的显式默认值一致，数字 1 与 1.0 等常用等效写法一致，布尔值保持独立；断言顺序不改变指纹。地址别名不进行语义等价推断，可能保守地分开统计。数值规范化不依赖调用线程的 Decimal 精度。

修改地址、窗口、阈值、断言、验证层次或引擎语义会生成新标准；错误、重复或范围不匹配的配置没有完整指纹，不回退为较弱标准。验证引擎改变接受条件时，维护者必须更新标准版本；指纹不自动绑定 Git 提交或模型版本。

## 查询、写入与门禁

Web 方案的 `recovery_scope_v2` 在原动作/环境指纹之外增加验证标准指纹。历史查询传入 `verification_fingerprint` 和 `require_verification_contract=true`，仅统计同一标准、具备明确验证状态的已分类恢复结果。自动执行仍受原有置信度、样本数、统计下界、风险、回滚和权限门禁约束；缺少任一范围或验证标准均不能放行。

原有不带标准的记录保留，不改写、不删除、不补猜指纹。通用 `resolution_stats` 不传新参数时仍可用于旧记录概览，但这种汇总不能进入自动执行。新查询同时给出缺失标准、标准不符、未完成验证和元数据冲突的排除数量，便于区分“没有当前标准样本”与“旧样本很多”。查询受既有保留数量上限限制，不承诺统计全部历史；零样本不证明底层存储健康。

恢复写入必须为非预演、明确终态。恢复验证结果的版本、指纹和层次必须与方案一致，业务验证成功还必须有对应业务验证范围和结果。另将源头明确确认的动作执行失败作为计划接受标准下的失败尝试计入分母，标记 `verification_scope=action_execution` 和 `verification_contract_basis=planned_acceptance`；该分支不运行恢复探针，不表示已实测业务未恢复。超时、传输异常、信号中止、结果未知、未派发、预演及缺少派发证据的旧失败结果均不计入成功/失败；配置改变或元数据不完整也不能借用其他标准。JSON 存储保留结构化信息，扁平元数据同时保存验证指纹、版本、层次和验证状态；两种表示冲突时排除记录，不能挑选其中一个覆盖另一个。统计接口不支持新范围或显式报错时，返回不可用标记并阻断门禁，不借用宽泛汇总。

## 恢复复验

恢复复验仍只做观测，不重放原动作，也不向恢复历史补记因果成功。已经绑定的标准不能被请求参数替换；配置改成其他标准时，普通探测成功也保持待验证，并说明 `verification_contract_changed`。原记录没有方案指纹、但已有验证指纹时，服务端固定最初的要求，重复复验不能逐次采用新标准。已经明确的基础设施失败继续保留为失败。

## 边界

指纹用于匹配验证条件，不是签名，不证明记录来源真实或原动作造成恢复。恢复结果不是根因正确标签。本阶段不进行真实业务故障注入或模型准确率、MTTR 改善评测；验收对象为数据流、持久化和门禁契约。

## 2026-10-26 验证结果

历史隔离功能阶段冻结候选 833 文件，在远端禁网容器通过 165 项专项和 2199 项完整回归，保留 40 项现有弃用警告。该阶段新增 43 项用例，覆盖标准变更隔离、默认值规范化、类型区分、JSON 重启持久化、扁平元数据适配、冲突/未知结果排除、读写范围一致性和复验异常保护。最初 24 项在旧实现失败，其中直接复现了 14 条旧成功记录被算入新标准；异常保护还单独保留两项修复前失败记录。

按实际 COPY 指令构建的应用复制层镜像，在无源码挂载条件下通过完整 Web 应用导入，以及三个变更模块与测试源码的 SHA-256 一致性检查。镜像内合成历史展示“旧记录不放行→匹配标准可满足门禁→标准改变不再放行→新失败单独计入”，并验证首次复验异常后不会采用较弱标准。另以真实 loopback HTTP 保留四种响应合同检查。构建复用已有依赖，不代表从头重建依赖；扁平元数据测试是适配器契约验证，不等于实际 Chroma 服务的完整验收。

上述门禁通过只是隔离测试中的计算结果，没有执行真实动作或写入生产记忆。公开记录见 [恢复验证与历史隔离验收](validation/recovery-verification-20261026.md)。本次仓库发布没有执行生产部署。

最终发布候选 `recovery-publish-20261026-r2` 冻结 846 文件，补充数值精度、真实 JSON 探针成功经原生写入与重启读取的组合验证，以及十一种执行结果分类；远端通过 181 项专项、2215 项完整回归，保留 40 项现有弃用警告。明确动作失败的回归从 14 成功加入 5 失败，重启后得到 19/14/5 并拒绝自动门禁；未知、未派发和预演不计数。实际 COPY 层镜像通过五种 HTTP 情况、五阶段历史检查与七项前端徽标函数检查。最终日志、模块哈希和修复前反例均见上述公开验收记录。
