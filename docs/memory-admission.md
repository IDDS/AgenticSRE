# 历史记忆的范围与时间准入

2026-10-22，接续[反馈消费契约](feedback-contract.md)的第二个实施切片。代码仍未提交、推送或部署生产。本轮解决历史经验是否适用于本次调查的问题，不把范围匹配等同于知识正确或已证明有收益。

## 消费契约

`MemoryScope` 固定本次召回的 `cluster_id`、`namespace`、`as_of`，可携带 `workload_version`、`entity_uid`。多智能体 RCA 从实际配置和 namespace 建立范围；匹配当前集群和命名空间的结构化初始证据可以提供 UID 和版本。Agent+Skill 使用请求的结构化 payload/namespace；六种实验范式和 MCP 历史查询也传递范围。没有从事故自然语言或提取模型的输出猜测这些身份。

缺少集群或命名空间时，历史读取返回 `blocked_scope`，不初始化存储、不回退到全局查询。请求 namespace 与 payload namespace、cluster_id 与 target_cluster_id 若相互冲突，同样阻断记忆并标记 `memory_scope_conflict`，不自行选择一个范围继续召回。这是记忆门禁，本轮没有重新定义所有工具入口对冲突请求的执行策略。CLI/MCP 需要配置 `kubernetes.cluster_id` 并提供 namespace；跨所有 namespace 的查询本轮同样不自动获得跨域记忆。旧集成没有明确声明支持此契约时返回 `memory_scope_unsupported`，不悄悄忽略范围参数。当前观测采集和保守诊断仍可继续。

本地规则和历史事故必须同时匹配集群及命名空间。无范围、namespace 为 `general` 或仅有高相似度，都不构成通用知识认证。旧数据保留，可从管理入口查看，本轮没有补造范围或批量迁移。显式的版本/UID限制必须匹配；请求不知道被限制的版本/UID时也不放行。没有这些字段的条目不会因此获得对象身份验证，本轮没有补齐所有生产源的 UID/版本采集。

规则须为 active；candidate、inactive、revoked 等不能进入诊断。历史事故、完成运行和成功反馈按各自状态及时间检查。历史材料只供生成和检验候选，过去的根因和旧对象状态不能替代当前工具证据。

## 时间不是相似度的一部分

时间字段采用有限、非负的 epoch 秒，Chroma 字符串元数据采用同样校验；布尔、NaN、无穷和格式错误不通过。

条目必须有 `recorded_at`，兼容旧记录的 `timestamp`；未知写入时间不进入受约束召回。时间晚于本次 `as_of` 的记录和后续修改不可见。显式 `valid_from` 尚未到达、`valid_to` 或 `review_expires_at` 已到达，均不放行；`valid_to` 采用右开区间。`observed_at` 在未来也不放行。反馈的 recorded_at 在处理完成时保存，避免把开始处理的时间冒充标签已经可用的时间。近期运行要求有 finished_at，不从尚未结束的调查或只有 started_at 的旧记录提取结论。

没有有效期的旧条目不会被补造一个有效期；本轮不是自动过时检测，也没有重建旧内容版本的时间旅行查询。使用 `updated_at` 的保守检查可能少召回后来仅更新了计数的条目，优先避免将未来内容带入过去时点。回放继续使用原来冻结的召回元数据，不重新查询当前库。

## 通用规则的显式审核

只有规则可以声明 `scope_kind=global`，同时须提供非空 `scope_reviewed_by`、不晚于 as_of 的 `scope_reviewed_at`，以及匹配 `global_scope_revision(record)` 的 `scope_review_revision`。该哈希绑定条件、结论、类型和适用限制；修改内容或限制后，旧审核不能继续放行。事故、专家反馈和近期运行不能靠 global 标记跨域。

这是明确元数据及版本的消费门禁。本轮没有新增通用规则的审核发布页面、签名身份认证或自动晋升流程；不得将一个字符串形式的 reviewer 字段宣传成已验证的审核人身份。普通自动/监督提取不会生成通用审核字段，而是保存实际来源范围和 source_incident_id。通过既有学习门禁的规则仍沿用原激活行为，候选隔离和独立评测晋升尚未实现。

## 先准入，再排序

JSON 每次受约束查询重新读取持久记录，先检查范围、状态和时间，再执行关键词排序及 top-k。已有实例能看到其他实例对规则的停用和范围修改。

Chroma 先用集群/namespace或显式global元数据缩小候选集，再执行精确准入检查；仅对合格 ID 集合进行向量查询，返回时再校验一次，以防中间发生编辑。超过4096条范围候选时保守报告检索不可用，不把截断的扫描伪装成完整召回。没有合格候选时不调用查询嵌入。该上限与既有总时间预算、单飞和迟到结果隔离一起生效，不为每层重新申请预算。

专家反馈在取最近 N 条、统计样本限额和事故去重前先过滤。多智能体的诊断历史分数也使用同一范围；业务恢复统计仍保持独立语义。本轮没有将恢复策略的所有历史统计入口重新实现一遍。ContextBuilder 对传入的快照再做准入检查；没有范围能力的全局执行 trace 和性能汇总不再带入受约束诊断上下文。手工配置的 domain hints 仍作为组织背景使用，不是历史事故事实。

管理用知识列表和搜索仍支持全库查看，属于现有管理接口。范围准入不是完整的主体授权或租户访问控制；下层存储的无范围管理查询保留兼容，不能用于绕过诊断消费者的门禁。

诊断过程中的历史检索卡片展示实际集群/命名空间及检索状态。缺少范围显示“已阻止历史召回”；检索失败与零个合格候选保持区分。`history_retrieval` 保存 `memory-scope/v1`、固定时点和 `scope-and-time-before-top-k/v1`。admission 计数描述发布/快照复核阶段的条目，不代表全库所有被排除条目的统计。
