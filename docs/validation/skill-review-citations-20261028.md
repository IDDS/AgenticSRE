# 缩零证据的重复引用核对

对前次真实缩零故障的保存观测进行只读独立审核重放时，模型引用了 Service、Endpoints 和 Deployment 的六条事实。原门禁要求每种对象恰有一条引用，因此即使多条事实来自相同对象和版本，也会报告 `cited_objects_incomplete_or_ambiguous`。核对发现这些事实中同类对象的 UID、资源版本和投影状态一致，来源包含命名读取及清单或其他读取。

本轮保留模型原始引用，对同类引用逐条核验身份、版本、删除状态、`spec`、`status` 和 `subsets`；只有状态完全一致才视作同一对象状态。系统不拼接缺失字段，不将重复读取当作独立证据，并以 `equivalent_cited_evidence_ids` 保存所有引用。不同 UID、版本、状态、缺失字段、非法时间或重复证据 ID 均保持阻断。证据满足条件仍不代表根因已证明，也不授权执行动作。

对同一组真实故障观测的[修复前重放](evidence/skill-citation-baseline-20261028.json)和[修复后重放](evidence/skill-citation-candidate-20261028.json)中，独立模型均引用六条事实并返回完整凭据；修复前类型化检查阻断，修复后满足进一步审核条件。模型结果可能变化，这两次重放不改变原始调查，不构成新的实时故障实验，也不证明自主恢复。

在最终候选的远端隔离测试中，专项 494 项、完整回归 2435 项及 JavaScript 语法检查通过。随后在非生产测试床进行了一次新的真实缩零：基线业务 20/20 成功，故障期间 0/5 成功，对照健康；独立看门狗已就绪。诊断在 32.522 秒完成，并正确绑定注入目标，置信度为 0.606。独立审核接收了 13,676 字节输入并获得完整结束凭据，未再因输入预算跳过。

此次审核发现推理阶段声称排除的两个候选缺少同对象、同事故窗口的直接反证；宿主将其保留为 `uncertain` 并阻断整体审核。自动恢复记录因此为 `blocked`，真实自愈动作数为零。实验控制器恢复后，业务连续三个窗口各 10/10 成功、对照健康；Deployment 恢复为 1/1 且围栏释放。该恢复不是系统自愈。[脱敏实时验证摘要](evidence/skill-citations-live-fault-20261028.json)包含状态、窗口指标及远端原始记录哈希。

新实验尚未覆盖实时审核通过后的对象动作路径，也不能证明总体准确率或自主诊断自愈闭环已验收。下一步需要改进假设状态更新和直接反证采集，同时保留独立审核、真实历史、审批及业务验证门禁。
