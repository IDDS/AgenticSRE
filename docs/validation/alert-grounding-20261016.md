# 告警诊断证据约束与自动动作门禁（2026-10-16）

本轮针对上一轮已观察到的无依据机制推断、原始告警引用缺失，以及待人工复核结果仍可能自动学习或恢复的问题实施修复。实现与验证均在远程 snail 的隔离环境完成；该验证阶段没有更换生产版本或提交代码。后续用户授权的提交、部署与上线核验见[发布记录](alert-grounding-release-20261016.md)，以下实验记录保持原运行时点口径。

正式验收仍需独立事故标注、客户确认的质量与性能阈值和上线验证。README 中根因推荐准确率 ≥80% 保持项目目标；此前交付对照表对该指标及“准确率提升 10%”的完成标记已纠正为待独立验收。本轮测试通过率不作为根因准确率。

## 实现边界

告警证据包进入实际多智能体 RCA 后，为采集观测建立稳定引用目录。目录使用原始告警 ID，以及包含来源、对象、命名空间、时间和原文的内容摘要 ID。失败采集结果、生成式摘要和重复结构化索引不作为新事实。供模型阅读的目录使用完整 JSON、逐类轮转取样和显式遗漏计数；完整的可用观测仍保留在最终结果中。目录只覆盖已经收到的证据，本轮没有实现自动拉取所有被省略的原始记录。

模型报告必须区分 observation、mechanism、hypothesis，并列出具体支持观测与逐字引文。原始告警引用按同一扫描、版本、分组中的已知成员精确核对，不纠正拼写、不模糊匹配。成员列表不完整时，未见 ID 标记为“在可用成员中尚未核实”，不能直接称为伪造；校验未通过时进入复核。

观测引文逐字校验后直接作为展示原文。模型的中文改写保留在分析草稿中，不自动认定其含义已被验证。明确标注 `hypothesis` 且列出待补证据的假设可以保留，但不能作为 `root_cause_claim_ids` 中的机制依据；其引用若存在，仍必须通过精确校验。机制断言还需存在支持机制分析的采集信号、同命名空间与已观测对象、逐项模型评审，以及通过总体质量审核。仅有告警名称、错误率、延迟或相关 Trace 时，高分模型评审也不能将其升级为内部机制。通过这些检查的机制仍标为 `supported_hypothesis`，不宣称独立因果真值已确认。

目前可提供机制背景的信号类型限于原始 Pod 日志、Pod 等待状态、容器退出、Deployment 副本与就绪状态、Service 空端点等已存在的结构化采集类型。未覆盖的机制会保守进入复核；类型符合要求也不保证语义正确，逐项评审仍有模型误判风险。不得将该实现描述为通用因果证明器。

最终对外结论由已校验断言生成。原模型根因、建议、摘要和原断言单独保留在 `unverified_analysis`，页面默认折叠。没有足够机制证据时显示“根因机制尚未证实”，保留观测并要求人工复核。页面还显示原始告警引用核对结果及可展开的原始观测；“流程完成”与“需要复核”分别呈现。

自动动作门禁覆盖实际多智能体 RCA 的所有最终待复核结果，包括质量审核、协作审核、引用与断言校验、前序模型响应完整性检查。门禁同时阻止自动学习和自动恢复；人工复核记录写入失败也不能放行。门禁没有把人工触发的独立处置入口或 Skill 独立诊断路由纳入本轮改造范围。

## 真实回放中发现的设计问题

首版将新断言结构附加在原长报告格式后，导致重复输出。`case-00`、`case-03` 的最终报告达到原有 2,048 输出 token 上限，后一例补查报告也发生截断。该版实际完成 3 个样例，第 4 个在调查阶段被主动中止，剩余 6 个未运行；原始记录保留，不能从分母删除失败，也不能把本轮当成已完成的 10 例测试。

修复采用单一紧凑报告格式：最终报告与补查共用字段，最多三条关键断言，保留引用、支持原文、对象和缺失证据，避免重复时间线和摘要。质量审核使用同一份带引用 ID 的观测目录，不再重复传入另一套目录。关联分析限制为短摘要。模型、2,048 token 上限、单次 45 秒和整个流程 180 秒预算保持原协议，不通过增大输出上限解决格式重复。

精简后另行冻结同一批 8 个现场快照与 2 个明确标注的构造状态样例。现场快照仍使用冻结领域采集适配器，调用真实 `Pipeline.run → run_rca` 推理流程和真实模型；不是完整在线工具取证。两项构造样例分别表示镜像拉取等待、Deployment 期望副本为零，单独报告，不作为两个自然事故计入生产准确率。

后续调整确定性展示与分类：通过校验的观测引文直接呈现，模型改写保留草稿；明确列出缺失证据的假设允许保持待验证状态，不因缺少支持就抹除另一个分别通过验证的机制判断。两个原状态样例依然没有形成通过全部门禁的机制判断，原冻结协议对它们的正例预期保持未通过，不追改为成功。

为检查有直接机制观测时的可用性，另行冻结仓库返回 401 Unauthorized、内核 cgroup OOM 终止容器两个构造样例，完成 13 次真实模型调用。该批仅检查明确错误机制，不替换前两项状态样例，也不充当独立生产事故。首次运行脚本在写主机日志时遇到容器新建目录的权限问题，尚未发出模型请求；仅调整日志保存位置后继续原冻结输入。

最终分类调整不修改模型提示词或推理阶段；使用上述 12 例保存的每一条模型响应在最终候选中重新执行完整 Pipeline。共 91 条提示词逐条与原运行完全一致，12 例全部完成。此步骤没有新增供应商调用，其用量回执归属于原真实回放，不能再次计入成本。
