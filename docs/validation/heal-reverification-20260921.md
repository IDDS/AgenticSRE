# 待验证自愈运行的只读复核

## 行为与范围

新增 `POST /api/heal/runs/{run_id}/verify` 及前端“重新验证（不执行动作）”。
仅允许真实动作已成功、当前仍为 verification_pending 的记录复核。新运行
持久化 verification_target；缺少原目标的旧记录拒绝复核，不从调用方补造目标。
复核固定使用原集群、命名空间、目标与命令记录，只执行既有只读 Kubernetes
检查及当前服务端配置的 HTTP 探测，不生成新方案、不执行原动作。

HTTP 探测成功才允许复核转为 succeeded。配置被删除时不能降级成仅凭基础设施
就绪通过。明确未恢复转为 failed，证据不可得继续 pending，终态拒绝重复复核。
保留最近 20 次验证历史、最新验证时间；动作结果与原完成时间不改动。
复核读取当前探测策略，未冻结原策略版本；这是当前状态观测，不证明原动作
导致恢复，因此不向知识库追加正负恢复样本。

## 并发和持久化

同一运行的复核与回滚使用文件锁互斥。回滚的锁由执行线程持有，HTTP 请求
取消不会提前释放仍在运行的写操作。真实回滚前落盘 running 意图，失败或
异常保留 outcome_unknown；重启后遗留 running 同样拒绝盲目重试和复核。
回滚预演独立保存在 rollback_preview，不覆盖真实回滚状态，也不阻止正常复核。

运行索引用全局文件锁保护读改写，JSON 使用原子替换；损坏索引拒绝覆盖，
持久化失败明确返回 503。索引与单条归档是两个文件，不是跨文件事务；索引
是本接口的有效记录来源，保留 300 条。此锁只适用于共享支持 flock 的文件系统，
不是跨站点分布式锁，也未实现通用自动续跑。记录仍需人工触发复核。

## 审查与验证

审查发现并修复两项问题：请求取消导致回滚锁提前释放；回滚预演被误视为真实
回滚而永久阻止复核。新增相应测试，并验证预演不能擦除未知真实回滚状态。
修复后独立只读复审无剩余阻塞。

远端候选 HTTP API 验收：构造一条隔离待验证记录，读取实际 frontend Service
的 Kubernetes Endpoints，探测独立测试 HTTP 服务。第一次请求超时保留 pending；
同一记录第二次复核连续两次通过后变为 succeeded；第三次复核返回 409。
共 3 次真实探测请求，原动作字符串和结果保持不变，动作重放标记文件未出现，
知识库未增加样本。**这是构造记录的真实 API/读取/HTTP 验收，不是生产业务
故障注入或真实自愈成功率实验。** 候选配置与数据独立，不写入正式运行记录。

完整回归包含原有测试、原目标保存断言、缺失目标与不合法状态、篡改请求参数、
验证异常、并发复核/回滚、取消回滚、落盘失败、损坏索引和并发保存等场景。

证据目录：`outputs/reverify-release-20260921/`；远端对应同名 releases 目录。
