# 纯多智能体远端验证与 Skill 边界修复

日期：2026-09-24。

后续状态：本文记录修复前测试；其后已完成修复和正式部署，见[最终发布验证](pure-agent-release-20260924.md)。

## 结论

纯多智能体可以完成本轮真实三服务故障诊断，确认 Skill 调用为零。原有 10 项验收全部通过，但协作反思超时并触发人工复核，因此不能把 10/10 解释为所有质量门禁通过或系统完全正常。

产品边界按用户明确要求确定：**多智能体就是纯多智能体，不得调用 Skill；Agent＋Skill 使用独立入口。** 不保留默认混合模式。

## 真实实验

命名空间 `agenticsre-propagation-3b40aa34` 中真实启动 caller → middle → dependency。实际 HTTP 请求依次为 200、503、200，各阶段 5 个 Jaeger spans，并额外采集 12 次请求的 24 条数值观测。通过真实 `/api/rca/run` 提交任务 `rca-c734e1b0`，不是直接调用内部诊断函数。

## 未解决的问题

1. 指标摘要为空仍可复现。
2. 关联分析与协作反思存在超时；反思超时使最终结论仍需人工复核。
3. 根因正文把恢复事件时间 `1790234358.0758712` 写成注入时间；日志与报告时间线中的实际重新注入时间为 `1790234361.6013405`。根因实体正确不代表所有时间细节正确。
4. 原有十项验收不检查协作反思成功和逐条时间一致性，覆盖范围不足，不能代替完整诊断质量评测。

## 代码修复及回归

在本轮实验运行期间，完成了独立的边界修复：

- 从 `orchestrator/rca_engine.py` 删除自动 Skill 桥接阶段；显式 Skill 工作流传入该引擎时拒绝执行并要求使用专用入口。
- `tools.build_tool_registry` 默认不注册 Skill，忽略旧桥接配置；仅显式 `include_skill_runtime=True` 的工具调用方可注册。
- Pipeline 和引擎自行创建的注册表改为独立实例，避免共享注册表互相污染。
- 旧配置字段保留以兼容读取，默认 false，不再控制多智能体能力。
- Agent＋Skill 专用执行器保持独立，既有 Skill 工具测试改为显式注册能力。

远端修复候选镜像：`agenticsre:pure-multi-agent-check-20260924`，镜像配置摘要 `sha256:1df0869c6d50ef9e2cd31977256656921e58e30323f4058a6d175406eec7643b`。

新增边界用例在旧镜像上为 **3 failed / 1 passed**。修复镜像完整离线回归为 **1028 passed / 224.27 秒**，33971 条警告，无失败。远端测试使用独立容器，不替换正式服务。

注意：上述真实模型实验运行的是旧镜像关闭桥接后的纯模式；代码删除桥接的候选版本经过完整回归，但尚未部署到正式服务，也未再运行第二轮真实模型实验。不能把正式环境描述成已完成升级。
