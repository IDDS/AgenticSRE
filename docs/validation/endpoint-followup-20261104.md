# 缩零场景中的端点补证

在完整的当前工作负载清单中，只有唯一零副本 Deployment 的模板标签与 Service 选择器匹配时，才选择有限的相关 Service（最多两个）进行后续读取。Service 及 EndpointSlice 须匹配 UID、资源版本、命名空间、所有者及明确的就绪状态；Service 在结构关联与后续读取之间版本发生变化时不沿用旧关联。缺失、冲突、数量超限或查询失败均不作为“端点为空”的证明。记录包含 Service、EndpointSlice 和 Deployment 身份及资源版本；选择器匹配只说明结构关系，不证明实际归属或故障因果，跨对象读取也不是原子快照。

在非生产真实缩零试验中，自动多智能体 Pipeline 记录了三次同一 Service 的 UID 绑定端点补证，均显示零就绪端点；这些是同一故障中的重复读取，不是三个独立案例。该次诊断仍需复核，独立审核未返回，自动恢复被阻断。随后增加 Service 版本一致性保护，在新的真实缩零试验中由实际 EventAgent 完成端点补证；Service 与 Deployment UID 均与独立目标一致，EndpointSlice 的 UID 和资源版本被记录。该第二次实验验证检测与补证，并未运行完整诊断或自主恢复。

两次试验均在独立看门狗保护下，由测试控制器回退；每次恢复后目标与对照业务连续三个窗口各 10 组检查成功。远端隔离环境的 140 项相关测试通过，另有 4 条依赖弃用警告。结果不证明总体定位准确率、正式验收或自主自愈通过。
