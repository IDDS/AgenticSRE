# 运行可用性修复与验收（2026-10-15）

本轮根据客户演示发现的问题修复智能助手、自愈历史和告警扫描，并补充智算指标来源隔离。
构建、测试、真实模型调用及浏览器验收均在远程 `snail` 完成，本机只编辑源码和接收证据。
未执行 Git commit 或 push；交付版本通过源码 SHA-256 清单和候选镜像标识追溯。

## 问题与修复

| 问题 | 原因与最终行为 |
| --- | --- |
| 助手显示就绪但对话失败 | 原发布沿用旧镜像依赖，只覆盖源码，缺少 `fire` 等 Hermes 依赖。候选镜像安装完整 Hermes 包；普通及离线 Dockerfile 加入真实导入门禁。就绪接口用相同解释器、相同模块路径执行独立导入检查，15 秒上限、60 秒缓存；运行时不可用时聊天入口返回 503。 |
| 恢复记录汇总与列表不一致 | 原页面只加载最近 10 条后在浏览器筛选，汇总却统计全部历史。改为服务端先筛选再分页，返回匹配数量及下一页位置；页面支持上一页、下一页，并丢弃过时响应。 |
| 扫描超过请求时限后显示失败 | 网页此前仍使用同步接口。新增实时扫描任务入口，复用 SQLite 持久任务、单工作进程及分批检查点；网页展示进度、取消、重试，刷新后续查。同一任务 ID 重复提交不会重复创建扫描，暂时断网只提示查询中断。 |
| 智算看板混入其他集群指标 | 本集群 Prometheus 不可达时，原代码回退到全局或本地其他端点。现在有集群范围或显式地址的查询只使用对应配置；缺失指标保持未知，并提示检查本集群 Prometheus、GPU/DCGM、vLLM。 |

助手调用中的动态配置通过子进程标准输入传递，不再把含凭据的请求写入临时脚本。
告警同步接口保留兼容；导入告警强制标记为导入来源，不能冒充实时观测推进告警生命周期。
实时任务复用固定准备快照、模型批次和确定的扫描 ID，最终写入生命周期与历史基线。

## 智算环境仍存在的问题

正式服务的集群档案配置 `http://127.0.0.1:19090`，原看板实际回退到了另一通算集群的 Prometheus。
只读调查发现目标集群两节点上报可分配 GPU 均为 0，两个 vLLM 模型 Pod 处于 Pending，调度信息包含
`Insufficient nvidia.com/gpu`、节点选择约束或控制面污点；GPU Exporter 与本集群 Prometheus 也未就绪。
这不能证明物理 GPU 不存在，需要继续检查驱动、设备插件和节点运行状态。

本轮没有重启节点、删除失败 Pod 或调整 GPU 调度；只修正应用的数据来源和缺失提示。候选看板保持本集群
配置地址，返回 `profile_only`，节点、GPU 和模型指标缺失值保留为 `null`，不使用另一个集群的指标填充。
自动值守保持原状态，未开启自动处置。
