# Deployment 诊断对象的身份绑定

多智能体诊断原有身份绑定仅覆盖 Pod，Deployment 报告可能只有名称而缺少对象 UID。现在仅在当前调查的事件采集返回完整结构化工作负载清单时，为明确选出的 Deployment 绑定唯一 UID 和资源版本。调用方必须提供明确的集群与命名空间；观察时间必须落在本次调查内。相同名称出现多个 UID 或版本、采集失败、信息缺失、对象正在删除、显式 UID 或版本冲突均保持未验证。若存在后续补证采集，以该采集为准，失败时不回退到较早快照。

绑定仅确认所采集对象的身份，不证明故障因果、完成独立审核、授权动作或验证业务恢复。原有诊断质量、审批、实时对象检查和恢复门禁不因此放宽。

在隔离非生产环境的只读预检中，真实事件采集器观察到的 Deployment UID 和资源版本与独立 Kubernetes API 查询一致。该预检未注入故障，不证明定位准确率。远程隔离环境中新增 4 项身份绑定测试及 60 项既有 Pod 身份验证测试通过；覆盖不完整采集、跨集群、过期时间、身份或版本冲突以及后续采集失败。测试结果不等于自主自愈验收。

随后在非生产 Train Ticket 环境进行一次受控缩零，真实端点信号自动触发多智能体 Pipeline。隔离实例显式指定集群，诊断在注入开始后约 133.435 秒返回 Deployment 候选，绑定的 UID 与独立注入目标一致。身份绑定成功，但诊断仍为 `requires_review`，自动动作门禁因 `unresolved_investigation_gaps` 和 `quality_review_required` 保持关闭。测试控制器恢复副本后，目标和对照业务连续三个窗口各 10 组检查通过。该结果是同一故障机制的单次验证，控制器恢复不是自主自愈，不能证明总体准确率或正式验收通过。
