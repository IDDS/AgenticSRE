# Agent＋Skill 取证职责与诊断耗时优化（2026-10-13）

## 设计与问题定位

本次沿用原有设计：Agent 根据现场与历史上下文提出假设，Skill 实际调查，
Agent 根据证据裁决。此前的[泛化方法论](../agent_skill_generalization_methodology.md)
已明确这些职责，并要求模型失败时显式失败。因此本次属于修正实现偏差，
并非提出一套新的 Agent／Skill 分工。

[优化前复验](agent-skill-diagnosis-20261013.md)发现：默认路径包含模型假设、
模型规划、Agent 调查、模型选 Skill、Skill 模板诊断及模型裁决。镜像 Skill
自身没有工具取证；模型失败还可能被确定性候选掩盖。Skill 的毫秒级模板执行
没有减少前面的模型往返，整体镜像诊断反而达到 114.084 秒。

## 实现

默认完整流程将假设与 Skill 选择合并为一次模型调用，随后直接运行所选 Skill，
最后调用模型裁决。保留阶段审计，但取消独立模型规划和 Agent 预调查。
正常路径为两次模型调用；旧协议、无效 Skill 选择或证据矛盾仍可能触发有界重试。

`k8s.image_pull_error` 读取目标 Pod 的当前容器状态，区分镜像不存在、访问
被拒绝及连接失败。告警文本只用于选择调查方向。Runtime 在 detect 未匹配时
跳过本次 diagnose，避免健康对象得到模板故障结论。

其他尚未实现自带取证的专项 Skill 通过 `generic.evidence_collection` 获得
实际工具结果。模型最多指定四条只读命令；若全部查询没有有效对象输出，Skill
追加 Pod 名称发现并读取最多三个实际 Pod 的当前日志。命令仍受请求 namespace、
宿主集群和只读权限约束，拒绝跨 namespace、写操作和 Secret 读取。

最终裁决只接收一份有预算的原始证据，避免重复工具结果挤掉 JSON 输出协议。
当前成功查询到的 Ready 状态会作为显式反证，阻止旧启动告警覆盖当前状态；
发现矛盾时要求模型重新裁决。最终根因须保留已证实的对象名称和异常状态。

现场复验另外发现：`memory.enabled=false` 时上下文提供器仍初始化并查询
故障库，一轮检索耗时 221.288 秒。已修复为禁用记忆时跳过历史检索，并增加
禁止访问故障库／反馈库的回归测试。该修复不等同于为启用状态的远程知识库
查询设置统一超时。

## 复验过程与未通过轮次

所有构建、依赖安装、pytest 与 Kubernetes 实验均在远程 `snail` 完成。
从正式镜像创建隔离候选，使用相同正式模型配置；凭据仅从既有挂载在内存读取。
关闭自愈、记忆学习和演化。没有向诊断输入添加注入标签或预期答案。

| 版本／现场 | 耗时 | 结果与发现 |
|---|---:|---|
| 原正式版本，镜像失败 | 114.084 秒 | 根因正确，但有效模型假设门禁失败 |
| 首轮优化，镜像失败 | 17.748 秒 | 真实专项取证与有效模型假设通过；同场纯多智能体 64.65 秒并通过其门禁 |
| r4，三服务传播 | 32.752 秒 | 模型猜错标签，全部调查空匹配；未定位，通过流程完成不等于诊断正确 |
| r5，三服务传播 | 33.801 秒 | 日志支持正确传播方向，但最终摘要遗漏完整对象名与 FAILED 状态；严格门禁失败 |
| r6，三服务传播 | 246.232 秒 | 历史检索占 221.288 秒；把旧 readiness 告警误当当前根因，机制门禁失败 |

失败轮次和原始输出均保留。原传播脚本的日志门禁仅检查非空输出，r4 仍把
“No resources found”计为日志采集成功；独立复核不接受该项，后续脚本已排除
这种空匹配输出，没有据此宣称 r4 诊断通过。

## 最终验证

最终候选 `agenticsre:skill-owned-20261013-r7` 的远程全量测试为
**1059 passed，5 warnings，218.91 秒**；定向测试 **241 passed**。
新增回归覆盖两次模型调用、模型空输出停止、健康对象反证、长工具输出保留
完整 JSON 协议、命令权限边界、错误标签后的真实对象发现、记忆禁用与旧
readiness 事件反证。最初四项核心回归在原正式镜像上全部失败，在候选上通过。

最终三服务传播复验耗时 **23.786 秒**，两次模型调用、四条实际只读命令。
八项门禁全部通过：任务完成、有效模型假设、实际 Skill 调用、有效日志输出、
完整根因对象、FAILED 状态、模型最终裁决、无独立模型规划。根因指向
`agenticsre-propagation-690e25f3-dependency` 当前 FAILED 状态及向 middle、
caller 的传播。基础现场同时验证了 HTTP 200→503→200、真实 Jaeger Span
及数值观测；诊断本身的日志取证不等同于已执行 Jaeger 查询。

最终镜像故障复验耗时 **14.261 秒**，两次模型调用、一次实际只读状态查询，
七项门禁全部通过，准确定位当前目标容器镜像引用不存在。

| 最终候选场景 | 耗时 | 模型调用／只读命令 | 结果 |
|---|---:|---:|---|
| Agent＋Skill：镜像拉取失败 | 14.261 秒 | 2／1 | 7/7，通过 |
| Agent＋Skill：三服务 HTTP 503 传播 | 23.786 秒 | 2／4 | 8/8，通过 |
| 纯多智能体：同场镜像失败 | 229.000 秒 | 保留原有多智能体流程 | 5/7，Judge 无有效评审结果，进入人工复核 |

纯多智能体最后一轮文字定位正确，但 Judge 返回
`invalid_or_unavailable_review`、`reviewer_failed_or_invalid`，不能记为通过。
镜像对比脚本因此退出码为 1；Agent＋Skill 两项通过的结论来自各自原始门禁，
而非把脚本退出或任务 completed 当作诊断正确。首轮纯多智能体曾在 64.65 秒
通过，最后一轮失败也保留，不能据两次结果宣称固定速度比或稳定准确率差异。

按事件时间戳拆解，最终镜像假设及选择约 6.70 秒、最终裁决约 7.08 秒；传播
场景分别约 12.33 秒和 10.06 秒。两轮关闭记忆时的上下文阶段均约 0.005 秒。
这些数字说明主要时间仍在模型往返，专项工具取证本身不是主要耗时来源。

## 结论边界

镜像与传播场景是少量受控现场，不能据此计算总体准确率或宣称所有事故都更快。
不同链路工具与门禁不同，纯多智能体保留 Judge；Agent＋Skill 使用有效模型
假设、实际 Skill 取证、具体对象及状态定位等门禁。传播验收验证观测到的异常
状态及传播方向，不证明是谁触发状态变化，也不等同于完整因果推断。

本次未验证所有 Skill、智算故障、自然生产事故、自动修复或生产知识库效果。
未修复此前纯多智能体闭环改写丢失 `root_entity` 的独立问题。
