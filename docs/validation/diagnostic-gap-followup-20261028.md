# 未核实排除结论的补证调度

在此前真实非生产故障中，模型对低分候选提出排除，但没有同对象、同事故时间窗的直接反证。候选虽被保留为活动状态，调查控制器仍可能只看领先候选和分数接近的替代候选，提前报告准备进入复核。独立复核仍会阻断，但调查机会和停止原因不准确。

现在，带有 `unverified_rejection` 的活动候选无论分数和支持引用多少，都会成为明确的调查缺口。模型同时给出的未决问题及已注册采集器提示可在有界条件下保留；未知采集器不会执行，已有问题不会被新提示挤掉。多智能体调查器优先考虑这些提示，仍遵循迭代、模型预算、来源尝试和失败重试限制；无法补证时记录停止原因并保持人工复核门禁。模型不能通过后续不完整更新撤销其先前未核实的排除断言。

Skill 推理提示要求只有存在对应类型化验证测试和直接反证时才提出排除，其他情况保留未决。它不改写已有断言，也不替代宿主验证或独立审核。当前 Skill 路径仍为单轮：它能如实报告这些缺口，但尚不能自动执行第二轮针对性补证。

最终快照的远端隔离回归结果和两次健康预检摘要见[验证数据](evidence/diagnostic-gap-followup-20261028.json)。两次预检的业务基线均为 20/20，均因候选诊断未完成而在故障注入前停止；没有注入故障，也没有系统自愈动作。因此这次不能证明真实故障下的新调度有效，更不能宣称自主诊断自愈闭环已验收。健康预检中首选专项 Skill 未匹配是后续需要处理的问题，不能通过跳过预检解决。
