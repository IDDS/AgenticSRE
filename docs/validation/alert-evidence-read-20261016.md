## 实现与边界

新增 `GET /api/alerts/compression/{scan_id}/groups/{group_id}/evidence?revision=…&offset=…&limit=…`。revision 必填，每页默认 20 条、最多 100 条，返回完整标准化记录及原始 raw 字段、下一页偏移和扫描/分组/版本快照 SHA256。接口核查成员索引、成员 ID、数量及集群/命名空间；不返回其他分组数据。分组编辑后，旧版本请求返回 HTTP 409，不悄悄切换至最新分组。该接口不提供历史版本永久存储；已有 RCA 会保留启动时选取的证据快照。

[诊断入口](../../web_app/app.py)在一次读取的扫描快照上构造证据包，避免分别取摘要和原文时读到不同分组版本。[读取模块](../../agents/alert_evidence_read.py)优先保留数值极值、不同来源/模板/对象/状态/严重性的代表及既有首尾样本。剩余预算不再填入重复通知。默认上限是 32 条、所选样本序列化后 12,000 字符，每条消息最多 4,000 字符；这不是 token 预算，也不是存储读取字节上限。

所有原始告警 ID 仍用于同版本成员核对，未加载数量和消息节选数量单独记录。消息不再先变为 JSON 字符串，再嵌入另一个观测字符串；原始引号、反斜杠、换行和制表符保持可逐字引用。最终推理目录仍受既有 6,500 字符及单条观测 1,200 字符限制，所以“加载到证据包”与“进入推理目录”分别计数。没有声称任意长度原文均完整进入模型；超出部分可通过上述分页接口读取。

[证据约束](../../agents/diagnosis_grounding.py)还明确区分可供机制审核的实时采集观测与导入告警。目录优先展示前者，并提供 `mechanism_eligible` 标志；提示词要求机制引用至少包含一条此类采集观测。同样的错误文本出现在告警中，不会使告警自动升级为机制依据。既有精确引文、对象范围、逐项模型审核和自动动作门禁均保留；该标志表示可进入审核，不表示因果真值已确认。

页面展示已读取条数、最终推理目录中的条数、节选数量及同版本原文链接。告警记录数不再暗示故障对象数；对象身份有缺失时数量记为未知。混合对象分组中的告警保持各自身份，不继承分组代表对象的名称。

新模型输出使用 `evidence_id + quote_index=0` 选择已展示的原文摘录。系统在首次审核和闭环再审核之前取出对应 observation，并标记 `quote_origin=selected_catalog_excerpt`，让审核器评估该原文是否支持断言。引用选项本身保留供审计。未知 ID、未展示证据、非法索引及同时提供自由引文的歧义输入被拒绝；旧格式的 quote 不被纠正或模糊匹配。这样减少复写引文造成的格式错误，同时保留来源资格、对象范围与逐项机制审核。

## 实验协议

所有构建、pytest、模型调用、浏览器和集群实验均在 snail。对照镜像为上一轮候选 `sha256:9f6322566ad7f2c5c6713c80fdfe0bc27422ed914a4f0639bbe53c510dde3e43`，不是当前生产镜像。各轮先保存 contract、驱动源码及 SHA256，再创建受控故障；基线与候选使用独立 Web 实例、独立数据和日志目录，2 CPU / 4 GiB，生产配置只读挂载且不进入归档。

故障仍为应用容器缺失 ConfigMap、非法镜像名称、初始化容器缺失 ConfigMap，另设健康对照。每例根据实际 kubelet 状态构造 101 条受控导入记录：100 条相同 Pod 未就绪通知，第 51 条包含本次实际状态详情，并用明确的实验前缀将关键文本置于第 500 字符之后。所有记录指向同一个真实 Pod，且同轮基线/候选输入的摘要完全相同。

两类消息先由系统保留为两组，再通过真实人工合并 API 合为一组，留下 revision=2 的操作记录。此处验证手工分组后的读取与诊断，不能计作自动语义归组准确率、101 个自然事故或现场原生告警流。注入设置只供驱动使用，告警中的状态详情来自实际 Pod；没有把评分真值作为模型答案注入。

实际 Pipeline 使用实时 Kubernetes 工具和真实模型，无冻结采集器替身。每次 RCA 最多 16 次模型请求，单次输出上限 2,048 token。指标和 Trace 后端明确不可用，恢复、自学习和演化关闭，因此不扩展为生产多信号诊断或自动修复验收。
