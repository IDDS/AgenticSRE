## 真实业务探测结果

从候选镜像对现有 frontend NodePort 首页发起只读 GET，不注入故障，不执行
自愈。实际响应 HTTP 200，但响应头耗时 **2399.411 毫秒**，超过本次探测
预先配置的 1000 毫秒门槛，因此第一项样本判定失败并停止，没有返回恢复成功。
未降低门槛，也未把这个负例写成生产业务恢复验收通过。

此样本验证“200 但响应慢不能通过”的真实处理路径，不能证明现场 SLA 应为
1 秒，也不能证明当前服务根因或整体性能。正式启用前仍需按实际业务路径和
基线确定阈值，并完成多负载/故障恢复实验。远端测试服务的连续成功、503、
间歇失败、重定向和不可达场景，见 business-probe-20260921.md。
