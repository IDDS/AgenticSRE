# 调查规划的输出约束与真实故障验证

在一次非生产真实缩零诊断中，受控调用计时记录显示两次不完整响应均发生在调查阶段、每次上限为 1536 token；随后在同一历史故障上下文的离线探测中，原规划提示有时返回六至八个步骤，而宿主每轮实际最多调度两个不同智能体。原 JSON 示例包含未替换的双大括号，模型也曾返回无法解析的 JSON。单条“提供方正常结束”不能证明规划结构有效。

规划提示现要求最多两个精简步骤，选用宿主支持的智能体、描述具体资源和数据源，并将命令执行留给宿主。修正示例的大括号；宿主校验计划为一至两个有效智能体步骤，含非空动作和有效优先级。非法、不可解析或未完成的模型计划使用显式标记的回退计划，并记录失败阶段；后续审核不能因此把模型执行不完整当作自动处置通过。提示约束是模型请求，不保证模型总会遵守；结构校验也不证明计划有用或结论正确。

对同一历史故障上下文的两组离线交替对照中，精简提示的四次响应均正常结束并可解析，其中三次符合所测两步骤与智能体约束；原提示的四次中三次可解析，可解析结果均输出六至八个步骤。两组均只使用同一上下文和模型，样本很小，且步骤数量是新约束，不能据此推断整体准确率或统计显著性。输出正文未存入对照记录。

在随后的非生产真实缩零试验中，隔离实例显式启用已验证的 `deepseek-flash` 思考参数兼容选项，使用两轮调查、150 秒模型总预算。17 次记录到的模型调用均正常结束，两轮调查阶段各一次 1536 token 规划调用均完整；本次没有不完整响应或模型计划回退记录。注入开始后约 129.024 秒返回 UID 与独立注入目标一致的 Deployment 候选，独立审核有记录并覆盖全部候选。缩容时间及执行者仍缺少审计证据，诊断保持 `requires_review`，自动恢复门禁关闭。控制器回退后，目标和对照业务连续三个窗口各 10 组检查成功；控制器回退不是自主自愈。一次复测不能证明总体准确率或正式验收通过。

远端隔离环境中 140 项相关回归通过，另有 4 条既有依赖弃用警告；覆盖计划格式、回退及不完整执行门禁。模型调用计时只记录阶段、时长和完成状态，不记录提示词、响应正文或凭据。

提交前复核发现该规划器也被另一诊断范式复用；最终实现仅在多智能体 RCA 中启用两步合同，其他范式保留原有较宽的规划合同，并在 RCA 两个规划分支中均记录回退失败。扩展回归首次使用过期的远程测试文件，出现一项与修改前一致的失败；换用当前仓库版本后 146 项通过，另有 4 条依赖弃用警告。

最终限定范围的候选随后在同一非生产服务再次真实缩零：注入开始后约 135.571 秒返回 UID 匹配的 Deployment 候选，17 次模型调用均完整，独立审核有记录且覆盖全部候选；诊断仍因未解决调查问题要求复核，自动恢复被阻断。模型报告将 Service UID 与 Deployment UID 不同作为身份链问题的理由，这个理由不成立：不同资源的 UID 本来就不同；跨对象关系仍须通过选择器、所有者及运行时证据单独验证。控制器回退后业务连续三个窗口各 10 组目标及对照检查成功；不构成自主自愈。上述均为同一故障机制的单例复测。
