# Train Ticket 站点查询：真实故障、诊断和恢复验收

2026-10-26 在远端既有 Train Ticket Java 服务上，执行了同一副本为零故障的两轮实验。实际业务为经 `ts-ui-dashboard` 访问 `GET /api/v1/stationservice/stations`，要求 HTTP 成功、`status=1` 且 `data` 非空；同入口的路由目录查询作为独立对照。没有新建替代业务的响应夹具，没有修改业务数据库或执行预订、支付。

**业务故障及第二轮恢复已验证，完整自主诊断与自愈尚未通过。** Agent+Skill 的证据格式兼容问题已修复，但仍未完成从空端点到其所属 Deployment 缩零的取证。多智能体在观察预算后报告了缩零，审核仍要求复核；第二轮还发生模型响应截断。所有原生处置门禁均拒绝，没有系统自愈动作。恢复来自独立实验控制器，不能算作 AgenticSRE 自愈成功。

## 环境与执行边界

使用独立 Web/Skill Runtime 实例和独立 JSON 数据目录，继承现有已授权模型与只读集群连接配置，关闭自动学习和自动处置。本次模型预检 HTTP 200 并取得有效文本，更新了 [10 月 23 日实验](train-ticket-business-injection-20261023.md) 当时 HTTP 402 的状态；不改写其失败记录。

注入前检查健康单副本、Service selector、Ready Endpoint 的 Pod UID、Pod→ReplicaSet→Deployment 所有权、无目标 HPA 和无并发 NetworkChaos。将实际 `ts-station-service` Deployment 从 1 副本设为 0，写操作带 UID、resourceVersion 和原副本数原子前置条件。部署 UID、非副本规格摘要固定；模型请求只包含服务、业务路径、观测时间、响应统计及实际 trace ID，不携带注入命令、预期根因或故障类型答案。

故障前启动独立远端看门狗，240 秒后触发恢复，瞬时错误另有 60 秒协作重试预算。未知注入恢复无论观测到 0 或 1，均以真实元数据更新形成 fence，阻止迟到请求及原调用恢复后的再次降零；每次注入重试还检查截止时间。身份、规格或其他归属变化时拒绝覆盖。上述预算不是硬恢复 SLA；单次 API 请求仍可能跨过检查时间，持久集群故障不能靠重试保证恢复。

第二轮在开始前明确区分 Java 业务冷启动与 Pod Ready：最多用 120 秒协作预算等待首笔有效业务响应，保存每笔 `recovery_warmup` 成败，再执行固定三个连续窗口；任何窗口失败都不重置重试以凑成功。这是新实验的预声明条件，第一轮仍按原条件保留失败。恢复耗时不能归因于某个智能体，未形成优化前后 MTTR 对比。

## 诊断、门禁与证据格式修复

两轮均并发启动多智能体与 Agent+Skill，只读观察预算为 165 秒，轮询和 API 请求可能越过该边界。最终/后续快照与预算内状态分开保存：

| 模式 | 第一轮 | 第二轮 |
|---|---|---|
| Agent+Skill | 约 29 秒失败，专项 Skill 未形成结论 | 22.586 秒流程完成，确认空端点和无就绪后端；仍未确定缩零原因，置信度 0.683、根因实体未绑定 |
| 多智能体 | 预算内未结束；后续报告 Deployment 期望副本为零，仍需复核 | 预算内未结束；后续报告缩零，但有证据/时间缺口及模型输出截断，置信度受限为 0.65，仍需复核 |

这两次调用不是重复统计实验，不能把 29 秒到 23 秒写成已证明的性能提升。`completed` 只表示流程结束；根因粒度、实体绑定、引用审核和自动执行资格分别判断。脚本只在原生 Ontology 门禁满足且绑定同一目标 UID 时才允许提交人工选择的动作，未改写诊断或降低阈值。本轮所有处置均被拒绝，没有执行该分支。

实际轨迹发现：模型提出合法的 `kubectl get … -o yaml`，通用采集器照此执行，但下游空端点判据仅能识别 JSON 或默认表格；HTTP 502 也不能用硬编码的 503 文本代替结构事实。现在只对 `get` 的显式 YAML/YML 输出规范化为 JSON，保留原有只读、namespace、Secret 和参数边界检查，工具收据记录实际执行的命令。健康端点仍不匹配该故障判据。

正确定位 Skill 包后，修复前 8 项格式反例失败、1 项跨 namespace 拒绝对照通过；较早两轮只是测试路径配置错误，不算算法反例。复核还以两项旧版失败重现了“看门狗恢复后，原注入调用恢复并再次降零”的竞态，再补齐 0→1 fence 与注入截止检查。
