# 同一真实失败 Span 的跨指标自动归并

后续[持续负载实测](alert-sustained-load-20260917.md)发现：不断变化的请求引用导致活动规则匹配或时序覆盖不足，单点故障 4→4、多点故障 9→9。本文 9→3 仅适用于下面描述的静态请求观测条件，不能作为持续负载达标证据。

## 方法与适用边界

新增 `agents/alert_trace_merge.py`，在实时指标、拓扑及 Trace 采集后、最终候选召回和模型提议前运行。先由现有嵌套阈值方法合并同指标规则，再检查不同指标是否为**同一失败请求的不同测量**。

自动归并要求：完整实时采集、无人工编辑、同集群/命名空间/Pod/维度、firing 告警；实际规则显式声明字段绑定 `agenticsre_trace_field: duration_ms` 或 `http_status_code`；指标携带同一 `trace_id` 和 `span_id`，且实际测量序列也具有相同引用；Jaeger 必须返回该确切 Span，并通过当前 Kubernetes Pod UID 映射。Span 明确失败且完整位于扫描时间窗内，所有有效采样必须在 Span 结束之后，并逐点匹配绑定字段值。延迟绝对误差最多 0.01 ms，HTTP 状态码必须完全相同。

仅当至少两类字段同时满足条件时归并。不同请求、健康 Span、旧 Pod、时间越界、采集截断、重复/歧义 Span、混合数值、导入数据、注解缺失及测量不符均不会获得自动归并授权。不会仅凭同对象、同时触发、相关系数、LLM 提议或相同 Trace ID 归并。

这标识同一请求观测，不确认跨请求共同根因。要求有对应的请求级测量及明确字段绑定，**不意味着已有的无引用指标自动适配，也不适用于聚合指标仅附带一个代表性 Trace 的情况**。原来无 Trace/Span 引用的阈值实验仍是 9→5。

## 证据与接口

实时告警标签中的 Trace ID 进入确切查询；链路适配器增加根 Span 在内的 `observed_spans`，与调用边分开存储。已有调用方向、传播方向及关联验证规则不变。

归并结果保留原始告警、最高严重度、原分组、规则引用及每份指标证据。多个单位的指标以 `composite` 分别保存、分别展示并分别进入模型，统计验证不会将它们混为一条数值序列。使用历史签名版本 4 并重新应用匹配基线，避免与旧分组数量直接比较。前端 app.js?v=139 新增 Span 归并依据与各指标独立证据面板。

## 实验设计

`eval/trace_metric_probe.py` 在三个独立 Pod 中处理真实 HTTP 请求，测量实际延迟和返回 200/503，将对应 OTLP Span 写入现有 Jaeger，并暴露该请求的指标与引用。`eval/trace_alert_acceptance.py` 使用独立 Prometheus 和隔离 AgenticSRE，通过实际扫描 API 验收，不注入告警 JSON。

规则为三个延迟阈值 100/200/300 ms 和 HTTP 503。两个 Pod 各触发三条延迟告警及一条错误告警，第三个 Pod 只触发独立 critical，共九条。正例要求 9→3；反例在同一 Pod 上分别执行两个不同的失败请求，延迟指标引用第一个、状态指标引用第二个，要求四条告警只做同指标阈值归并，保留两组。健康与恢复阶段均要求零告警。

本实验增加了请求引用和字段绑定，属于新的有埋点场景，不能冒充原无埋点实验达标。每请求标签只用于有界验证、仅暴露最后观测，不作为生产大规模埋点建议。实验 Pod 同节点以减少时钟差异；没有验证缺失链路、跨节点时钟偏差和多请求聚合指标。

首轮 `ba5a1e52` 因测试 Pod 启动时 readiness 过早产生三条真实 Warning，健康阶段断言失败。系统完整保留了这三条告警。测试 Pod 增加 10 秒启动宽限后重新执行，未通过过滤告警或改变预期计数绕过失败，原 namespace 已清理。

复验 `9585a546` 通过：正例 9→3（66.67%），其中阈值归并 9→5、同 Span 归并 5→3；反例 4→2，无跨请求合并；两次恢复均零告警，原文和 critical 保留，存储回读一致，生产 25 条生命周期记录不变，实验 namespace 与容器已清理。该版本随后补充了 composite 指标进入模型的表示，最终版本须另行复验。

最终镜像复验 `aa1b17c7` 同样通过上述全部阶段。正例实际取得六份已映射 Span，完成两组跨指标归并；归并后模型处理一对候选，携带各自独立的指标摘要，返回一条关联假设。**该模型假设没有参与已经完成的同请求归并，不将其归因为 LLM 压缩收益。** 反例取得五份 Span、保持两组，无跨请求合并。正式生命周期不变，测试 namespace、容器和临时配置均已清理。
