# 智算看板性能与节点异常展示优化（2026-10-15）

## 问题与修复

线上智算看板每次读取 llm-k8s 命名空间的全部 Pod，包括 4392 个历史 Failed
对象和 4 个 Succeeded 对象。压缩后的对象清单仍被同时放入 inventory 和
topology，单次响应约 4.89 MB；历史 Prometheus Pod 还占据了依赖图的有限展示位置。

本次在 Kubernetes 查询源头使用
`status.phase!=Succeeded,status.phase!=Failed`，实时拓扑只处理未结束的实例。
Pending、Unknown 以及 Running 但未就绪的 Pod 仍在查询范围内。服务端和页面
都保留终态过滤，页面明确说明展示范围。当前清单缩减为 7 个 Pod：4 个 Running、
3 个 Pending。没有删除或修改集群中的历史 Pod。

另一个问题是节点 CPU、内存和根分区卡片调用 `_chart_latest`，直接取第一条
时序的末值。线上根分区因此显示 dds-127 的 61.7%，没有显示 dds-128 的 94.9%。
本次对这三个卡片取各节点最新有效样本的最大值，并返回 `summary_nodes` 标注
来源节点；页面显示“最高”和对应节点名。此口径不是查询时间窗内的历史峰值。
图表中的各节点时序保留，样本缺失时卡片不补造数值。

健康计数同步按容器 Ready 状态判断，Running 但未就绪的实例不计为健康。
采集目标部分失败时使用警示状态，并将 GPU 数量明确标为“已观测”，避免把
部分采集结果理解为完整集群资源数。

## 性能验证

从部署服务器请求同一 T4 集群、同一 15 分钟时间窗，每组连续测量 3 次。
测量项是接口完整响应时间，包含远程 Kubernetes/Prometheus 读取；不代表所有
网络环境下的浏览器加载时间。

| 指标 | 线上旧版本 | 最终候选版本 | 更新后的线上版本 |
| --- | ---: | ---: | ---: |
| 响应时间中位数 | 9.395 秒 | 0.604 秒 | 0.549 秒 |
| JSON 字节数中位数 | 4,888,858 | 76,392 | 76,372 |
| 返回 Pod 数 | 4403 | 7 | 7 |
| 根分区摘要 | 61.7%，未标节点 | 94.9%，dds-128 | 94.9%，dds-128 |

最终线上版本响应时间减少约 94.2%，响应体减少约 98.4%。各组测试间集群
工作负载未因本次优化发生变更。最终线上测量存于 `production-measurement.json`。
