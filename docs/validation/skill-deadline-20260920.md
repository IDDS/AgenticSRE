# Skill 阶段超时、进程隔离与失败可见性

## 为什么需要独立进程

原执行器直接调用 Skill 的 Python 函数，异常可以捕获，但 sleep、死循环或
阻塞调用没有阶段时限。远端旧镜像中配置 0.3 秒时限后，测试函数仍运行约
0.90 秒并执行后续代码，复现测试失败。线程 future 超时不能终止 Python
线程，因此本轮使用独立工作进程执行阶段，而不是仅停止等待。

## 实现和边界

- 默认每阶段 30 秒，通过服务端环境变量
  `AGENTICSRE_SKILL_STAGE_TIMEOUT_S` 设置，必须为有限正数且不超过 600 秒。
  时限涵盖工作进程启动、执行和该阶段请求的工具/适配器调用等待。
- 超时终止 Skill 所属进程组，停止后续阶段，记录 skill_stage_timeout、
  worker_terminated、requires_manual_review、automatic_retry=false。
  工作进程异常退出记录 skill_worker_crashed，阶段异常记录 skill_stage_exception。
- 一次匹配流程复用一个工作进程，避免每次候选探测重复启动。每阶段仍有
  独立时限；某 Skill 超时后该进程被销毁，其他候选在新进程中继续。
- 工具及旧适配器通过宿主 RPC 调用，保留现有 runner、只读 kubectl 策略和
  工具轨迹。宿主回调并发上限为 8，迟到结果不修改已返回的诊断和轨迹。
- **终止 Skill 进程不等于撤销远端操作。** 已派发宿主回调可能继续运行，
  超时返回 outcome_unknown 并要求核对，不重放调用。永久阻塞的回调会占用
  有限槽位，暂未实现所有外部工具的可终止进程隔离。
- 匹配失败保存在 failed_runs 中，不再被过滤成“未匹配”。工作流返回
  failed/partial，停止旧方案降级并关闭自动执行门禁。直接执行任何阶段失败，
  包括 verify 超时，也会关闭 heal_ready/auto_heal_ready。
- 独立 Runtime 的执行/匹配/工作流接口使用 FastAPI 工作线程，避免堵塞健康
  接口事件循环；工作流 JSON 保存增加进程内锁，避免引入并发覆盖。

这不是恶意代码安全沙箱：进程继承现有服务权限。当前实现面向 POSIX/Linux
部署，未完成 Windows 兼容。注册发现时加载模块的顶层代码仍在宿主执行，
不在本轮阶段时限内；整个匹配工作流也尚无独立总时限。

## 验证方法

所有执行测试在 snail。新增用例覆盖延迟副作用、后续阶段停止、跨进程上下文、
工具超时与迟到响应、正常工具轨迹、工作进程退出、失败探测保留、子进程终止、
失败后禁用旧方案降级、工作进程复用、超时后新建进程，以及验证阶段关闭门禁。

真实实验启动隔离 Skill Runtime HTTP 服务，加载实际会阻塞、异常退出的测试
Skill，并在执行期间访问健康接口。初版及优化版均确认：约 1 秒时限能终止
4 秒阻塞阶段，健康接口保持响应，随后正常请求成功；等待后无延迟文件写入，
异常退出被记录，工作流失败可见，实验容器清理通过。

最终代码新增 **11 个用例**，远端全量结果为 **916 passed / 199.57 秒**，
31910 条既有依赖/AST 等警告。初版 913 passed / 548.84 秒；进程复用版
915 passed / 191.33 秒。最后再加入验证阶段失败关闭门禁后执行最终全量，
没有把中间版本通过当成最终版本通过。

最终真实 HTTP 实验中，1 秒配置在 1.032 秒返回超时，期间健康请求约
3.35 毫秒；随后正常请求、工作进程崩溃识别、失败工作流记录均通过。
5 个并发工作流的记录全部保存；等待后没有延迟副作用，隔离容器清理通过。
本轮没有在生产加载这些故障测试 Skill，也没有调用 LLM 或注入业务故障。

## 性能取舍

在同一远端对一个 ImagePullError Skill 做三次只读执行，并各运行一次 K8s
匹配工作流。该实验不使用 LLM，不是多并发压力测试；测量包含主机负载影响。

| 版本 | 单 Skill | 匹配工作流 | 匹配数 |
| --- | --- | --- | --- |
| 旧版进程内执行 | 约 0.00006–0.00018 秒 | 1.528 秒 | 6 |
| 初版逐次启动进程 | 0.120–0.130 秒 | 4.495 秒 | 6 |
| 优化为流程内复用 | 0.062–0.121 秒 | 1.739 秒 | 6 |

隔离带来实际开销，不能声称零性能回归。优化消除了大部分重复启动开销，
保留失败时能停止 Skill 代码执行的边界。
