# 告警证据进入诊断提示词的预算与保真修复

本轮修复了告警事实在真实诊断提示词边界被截断、合并组内错误告警缺少代表样本两个问题。最终配对试验中，严格观测读取通过数从 **6/30 提高到 29/30**，实际输入 token 减少 **42.86%**。剩余一例模型误写引用 ID，按原评分规则保留为失败；完整 RCA 效果及正式告警验收仍未完成。

## 问题与修改

此前完整证据包对比发现了输入膨胀。本轮沿真实 RCA 路径继续检查，发现更直接的信息损失：`run_rca` 先截取证据 JSON 的前 8,000 字符，`HypothesisAgent` 再截取事件上下文的前 3,000 字符，`PlanningAgent` 的上限则为 2,000 字符。关联审计内容排在 `alert_samples` 前面，导致完整扫描虽有事实，实际模型提示词却可能只剩一段未闭合 JSON。

新增 `agents/alert_dossier_prompt.py` 并接入真实 `run_rca`：对告警证据包构造最长 2,000 字符的完整 JSON，优先放入原始告警 ID、告警名称、严重级别、时间和待验证根因候选，再放入数值观测、消息和查询描述。每项按完整结构尝试加入，不能容纳的项目明确计数；不从中间截断 JSON 或缩短目标资源名。完整证据包仍保存在 RCA 会话中，事件成员划分和合并判定未改变。

指标点序列精简时，原先直接去掉 `points`，没有为诊断上下文保留其极值。本次复用已有的指标资格校验，保留匹配测量的样本数、首末点、最小值、最大值及常量状态；不同测量仍各自携带证据 ID 和指标类别，不把单位不同的序列混合统计。

真实模型检查还发现原证据包的采样盲点：首条、末条与最高严重级别样本可能全是延迟阈值告警，位于中间的错误告警没有原文代表。`CompressionStore.dossier` 现在额外保留每个来源/告警名称的代表记录，原有高危、首末、数值峰值采样继续保留。修改同时应用于完整和精简证据包。

## 试验口径

来源仍为受控现场实验 `4b51e0eb` 的 16 份冻结快照。4 份快照没有活动告警，因此没有组诊断入口；其余快照共有 30 个非空组。组与窗口存在关联，不是 30 个独立生产事故，也不是新留出集。

在两份不可变镜像中分别调用实际 `CompressionStore.dossier`，按各自的真实 RCA 入口构造事件上下文。旧版使用原有 8,000/3,000/2,000 字符路径；新版使用共同的 `initial_incident`。重新校验的时钟固定在各扫描的采集时点，避免回放时证据过期影响比较。

实际 `HypothesisAgent.generate` 和 `PlanningAgent.generate_plan` 使用捕获适配器，记录交给模型的完整 messages；这一步验证代理提示词边界，不产生真实假设或调查计划。随后使用真实模型作为观测读取器，读取假设生成器实际可见的事件片段，检查目标对象、症状、最高严重级别与原始告警引用。它验证输入事实能否被读取，**没有执行完整 `Pipeline` 的工具取证、根因判断和质量裁决**。

每轮 30 组×2 种输入，共 60 次真实供应商调用。模型为 `deepseek-v4-pro`，temperature=0、thinking=false、每次最多 1,500 输出 token、90 秒请求超时、自动重试 0。组间交替两种输入的先后顺序，每次独立上下文。消息、原始组成员标签、调用计划、镜像及实现摘要在调用前冻结。内部复用读取器的 `raw`/`dossier` 两个栏位，本轮分别指“旧版实际可见片段”和“新版有界上下文”，**不是上一轮的完整原文/完整证据包两种输入**。

评分标签来自冻结扫描的原始组成员，不根据新采样结果或模型回答生成。必须精确匹配目标对象及症状集合、最高严重级别；每个症状的引用须支持该对象和该症状。错引、漏报、降级或缺少引用均失败。未确认根因字段是提示词约束，只检查输出遵循该约束，不代表已证明独立因果辨别能力。

## 开发过程保留

第一版预算预检查显示 12 项指标摘要因附带长规则/窗口描述而未进入提示词；随后把数值观测和审计说明分开。该阶段未调用供应商，输入和检查记录保留在 `initial/`。

首轮 60 次真实模型检查中，旧入口 **6/30** 通过，新入口 **18/30** 通过，未将该候选标为保真通过。12 个共同失败组暴露出错误告警缺少样本的问题；记录完整保留在 `failed-first-model/`。修复类型代表采样后，原基线消息及评分标签与失败轮次逐字相同，模型和预算参数也相同，再执行完整配对复测。没有调整标签或只挑选失败组重复运行。

配对结果为两版都通过 6 组、仅新版通过 23 组、仅旧版通过 0 组、两版均失败 1 组。最终 60 次调用均正常完成、用量回执完整；连同首轮失败候选共执行 120 次真实调用。输出结构与“未确认根因”约束两版均为 30/30，但后者仅为指令遵循检查。

新版输入合计少 18,268 token（42.86%），输出增加 832 token，调用时间本轮略增。没有控制供应商缓存和负载，不能宣称加速或按 token 降幅推导实付费用。这是“旧版真实截断片段 vs 新版有界上下文”的观测读取对比，不能用本表替换上一轮完整原始告警/完整证据包对比，也未证明完整诊断成本下降。

最终 `case-20` 的对象、延迟症状与 critical 严重级别均正确，但把输入中的 `a-9a5b5d5e5de9b28d000c0db6` 抄成 `a-9a5b5d5e9de9b28d000c0db6`，引用检查失败。其余两个引用正确，不抵消该错引。本次保留原回答，没有模糊匹配修正 ID、放宽评分或重新调用该例以替换失败结果。

输入边界检查显示，新版 30 段上下文最长 1,715 字符，均为完整 JSON，并完整进入实际假设生成器和计划生成器的提示词。本批 77 条原始告警记录的 ID、名称与严重级别全部可见，42 项数值测量摘要均保留，并逐项核对样本数、首末点及极值；样本与测量省略数均为 0。这里的 77 条包含不同扫描中的记录，不是独立故障数；更大输入仍可能触发省略，不能外推为任意规模无损。

远程定向回归 **216 passed，3.21 秒**；全量回归 **1,338 passed，5 warnings，237.02 秒**，无失败、错误或跳过。两组测试存在包含关系，不累加计数。覆盖实际 RCA 入口接线、两种代理提示词边界、小预算完整 JSON、超长目标、失效候选、原始数值极值及跨告警类型采样。
