# 告警压缩诊断入口保真与实际 token 对比

## 判定

对同一批真实采集快照完成两轮、共 **64 次真实模型调用**。原始告警、修改前证据包、修改后证据包均保留本次检查的异常 Pod、延迟/错误症状、最高严重级别和有效原始告警引用。发现并修复精简证据包重复携带完整逐点对齐记录的问题，修改后证据包输入 token 下降 **17.99%**。

**成本目标仍未达标**：修改后证据包总输入仍比本轮原始告警输入高 **23.47%**。不能把分组数减少、模型回执计量已经实现、或这次局部优化，写成压缩已降低端到端诊断成本。

本次使用诊断入口观测核对任务，未运行完整 `Pipeline`、实时工具取证和根因机制判断。不是根因准确率、生产总体非劣验收或新独立故障集；“根因准确率 ≥80%”仍待独立验收。

## 冻结协议与范围

输入来自此前受控现场实验 `4b51e0eb`，8 个阶段、每阶段两份快照，共 16 份。全部快照纳入，两次窗口可能重叠，不能计作 16 个独立事故。阶段涵盖健康、单故障、多个独立故障、同 Pod 不同请求机制、缺失 Trace、突增负载、复发和最终恢复。

原始输入保留存储中的规范化告警及完整指标证据；证据包输入使用实际 `CompressionStore.dossier(compact=True)`。二者共享同一采集状态、证据截止时点、Trace/变更上下文和请求窗口证明。证据包还含产品生成的关联检查等派生内容，这也是额外输入的来源；原始输入是当前规范化结构，不声称是最小化后的最优原文提示词。

历史记录中的未来恢复结果、注入配置和机制标签不提供给模型。使用当前冻结快照，生成证据包时把重新资格检查的时钟固定在该快照 `created_at`，避免回放时因证据过期改变输入。故障阶段名、控制计划和评分标签保存在模型输入之外。

每轮在任何模型调用之前冻结提示词、输入与标签 SHA256、调用顺序和预算。固定配置模型 `deepseek-v4-pro`、temperature=0、thinking=false、每次最多 1,500 输出 token、90 秒请求超时、自动重试 0；输入上限 262,144 UTF-8 字节，超限直接停止，不静默截断。每个阶段第一次扫描先原文，第二次扫描先证据包。每次独立上下文，不使用实时工具或故障记忆。

两轮的 16 份原始输入和 16 份评分标签摘要完全相同，提示词、模型配置、预算和调用计划相同。64 份回执均为正常完成，输入/输出 token 计数齐全；供应商返回的模型摘要和 system fingerprint 摘要各只有一个不同值。但这里没有供应商版本冻结保证，也未控制服务端缓存或负载。

评分要求异常 Pod 集合、每个 Pod 的症状集合和最高严重级别精确相符；每个症状至少引用一个支持同一 Pod、同一症状的原始 `alert_id`，错引或凭空引用失败。重复项、漏报和降级失败，根因确认字段必须保持未确认。提示词明确要求该结构，因此最后一项只证明输出遵守约束，不证明模型具备独立因果辨别能力。空快照要求没有虚构异常，不等于确认业务整体健康。

标签中异常对象/症状以已固定的控制计划为依据；最高严重级别按已触发规则的配置定义核对。同 Pod 交替请求场景的滚动均值可能触发或不触发 300ms critical 规则，不能给整个阶段指定固定严重级别。准备阶段发现并修正最初把延迟告警一律设为 warning 的标签假设；修正及评分器测试在首个模型调用前完成，未根据模型回答调整标签。

## 实测结果

| 轮次与输入 | 观测核对通过 | 实际输入 token | 实际输出 token | 16 次调用耗时合计 | 单次耗时中位数 |
|---|---:|---:|---:|---:|---:|
| 第一轮原始告警 | 16/16 | 160,728 | 3,754 | 45.053 秒 | 2.367 秒 |
| 第一轮原证据包 | 16/16 | 241,975 | 3,768 | 49.642 秒 | 2.798 秒 |
| 第二轮原始告警 | 16/16 | 160,728 | 3,748 | 35.883 秒 | 2.092 秒 |
| 第二轮新证据包 | 16/16 | 198,449 | 3,746 | 36.957 秒 | 2.175 秒 |

第一轮证据包比原始输入多 50.55% token；此次修改减少 43,526 个输入 token，但仍多 37,721 个。两轮合计 761,880 输入 token、15,016 输出 token；这是供应商用量回执，不是价格估算或实付账单。

第二轮原始输入未改动，耗时也明显下降，因此不能把证据包总耗时从 49.642 秒降至 36.957 秒全部归因于代码修改。调用串行执行，轮次不随机交错，服务端缓存和负载可能影响计时；只报告描述性时间，不作吞吐/SLO/稳定加速结论。

## 修改与保真边界

根因定位到 `association_candidates[].checks.statistics.matched_evidence`：每个关联重复附带整个窗口的逐点对齐回执，关联又会出现在两个端点组的证据包中。即使统计结论是“常量序列，相关性未知”，完整回执也全部进入模型输入。

精简模式对超过三条的对齐回执展示首、中、末三条，明确写出总条数、节选标志和含扫描版本/关联端点的完整证据引用。统计状态、失败或未知原因、相关系数、覆盖率、样本总数、容差、最大偏移及指标证据 ID 保持原值；告警原文、峰值样本和严重级别不受影响。完整扫描和非精简证据包保留全部对齐回执，不改动成员划分、合并判断或持久记录。

本轮只修复已定位的逐点对齐明细重复。小规模告警的诊断元数据开销、多个组重复携带请求窗口证明等仍存在；应继续按整个提示词的实际预算评估共享引用与按需取证，不能为提高压缩比强行合并独立事件，也不能直接删除支撑资格检查的原始证据。
