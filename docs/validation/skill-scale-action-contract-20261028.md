# Agent+Skill 缩零恢复动作契约验证

本轮针对服务端受控自动恢复编排增加有限准入：仅在同一已完成调查的独立审核和类型化缩零观测经重新核对、Service 与目标 Deployment 有唯一结构关系、对象身份及资源版本一致，且唯一启用的服务端策略明确指定目标与正整数副本数时，内部编排才可继续预演。实际执行仍受实时对象前置条件、历史、审批、动作风险与业务恢复验证约束；外部请求不能自行提供该内部能力。通用诊断动作门禁并未因此打开。上述结构关系只支持有限的恢复决策，不证明缩零触发原因。

调查模型构建此前可能先收录审核摘录，再因去重丢弃相同的已提交完整工具观测，使结构关系消失。本轮使完整采集和已提交工具记录优先于摘录，并增加覆盖实际 Skill 结果结构的回归。

最终候选在远端无网络隔离容器中运行，应用模块均来自只读候选快照。专项回归 481 项、完整回归 2422 项通过，JavaScript 语法检查通过；其中包含可控集成测试，检查内部契约、错误目标和副本数拒绝、真实执行门禁组合及重复调用。该集成测试使用合成审核、历史、动作执行和恢复验证，不能视为真实故障自愈。前两轮专项分别暴露来源优先级问题和测试夹具故障类别不完整，修正后重新运行；失败日志保留在远端。

远端 Chromium 加载实际页面及候选脚本，接口使用替身；覆盖证据展示、阻断、恢复状态、读取失败、历史切换和无写请求。该验证不证明实际后端端到端恢复。此前真实缩零故障记录不包含新契约所需的全部证据，本轮未将其补造为通过，也未把受控样本写入真实历史。

非生产测试床只读预检通过：基线业务请求 20/20 成功，对照请求均健康，P95 为 50.141 ms；此次预检没有注入故障。实际故障注入、受控自动动作、独立业务恢复验证和真实历史门禁的完整闭环仍需在具备条件的非生产环境验收；此处不宣称自主诊断自愈已通过验收，也不据此估计总体准确率。
