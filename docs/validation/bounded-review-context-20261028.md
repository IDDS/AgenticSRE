# 受限文本采证的独立审核

此前真实故障中的 Service 描述和事件查询产生非结构化文本，独立审核不能确认这些结果是否被考虑，因而保留 `unreviewed_tool_output`。本轮不把文本解析成 Kubernetes 对象、资源版本或根因证据，也不将名称相同当作 UID 或事件时间已绑定。

仅当集群宿主确认命令成功、标准错误为空且原始输出完整，工具链未截断，采集时间有效，且命令严格限定为当前唯一已观察 Service 的描述，或按该名称、已观察的 Service/候选 Deployment UID 筛选的事件查询时，完整文本才可作为补充上下文交给独立审核。UID 筛选条件本身不证明文本内每条事件的对象或事件时间。每条上下文有独立标识；模型必须逐条返回无可见冲突的审核结果。漏审、重复、未知标识、冲突、不确定、过长或缺少完整性证明均阻断。范围之外的日志和未知输出仍按原规则阻断。

审核提示明确将这些文本标记为不可信、仅名称关联、UID 和事件时间未独立绑定，不能作为根因、缺失事实或动作授权的证明。模型判断仍有误差；原有对象身份、类型化证据、审核收据、历史、审批和动作验证门禁不放宽。旧记录没有宿主完整性证明时不会被追补或重新标记为完整。

最终候选在远端无网络容器中通过专项 677 项、完整回归 2485 项及 JavaScript 语法检查。随后进行一次非生产真实缩零：基线业务 20/20 成功、故障期间 0/5 成功，对照健康；诊断在 28.911 秒完成并绑定实际注入目标。Service 描述和按名称筛选的事件文本分别获得宿主完整性标记，独立模型逐条返回无可见冲突并提供完整结束凭据；本次没有出现 `unreviewed_tool_output` 阻断。

独立审核仍因两个已提出排除但缺少直接反证的候选保留 `candidate_review_incomplete` 和 `asserted_hypothesis_not_independently_verified`。自动恢复记录为阻断，真实自愈动作数为零。实验控制器恢复后，业务连续三个窗口各 10/10 成功、对照健康；原 Deployment 恢复 1/1 且围栏释放。控制器恢复不属于系统自愈，自主闭环仍未通过真实验收。

两次早期健康预检均未注入故障：一次因专项 Skill 不匹配停止，另一次为补充 UID 筛选边界而主动中止。[脱敏摘要](evidence/bounded-review-context-20261028.json)记录本次结果及远端原始记录哈希，不包含工具原文或配置。
