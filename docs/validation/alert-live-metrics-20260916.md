# 实时 firing 告警到指标证据接入（2026-09-16）

## 本轮目标与实现

此前统计验证只消费输入中已有的数值观测，实时告警扫描没有自动补取底层指标。本轮为 live_scan 增加独立的 metric_evidence：以告警标签和资源身份唯一匹配健康、仍处于 firing 状态的 Prometheus 规则，再读取底层指标的历史序列。补取结果不改变原始告警条数、分组成员或生命周期输入。

采集使用产生本次 ALERTS 的同一个工具实例实际选中的 Prometheus 地址，包括原工具的可达地址发现结果；不将固定配置地址与实际告警来源混用。通过 `/api/v1/rules` 和 `/api/v1/query_range` 读取数据，接口与响应格式依据 [Prometheus 官方 HTTP API 文档](https://prometheus.io/docs/prometheus/latest/querying/api/)。

自动支持“单指标选择器与数值阈值比较”的规则，例如 `request_count{job="api"} > 2`，从比较左侧提取测量序列并增加 namespace 与资源标签约束。复杂表达式不做字符串猜测，可由规则维护者显式配置 `agenticsre_metric_query` 注解；未配置则报告不支持。拒绝把 ALERTS 或 ALERTS_FOR_STATE 作为测量证据。

返回序列须唯一匹配命名空间与资源，具备至少五个有限数值样本和 80% 历史网格覆盖率；多条序列、规则重名、身份不一致、冲突值、警告响应或历史不足均不提升为统计支持。保留规则名称/文件/表达式、实际查询、返回标签、起止时间、采样步长、原始值及证据 ID。采集截止后停止新增查询，报告未完成的组，不在超时后持续请求后端。

统计检查在告警自身没有数值观测时使用合格的 live metric evidence；导入数据不能继承此来源。紧凑事故证据包提供来源摘要，完整证据包和扫描结果保留样本。Pearson 仍只衡量线性共变，不确认根因或授权抑制告警。

## 实验设计

使用独立 Prometheus 2.51.0 和两个独立 HTTP 监听器，由实际 `/probe` 请求增加各自计数。Prometheus 每秒抓取，规则 `agenticsre_probe_requests_total > 2` 产生真实 firing 告警。候选服务单独配置该后端及 30 秒观察窗口，使用既有 `/api/alerts/scan` 入口，而非把测试序列直接注入统计函数。

实验检查：未触发时 ALERTS 为空；真实请求后出现两条 firing 告警；扫描自动关联规则并补取两组历史；统计结果可在 SCAG 中读取；原始告警保持两条；存储接口返回同样证据。最后重置实验请求计数，验证规则清除。计数重置用于验证规则状态转换，不宣称完成真实业务故障修复。关联的是实际抓取的请求计数，不是延迟或错误率，不据此推断因果。

实验 Prometheus 程序从集群当前运行的同版本实例只读复制，独立运行；不改原实例或生产规则。实验使用容器实例标签，没有伪装成 Kubernetes Pod。候选配置与数据独立，结束时恢复原候选配置并仅删除本轮创建且有实验标记的容器。

## 实验发现

首轮 Docker 未缓存 Prometheus 镜像，独立实验未启动，已清理已创建的 exporter。改用只读复制的现有程序。

随后真实扫描返回 500：工具注册器无论是否配置模型都创建 LLM 客户端，缺少凭据时提前失败。异常堆栈确认后，修复为没有有效凭据时不初始化模型客户端；只读指标采集仍可工作，已有有效模型配置保持可用。相关失败日志和清理记录保留。

无模型修复后，接口正常返回且取得两组真实序列，但严格网格检查拒绝了 Prometheus 四舍五入到毫秒的时间戳。根据返回的原始值修复：查询起止时间和步长统一为毫秒精度，并增加对应回归测试。

## 边界

复杂 PromQL 需要规则显式注解；缺少 namespace 或支持的实体标签时不补取。当前查询仍有时间窗口、截止时间及历史覆盖要求，不保证所有现网规则都有可用序列。统计关联不是因果检验，本轮不完成自主假设、反事实、异步或跨命名空间传播。

### 现网覆盖结论

因此，本轮证明了真实触发、规则匹配、历史查询、统计检查和存储回读这条链路可工作，但**不代表当前所有现网告警已覆盖**。下一步需要逐条核对复杂规则的测量含义、补充显式查询和必要资源标签，并继续使用真实序列验证；不能把 unavailable 改成 pass。现有 717 项回归和部署检查支持“已验证范围内未发现回归”，不构成所有故障模式均不存在的保证。
