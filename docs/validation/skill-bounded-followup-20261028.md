# 未核实排除结论的受限补证

Skill 调查首次评估后，如果候选仍有未经直接反证的排除断言，且根因已绑定到唯一候选 Deployment，系统最多执行一次受限补证：先按固定投影读取该 Deployment，再按已观测 UID 查询事件，最后重新读取同一 Deployment。每次查询及整个过程均有时间上限；UID 或资源版本变化、读取失败和超时均停止并保留人工审核门禁。模型不能指定任意命令。事件文本只是查询范围内的不可信上下文，不能证明事件时间、对象关系或反驳候选。

成功采证后，模型可以根据完整证据目录重新评估候选；先前未核实的排除断言不能通过改口或不完整更新消失。系统分别保存首次审核与补证后审核，并要求完整的提供方结束凭据。页面显示实际查询、停止原因、候选缺口、模型是否调用及凭据状态。本次仅实现固定范围的条件式补证，不等于通用自适应 Skill 重规划，也不授权执行恢复。

前一轮真实缩零中，补证三次查询和候选重评实际完成，但补证后的独立审核因为完整提示超过旧 32 KB 上限而未调用。对这份真实快照的离线重放显示，快照为 15,518 字节、完整提示为 34,099 字节；新的 48 KB 提示上限允许完整提示进入调用，同时仍保留 16 KB 证据快照上限、响应完整性检查和超限阻断。重放没有调用模型。

调整后，最终快照在远端通过专项 704 项、全量 2512 项，以及页面渲染和 JavaScript 语法检查。一次非生产注入中故障窗口仍有 1/5 次请求成功，实验因此未启动诊断并由控制器恢复；再次注入后基线 20/20、故障 0/5、对照健康。Skill 诊断 51.324 秒，对象 UID 与注入目标一致；对 H2、H3 实际执行三次只读补证并收到候选重评，首次和补证后的独立角色审核均调用了模型并取得完整结束凭据。两个角色可以使用同一模型，不代表人工审核。

两项候选仍缺少同对象、同事故时间窗的直接反证，因此独立审核继续阻断，自动恢复动作数为零。实验控制器恢复后，业务三个连续窗口各 10/10 成功。隔离环境的恢复历史为空、审批开启；这些条件与诊断审核均未被绕过。**控制器恢复不是系统自愈，自主诊断自愈闭环仍未通过真实验收。**[脱敏验证数据](evidence/skill-bounded-followup-20261028.json)包含结果及原始记录哈希。
