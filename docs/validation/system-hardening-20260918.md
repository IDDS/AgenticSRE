# 系统可靠性与 Skill 发布证据完善

## 范围

本轮处理 RCA 过程持久化、Skill 草案审批内容绑定及能力说明。所有执行验证位于
远端 snail，本地仅编辑文件、整理证据。未修改生产数据或部署正式容器。

## RCA 过程持久化

旧实现只在诊断结束时保存 completed/failed 记录，且直接覆盖 JSON。修复在任务
启动之前以及日志/事件到达时保存快照，复用临时文件、fsync、原子替换及 0600
文件权限。进程内锁串行化快照写入；所有活跃任务保留，终态历史仍限制最近 200 条。
初始落盘失败返回 503，不启动后台诊断；过程中落盘失败设置 persistence_error。

重启读取 running/queued/starting 任务时，保留 logs/events/partial_result，标记
failed、process_interrupted 和 requires_manual_review。既有前端能按失败任务
处理，不新增它无法识别的状态。中断任务不自动重放模型调用或修复动作。

这实现的是过程保留和中断识别，不是从任意步骤自动续跑。尚未验证多 Web 进程
共享 JSON、高并发写入性能或断电后的目录持久性；没有用单进程锁声称分布式一致性。

## Skill 草案内容绑定

release-gate 响应新增 draft_sha256，为草案完整 JSON 的规范序列化 SHA-256。
测试及审批证据必须携带相同 draft_sha256；缺失或草案任何内容变更都阻断
publish_ready。旧布尔字段仍严格要求 true，人工发布模式保持不变。

使用方式：先提交草案取得摘要，将其与实际测试及人工评审记录一起保存；最终
提交同一草案和含 draft_sha256 的证据。修改草案后重新测试、评审，不应简单
刷新摘要并沿用旧结论。旧客户端没有摘要时将被阻断，这是有意收紧的接口契约。

摘要只防止证据误用于其他版本，不提供审批者身份认证或外部证据真实性证明。
当前证据仍由调用方声明，发布仍为人工复制计划，未实现签名审批或自动安装。

## 复现和验证

- 修复前，新增四个反例在远端旧候选镜像得到 **4 failed / 1.51 秒**。
- 初次定向测试 **216 passed、1 failed**；唯一失败为实验容器未挂载 Hermes
  社区目录，保留原日志。全量测试补齐既有验收挂载，不跳过该测试。
- 新增草案代码、manifest、测试计划、目录修改后拒绝旧审批的四个场景。
- 实际进程验证：隔离容器内写入活跃 RCA 后 SIGKILL（退出 -9），新进程读取
  历史，确认中断标识、原始证据保留、0600 权限及无自动重放。结果 passed。
  此项未调用 LLM 或 Kubernetes，不冒充完整现场 RCA 中途重启验收。

**最终远端全量回归：883 passed，108.56 秒**。30982 条警告主要来自既有
依赖及 AST 弃用提示；没有把警告称为已修复。缺少挂载造成的社区测试失败在
完整环境中通过。五个修改文件的镜像内 SHA-256 与当前源码逐项一致。

候选镜像：`sha256:d59f06d40ab6bf28fabf9b08aa367f3825a33868844d9a77b1e91738c2056272`。正式两个服务仍为
`sampletime-20260918` 且 healthy。日志位于
`outputs/system-hardening-20260918/`。远端发布目录为
`/home/ubuntu/AgenticSRE-releases/system-hardening-20260918/`。
