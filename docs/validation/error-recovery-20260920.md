# 2026-09-20 智能体错误处理与持久化回滚

## 问题和修复范围

旧 RCA 修复接口每次创建新的 RemediationAgent，回滚栈只在旧实例内存中；
因此回滚接口可能没有撤销动作却报告 rolled_back。审批入口还会重新调用模型
生成计划，实际执行可能偏离已展示计划。动作失败、空计划和健康验证失败也
可能被顶层 executed 状态掩盖。

本轮修复三处运行代码：RemediationAgent、旧 RCA 审批/回滚 API，以及
AgentSkillBridge 的远端写请求降级。没有宣称所有 Skill 已具备通用自动恢复。

## 当前行为

- 审批只执行服务器保存的计划，不再调用 LLM 重新生成动作。全计划必须有
  非空执行和撤销命令，否则在第一项写操作之前拒绝。
- 动作在执行前保存 executing 意图，执行后保存结果、原命令和撤销命令。
  API 使用已有原子历史落盘机制，绑定原任务的集群与默认 namespace，使用
  隔离工具注册表。执行不再依赖临时 Agent 的内存栈。
- 同一任务已有执行记录时，重复审批返回 409。进程内全局锁串行化该 API，
  锁在执行线程内持有，HTTP 调用取消不会释放仍在执行的写操作锁。
- 执行失败返回 failed，停止后续动作。工具失败不能证明目标没被修改，记录
  outcome_unknown 并要求人工核对，不盲目重试或自动撤销前序动作。
- 回滚仅处理记录中确认执行成功的动作，按逆序逐项落盘。已成功撤销的动作
  不再执行；撤销失败或重启留下 executing/rolling_back 时停止并要求人工核对。
  缺少原始撤销记录的历史任务拒绝回滚，不编造恢复成功。
- 写操作前落盘失败返回 503，不执行该动作；写后落盘失败停止剩余步骤。
  重启读取到未确定的执行意图时拒绝重复执行或直接回滚。
- 健康检查异常、缺失或子项未知，返回 verification_failed 并要求人工复核；
  executed 只表示动作执行且当前健康检查通过，不代表业务根因已消除。
- Skill Runtime 的非 dry-run HTTP 请求失败后，不再自动转为进程内重放，
  返回“远端执行结果未知，需要核对”。dry-run 降级兼容性保留。

## 真实 HTTP 与 Kubernetes 实验

独立命名空间 `agenticsre-recovery-f3d3f636`，实际创建测试 ConfigMap。
隔离容器启动 HTTP API，使用真实 kubectl 修改 annotation，不调用模型。
仅关闭与本实验无关的启动后台采集，显式执行历史加载函数。

1. 经 HTTP 审批执行两项 annotation 修改，读取集群对象确认两项写入；重复
   审批返回 409。集群原有 Pods/Events 健康检查为 unhealthy，系统正确返回
   verification_failed，没有把写入成功当成集群恢复。
2. 对隔离 API 容器发送 SIGKILL，实际退出码 137；重新启动后从落盘记录回滚，
   实际读取对象确认 annotation 已撤销。再次回滚不重复修改。
3. 对不存在的 ConfigMap 写入，实际 kubectl 报错，顶层 failed，第二步仍为
   pending，重复审批被拒绝。
4. 正常执行另一个计划后，由实验脚本删除该测试 ConfigMap，制造真实撤销
   失败；回滚返回 failed，后续请求因 outcome_unknown 被阻止。

实验 passed，隔离 API 容器和命名空间均已清理且核验。此项验证错误处理、
真实写入、进程退出后的记录恢复和撤销，不是生产业务故障或完整 RCA 验收。

## 限制与后续

- 全局锁只保护单 Web 进程，不是多进程/多副本分布式锁；JSON 历史仍受已有
  终态保留策略约束，历史记录过期后不提供自动回滚。
- 未确定的写结果需要人工核对；没有新增自动重新执行、自动续跑或通用补偿。
- 通用 Skill 阶段硬超时、隔离执行、统一错误分类、有限退避重试仍待完善。
- 旧自动恢复编排调用仍不等同于本次 API 的逐动作持久化，不能外推所有路径。
- 回滚成功表示记录中的 Undo 命令成功，不证明业务恢复；当前健康检查仍是
  集群维度，未实现所有动作的目标专属验证。
- 完整 RCA 质量验收仍未通过，本轮没有改变诊断门槛。
