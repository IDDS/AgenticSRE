# 对象身份与副本状态的证据边界

一次非生产真实故障诊断中，最终报告同时列出 Service 与 Deployment 的不同 UID，并指出关系尚未验证。不同对象有各自的 UID；UID 不同本身不能证明身份链存在冲突，跨对象关系仍须由选择器、所有者引用以及运行时观测分别验证。已在最终报告请求中明确此语义，但模型输出不保证服从提示；此前真实复测并非修复后的复测，不能视为此问题已在现场消除。

进一步审查发现，针对证据的确定性根因对齐逻辑在同时看到 Deployment 期望副本数为零和 Service 端点为空时，会直接声称副本数“被设置为零”，并将其作为端点为空的原因。这些观测本身不能证明历史变更操作、执行者或跨对象因果关系。远程回归用例在修改前复现了该输出，修改后只分别描述两个观测，并明确关系和变更历史尚未证明。此修改不会自行解除审核或授权恢复；原始模型推理仍需独立审核。

远程隔离目录运行身份、选择器、审核、规划和目标证据相关测试，144 项通过。首次扩展运行因隔离目录残留旧版 `diagnostic_strategy.py` 有 2 项失败；同步当前源码后重跑全部通过。测试使用构造的观测，不能代替真实故障或证明自主自愈、总体准确率和验收达标。
