# 专项 Skill 未确认时的通用采证回退

健康预检中，模型先选择服务故障专项 Skill，再选择通用采证；专项未匹配时，原代码只检查第一个结果并停止，丢弃后续已执行的调查。现在仅当模型明确选择的后续通用 Skill 已成功完成，并至少产生一条实际执行、成功、结果确定且非空的只读观测时，允许继续通用调查。自动插入的辅助采证不能单独触发回退；专项成功时仍保留原来的首选顺序。原始运行均保留，回退事件明确说明它不是故障确认。主运行关联的服务范围优先于辅助运行的旧范围。最终根因仍需现有对象身份和独立审核门禁。

远端无网络容器针对最终快照通过专项 692 项、完整回归 2500 项及 JavaScript 语法检查。真实健康预检中，通用采证回退被触发且调查完成；独立审核因身份、证据等不足保留阻断，不构成故障确诊或动作授权。

随后，在独立看门狗保护下进行一次非生产服务缩零：健康基线 20/20，故障期间 0/5，对照健康；Skill 诊断 28.553 秒完成，对象 UID 与注入目标一致，置信度 0.618。系统准确记录 H2、H3 是提出排除但缺少直接反证的活动候选，并将 `unverified_candidate_rejections` 列为调查缺口。模型仍违反了要求仅在直接反证充分时提出排除的提示，独立审核因 `candidate_review_incomplete` 和 `asserted_hypothesis_not_independently_verified` 阻断。Skill 路径仍为单轮，尚未对这两个缺口执行自动二次采证。

自动恢复因诊断及审核门禁被阻断，真实自愈动作数为零。实验控制器恢复后，三个业务窗口各 10/10 成功；这属于控制器恢复，不是系统自主自愈。隔离环境使用空恢复历史、审批开启，也没有证明达到自动执行的其他条件。真实自主诊断自愈闭环仍未通过验收。脱敏数据及原始记录哈希见[验证摘要](evidence/skill-selection-fallback-20261028.json)。
