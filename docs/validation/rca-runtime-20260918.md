## 结论与范围

本轮补齐了状态变化日志采样、传播场景根因实体核验，以及最终 JSON 报告调用方式。
三轮完整真实实验均保留。最新完整诊断能定位正确 namespace/Pod，并说明
`/fault` 设置 FAILED、`/probe` 返回 503、错误向上游传播的机制，**但严格验收
仍未通过，不能宣称可信 RCA 完成或上线**。最终日志采样补丁另做真实专项验证，
不把专项通过等同于整条 RCA 通过。

所有执行验证在远端 snail；本地仅编辑和整理证据。输入是隔离三服务实际 HTTP
调用、OTLP/Jaeger、实际 Pod 日志和挂载代码，不是自然生产事故，也不是本轮
Prometheus firing 告警。真实模型参与关系提议、假设生成、重排、报告与评审。
故障标签只用于验收；应用实际打印的状态变更日志属于可观测证据。

## 修复

### 状态变化与请求日志

原日志 Agent 取最近 500 行，但仅交付最后 3 行，状态变化可能被后续流量覆盖。
新增对带目标 Pod、时间、before/after 的结构化 state_transition 日志的有界采样。
若首批已满且未见该记录，最多补查一次 2000 行；补查失败保留原结果。

真实第三轮又发现健康探针访问日志占据末尾两行，结构化请求记录被漏选。最终
补丁优先保留最新状态变化和同 Pod 的最新结构化 HTTP 请求，再附较旧变化和
末尾访问日志。原有 1500 字符观测限额保留，优先保护关键完整记录。
这些仍是应用观测，不自动证明因果关系、变更操作者或日志真实性。

### 根因实体

报告增加 root_entity，明确使用实际 namespace，而非 cluster|namespace 复合引用。
传播场景将 Pod 名称、namespace 与实际读取的 Kubernetes manifest 的 Pod UID
观测核对；无法匹配时要求人工复核、阻止学习增信，并限制置信度不高于 0.65。
校验结果和额外上限独立记录在 root_entity_validation；实体存在不等于根因成立。

### 最终报告调用

第二轮报告生成 120 秒超时，降级输出缺少完整实体，新的门禁正确拒绝。
对已采集事实的独立真实模型探针使用 thinking=False 和 JSON 模式，14.15 秒返回
完整报告。该探针是证据回放，不是端到端验收。

最终报告阶段采用该调用方式，其余阶段和质量阈值不变。第三轮真实 Pipeline 的
FINAL_REPORT 阶段耗时 21.38 秒，并实际输出完整 root_entity；不是通过拼接
预期答案填充字段。初始假设、规划及关联阶段仍有超时和耗时问题，尚未解决。
