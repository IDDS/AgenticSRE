# Pod 终止状态与时间来源

Service 范围的 Pod 固定投影此前只保留容器名称、就绪状态和重启次数，丢失了容器 `state` 与 `lastState` 中的终止原因。现在仅投影状态类型，以及终止原因、退出码、信号、开始和结束时间；任意消息和容器标识不进入该投影。字段格式不合法时拒绝该投影，避免把不完整数据当作正常状态。

诊断候选、独立角色审核和过程页可使用带原始观测引用、Pod UID、资源版本和采集时间的终止记录。`lastState` 明确表示上一次终止；容器报告的结束时间只与采集时间比较，晚于采集时间时提示核对时钟。该记录当前**没有独立绑定事故时间窗，也没有证明 Pod 与候选工作负载的归属或因果关系**。未出现在受限证据目录、没有 Pod、没有终止记录或退出码 137，均不能证明 OOM 未发生，也不能单凭 137 确认 OOM。此能力尚不覆盖 init 容器状态。

远端定向回归覆盖历史与当前状态、缺失及异常时间、对象替换、跨范围、无引用、无终止状态和字段脱敏；专项回归通过 790 项、全量回归通过 2535 项，页面渲染与 JavaScript 语法检查通过。

在非生产集群中，使用独立、48 MiB 内存上限、无业务 Service 关联的临时 Pod 进行内存限制压力尝试。Kubernetes 报告该容器的上一次终止为 `Error`、退出码 137，而不是 `OOMKilled`。新采证链忠实保留了该原因、退出码、Pod UID 和结束时间，并保持事故时间窗、工作负载归属与执行授权为未证明；因此本次不能宣称真实 OOM 已验证。临时 Pod 以 UID 前置条件清理，业务 Deployment 保持 1/1 就绪。

第一次尝试期间远端磁盘满，摘要未能落盘；当时也只观察到 `Error` 和退出码 137，临时 Pod 已清理。随后仅清理经核对的已停止项目测试容器和可重建快照，保留挂载数据卷及真实实验记录；磁盘仍接近满载，需要持续关注。第二次尝试的脱敏摘要及哈希见[验证数据](evidence/pod-termination-provenance-20261028.json)。本次没有验证业务故障自愈，自主诊断自愈闭环仍未通过真实验收。
