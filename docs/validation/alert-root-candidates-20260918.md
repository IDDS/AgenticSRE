### 尚未完成

最终 RCA 需要输出可独立校验的完整根因实体标识；机制确认还需要实际状态转移或变更审计证据，不能把声明源码当作进程状态证明。质量评估目前仍混合措辞规则与模型评级，需要在独立标注的正负样本上验证有效性，而不是为单个案例调分。跨服务多故障、共同根因、竞争解释、负载变化和置信度校准仍需专门验证。

## 范围与已确认缺口

原有系统已经实现同一 Trace 内的多跳错误传播识别，包括同服务内部 Span 桥接、独立时间序列对齐、关联图检查，以及告警证据包进入多智能体 Pipeline。此前实际实验使用显式测试关系，不能证明自主根因推荐闭环。

本轮审计确认压缩结果尚无结构化传播起点候选排序；另一个交接问题是诊断引擎截断上下文至 8000 字符，假设生成器进一步截断至 3000 字符，后置的候选可能无法进入模型。新增候选摘要必须位于提示前部，完整原始证据仍保留。

## 实现

从实际观测到的候选对同时检查两个传播方向，重新验证连续错误 Span、实体范围、时间和数值序列，不能依赖模型宣称的方向。仅满足检查的候选进入 Top-3，排序依据已观测影响范围和是否存在更下游依赖证据；这是调查优先级，不是根因概率。各路径保留原始 Trace/Span 引用，不拼接不同 Trace 来制造一条因果链。

候选报告包含逐项检查、缺失与冲突、传播路径、已知反证和后续只读取证建议。候选始终 `causal_confirmed=false`、`confidence=null`，不授权抑制告警或自动修复。健康调用、数值证据不足、显式冲突、过期、不完整或非现场输入拒绝生成候选。允许正式 `live_scan` 及专门采集的 `live_probe` 输入；普通导入不能继承现场身份。

证据包只携带涉及当前事件组的候选，打开证据包时重新核验有效期；人工拆合后失效。诊断提示前部保留有界候选摘要，避免长证据包将其截断，畸形可选字段不会破坏原有诊断流程。前端增加“传播起点与根因候选”面板，展示不确定性、路径和下一步检查，过期后隐藏候选。

## 专项实验发现的取证问题

首轮远端三服务实验通过结构、时间、统计检查，但候选因 Trace 被标为截断而拒绝。按 Trace ID 和按服务查询会重复返回同一链路；原映射器在去重之前截取前 20 条，因此重复返回消耗了配额并误标不完整。

修复为按独立 Trace ID 计数，最多处理 20 条独立 Trace。两个回归场景覆盖“25 个重复返回后仍有新 Trace”及“21 条真实独立 Trace”；旧正式镜像得到 **2 failed / 0.96 秒**，新实现仍应在真实超限时标记截断。首轮失败日志和原始观测独立保留，不以重跑覆盖失败。

## 验证边界

专项实验采用隔离 Kubernetes 命名空间内三服务真实 HTTP 调用、OTLP 上报和 Jaeger 查询，五个 Span 包括客户端与服务端桥接。正常、依赖故障、恢复及 12 次变化请求提供独立观测；故障注入标签只供验收器比对，不进入关联模型或诊断提示。

本实验输入为真实 HTTP 数值观测，不是 Prometheus 已触发告警。多智能体诊断使用真实模型、实时只读工具和隔离存储；学习与自动修复关闭。不能将单个受控场景的命中视为生产根因准确率、置信度校准或原设计全部完成。

## 真实 RCA 暴露的缺口及修复

第二轮实验（命名空间 `agenticsre-propagation-fe9721c4`）生成了正确的传播候选，但完整诊断不能验收为成功：三轮取证没有调度 Trace Agent，Log Agent 未获得目标 Pod，日志与指标返回为空，600 秒模型预算耗尽。最终诊断置信度为 0.429，质量检查要求人工复核。旧实验报告中的 `passed=true` 只检查流程结束，不能代表可信 RCA 通过；原始记录保留在 `live-856/`，不覆盖失败证据。

修复后，从有效证据包提取经过 namespace、实体格式和 Trace ID 格式检查的只读查询目标。存在传播候选时显式安排 Trace、Log、Event Agent；Trace Agent 按具体 ID 获取原始 Span，保留错误标记、父子引用和 Pod UID，并过滤其他 namespace。Log Agent 查询目标 Pod，保留原始日志样本。两者的结构化观测不依赖模型摘要成功，空取证明确返回失败。传播场景只有实际取得 Trace 与日志后才允许按高置信度提前结束。摘要调用可关闭模型 thinking，原有调用默认行为保持不变。

实际实验还发现 `k8s.service_unavailable` 将 HTTP 503 症状直接解释为无就绪后端。现修改为缺乏后端证据时输出待验证结论，不将 503 单独当作 endpoints 为空的证明；告警证据包中的 Pod 身份也进入 Skill 的结构化输入。

新版远端验收分别检查：流程完成、实际原始 Trace、目标 Pod 日志、独立注入目标命中、模型预算未耗尽及质量检查接受。所有检查结果先落盘，再决定是否通过。它仍然只验证一个受控故障场景，不能替代不同机制、竞争故障、混杂因素、负载和生产数据上的独立标注评估。

远端隔离全量回归：**869 passed，107.18 秒**。新镜像 18 个源码文件的 SHA-256 与上传清单一致；兼容 API、分页、旧结果接口、Job Skill 和首页浏览器检查通过。实际重测及未部署决定见本文最终结论。

### 第三轮独立验收结果

命名空间 `agenticsre-propagation-0b9e19bb`，869 测试版镜像，真实诊断耗时 451.63 秒。实际取得 5 个原始 Span 和目标 Pod 日志，形成 6 条结构化证据；第一轮假设重排达到 0.88，竞争假设下降。最终报告命中依赖组件，但将日志字段 `dependency: null` 解释为内部依赖缺失；这是没有字段语义或代码证据支持的推断。质量检查得分 0.64，要求复核，新验收器正确判定 **失败**，不以流程完成覆盖这一结果。记录保留在 `live-869/`。

摘要请求协议的独立在线探针复现：关闭 thinking 且强制 JSON 模式时，普通文本摘要提示返回 HTTP 400；相同提示不强制 JSON 模式时，返回 102 字符有效摘要。修复将 JSON 模式限制于 `json_chat`，普通摘要仅关闭 thinking，分类 JSON 请求保持原行为。新增空指标摘要失败标识，补充二次取证的目标传递，并在最终报告约束中禁止从未定义字段的 null 值推断故障及通过变更探针掩盖业务错误。后续重测不会复用本轮失败作为成功证据。

## 重现实验

运行位置为 `snail`，发布目录 `/home/ubuntu/AgenticSRE-releases/root-candidates-20260918`。完整回归使用该目录的 `run-full.sh`：Docker 隔离网络、固定候选镜像、既有离线测试依赖，不访问模型。真实实验使用 `tests/e2e/test_live_propagation.py`，显式启用 `AGENTICSRE_RUN_LIVE_PROPAGATION=1`，同时启用 MULTIHOP、SPLIT_SPANS、STATISTICS，指定候选容器、镜像与 `/audit` 证据目录。执行 `run-live.sh` 前需确认归档目录尚不存在；脚本保留上一轮现场记录、重建隔离候选容器后运行。

验收器通过配置中心读取当前模型设置，凭证只存在受保护配置文件，不进入源码或归档。`rca-progress.jsonl` 保留逐阶段证据事件，`rca-result.json` 保留最终报告，`root-acceptance-report.json` 分项报告门槛，`live-report.json` 记录正常/故障/恢复状态及命名空间清理结果。前端候选面板使用本轮真实采集结果回放，冻结原采集时钟后再测试过期隐藏；这项浏览器测试不冒充新的现场采集。

### 第四轮：可靠定位与机制未闭合

871 测试版在命名空间 `agenticsre-propagation-d2d52d55` 完成真实诊断，耗时 **364.90 秒**，模型无超时，剩余预算 835.1 秒。Trace 与日志摘要均实际成功，空指标摘要明确失败；首轮得到 6 条结构化证据。报告正确定位 dependency → middle → caller 传播，明确内部机制未证实，不再将 `dependency: null` 解释为缺失依赖，也不再建议变更探针掩盖 503。质量检查仍因机制未闭合要求复核（0.587），严格验收仍为 **false**。保留 `live-871/`，没有下调验收阈值。

为继续验证内部机制，增加 `configuration_agent` 的有界只读取证：仅查询目标 Pod 和它挂载的至多两个 ConfigMap，仅提取源代码文件中 5xx 分支及相关赋值的编号片段，附资源版本和内容哈希。不查询 Secret、无关 ConfigMap，不传递环境变量值；声明源代码明确不等于进程已加载版本或运行态变量的证明。配置证据仅提供后续推理材料，不直接生成根因结论。

证据格式化改为各来源交替提供观测，防止一个 Trace 的大量 Span 占满上下文，让后续日志、配置永远不可见；仍然先提供原始结构化观测，再提供模型摘要。
