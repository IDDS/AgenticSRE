# 自愈知识版本历史与恢复验证

## 问题与实现

前一版本已持久化策略修改前后的快照，但缺少查询历史和恢复入口。新增：

- `GET /api/heal/recipes/{fault_type}/history`：按策略返回历史，兼容已有无事件 ID 的记录，内容哈希生成稳定的选择标识。
- `POST /api/heal/recipes/{fault_type}/restore`：选择某次修改前或修改后的内容，重新经过现有校验、版本比较、文件锁和原子写入路径。
- 自愈知识库卡片的“版本历史”：查看修改前后内容，并选择恢复。

恢复不会执行集群动作，也不会覆盖已有审批方案。恢复产生新的库版本和审计事件，记录恢复来源；保留现有风险约束，仍要求审批、标为待验证、禁止自动恢复。历史最多保留全库最近 100 次变更，超出范围的版本不能通过此接口恢复。

## 远端验证

全部应用、测试和浏览器运行在 snail。旧镜像复现历史接口不可用；候选版本 22 项知识维护专项测试通过，覆盖恢复内容、保留审批约束、恢复审计、旧历史兼容、版本冲突、无效版本及磁盘写入失败。

最终远端全量回归 **938 passed / 205.34 秒**，32564 条既有依赖/AST 等警告。

真实 HTTP/浏览器完成修改、恢复修改前、恢复修改后；刷新与服务重启后内容仍在，两个并发修改分别返回 200 和 409。独立 Skill Runtime 的 `k8s.legacy_recipe_bridge` 从共享数据读取恢复后的动作。桌面及 390px 移动端无脚本错误、无横向溢出。隔离测试容器均已清理，没有注入生产故障。

## 生效范围与后续事项

此功能覆盖自愈知识库及其桥接路径。专用 Skill 仍维护独立动作，知识库恢复不会修改它们。知识发布审批、版本效果验收、晋升为自动执行策略、诊断知识历史恢复、统一执行日志与超时结果核对仍需继续完善。完整 RCA 质量验收的既有结论没有改变。
