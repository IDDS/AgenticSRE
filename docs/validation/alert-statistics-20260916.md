# 统计时间对齐与精确 Trace 取证（2026-09-16）

## 本轮实现

原统计检查只对时间戳完全相同的数值计算 Pearson 相关。真实上下游请求的完成时间不同，因此即使两端有完整观测，严格交集仍可能为零。

本轮采用只看时间的双向最近邻匹配：每个样本必须是对方的唯一最近邻，不重复使用，不按数值选择配对，不插值、不搜索最优传播延迟。容差取两侧中位采样间隔较小值的 10%，上限 1 秒。至少要求 5 对样本和双方较长序列 80% 的覆盖率；相同时间的冲突值、非有限值和常量序列保持 unknown。相同时间重复采样不增加有效样本数。保留匹配时间、原始告警 ID、偏移、覆盖率及样本数，便于复核。

Pearson >= 0.8 仍作为已有正线性共变支持阈值。以上阈值是工程规则，不是经过统计功效或显著性校准的因果检验；负结果只表示未满足该共变条件，不能排除所有非线性或滞后传播。`causal_confirmed` 始终保持 false。

## 真实实验发现并修复的采集问题

首轮完整回归 684 项通过，但重复请求后真实验收失败：近期查询每服务仅取 5 条 Trace，前一阶段明确引用的故障 Trace 已退出该集合。首轮状态 failed，清理验证通过，未发布生产。

据此增加已知 Trace ID 的精确查询：先取告警输入明确引用的链路，再补最近链路。只接受 16/32 位十六进制 ID，大小写归一化，响应必须匹配目标 ID。查询失败、无匹配和非法 ID 单独记录。当前每次最多精确查询 20 个唯一 ID，超出时设置 `exact_trace_lookup_truncated` 和 `truncated`；不宣称已经取消采集上限。

## 远端实际验收

复用三服务五 Span 实验，设置 `AGENTICSRE_PROPAGATION_STATISTICS=1`，增加 12 次实际 HTTP 请求，受控切换依赖故障与恢复。两端各保留 12 个 HTTP 错误状态数值，原始时间采用各自实际完成时间，未人为改成相同时间戳。每条数据保留 Trace/Span 标识及原始输入。

先验证正常、故障、恢复的传播限定，再检查额外 24 条数值观测的对齐和完整 SCAG 检查。使用一个实际故障请求的 Jaeger 链路，三重检查都通过时可以得到 evidence_supported，仍不是已确认根因。假设是实验显式指定的，模型调用为 0。

同时将上述实际观测通过候选和生产异步压缩 API 提交，检查 24 条原始记录完整保留、压缩为两组、统计对齐结果可由结果接口读取，且生产生命周期记录不受导入影响。该 API 导入不继承实验实时链路，图保持 unverified；这是预期的来源隔离。

本次输入是由真实 HTTP 状态转换的数值观测，不是 Prometheus 自动采集序列或 firing 告警。实时告警扫描仍未自动补充底层指标时间序列。自主假设生成、反事实检验、异步和跨命名空间传播仍未在本轮完成。
