# Agent+Skill 独立复核验收

本轮补齐独立角色调用、证据与候选核验、质量校准和结果持久化，重点防止对象定位正确被误认为因果已证实。全部应用执行、测试、构建和模型调用在远端进行，没有替换生产服务，也没有新增故障注入或处置。

## 冻结代码与回归

`skill-review-20261027-r6` 冻结 894 文件，远端禁网容器通过 **422 项专项、2358 项完整回归**，保留 40 项现有弃用警告，JavaScript 语法检查通过。新增 66 项回归覆盖独立调用、候选漏审/重复/错误引用、原生超时及迟到隔离、预算、UID/RV、普通 JSON 后续冲突、异常时间、相同状态合并、过度排除、传输收据及跨轮回执归因。

原版首先在“只有推理、没有独立复核调用”的反例上失败。后续审查和真实重放发现的问题也予以保留：目录前缀隐藏后续冲突、异常时间污染拒绝收据、日志伪装空清单、当前状态被误当成其它机制的反证，以及非法资源 kind 先触发共享解析器异常。最终收口到可记录的缺口和待审核结果，没有以放宽阈值使样本通过。

实际应用镜像完成导入、新工具 UTC 时间戳及变更模块哈希检查，全部 426 个应用 COPY 源文件与冻结快照逐字节一致。发布前只更新文档和选择性收据，运行/测试源码与冻结候选保持一致。收据索引见[证据目录](evidence/skill-independent-review-20261027/README.md)。

## 真实模型与观测控制

本轮使用上一轮真实缩零的保存记录，以及本轮只读采集的 Train Ticket 当前状态。当前采集实际得到一个匹配 Pod、唯一 Deployment 候选及完整范围，耗时约 1.186 秒；没有将其计为新的故障注入。

| 输入 | 最终实际结果 |
|---|---|
| 上一轮真实故障保存记录 | 普通输出缺少时间或未被覆盖，`skipped_input_incomplete`；未调用模型，保持待审核，不回填旧时间 |
| 当前真实健康观测 + 人为给定错误“副本为 0”结论 | 模型指出副本实际为 1、端点有就绪地址；约 4.411 秒，评分 0、待审核；正常完整停止收据存在 |
| 同一健康观测 + 有限状态结论、具体事故根因仍未知 | 模型认可状态证据，但因缺少具体根因和行动信息评分 0.6，仍低于现有门槛；约 5.193 秒，保持待审核 |

错误结论是复核反例，不是真实诊断结果或新注入。两项当前观测控制各发起一次宿主复核调用；网络配置通过标准输入在内存传递，没有落入配置文件或容器环境。三项控制均没有执行动作，也未证明总体准确率或 MTTR 收益。

早期 r3 重放曾得到模型评分 0.75，但模型用“没有 Pod”排除资源驱逐、用标签匹配排除端口错误。这是审核本身的过度排除反例，不能作为正确通过的证据。当前宿主要求直接类型化反证，否则把排除意见降为未知，保留模型原始观点并阻断未核验的排除断言。早期预算拒绝及该错误判断均保留在归档中。

## 完成范围与限制

独立复核结果已进入标准 `judge`、置信度校准、策略与 Ontology；引用与保存结果的契约由回归验证。本轮没有重新声称所有网页或所有故障场景都已准确通过；也没有把历史读取、只读健康采集或模拟反例计为真实故障。

目前完成的是有界复核及拒绝链路。非结构化证据解析、任意机制的直接反证、审核缺口驱动的自动补证，以及 Agent+Skill 对象动作准入仍需继续完善。`automation_gate.allowed` 保持 false，原生自主诊断自愈闭环尚未验收。
