# 真实 HTTP 指标多阈值告警实验

## 实测结论

**实验完成，但事件压缩目标未达标。** 实际执行目录为 `thresholds-20260917/4059a098`，命名空间标签 `agenticsre-threshold-4059a098`。本轮产生 660 次真实 HTTP 请求，Prometheus 实际触发告警并由扫描 API 采集；未用构造 JSON 代替告警。

| 阶段 | 实际 firing | 压缩分组 | 合法模型关系 | 结果 |
| --- | ---: | ---: | ---: | --- |
| A 越过 100 ms | 1 | 1 | 0 | 历史尚未充分积累 |

| A/B 多阈值 + 503，C 独立 critical | 9 | 9 | 0 | 模型完成 23 对，9 组历史取证成功 |
| 第一次恢复扫描 | 0 | 0 | 0 | 告警实际清零 |
| 间隔超过 30 秒再次确认恢复 | 0 | 0 | 0 | 满足生命周期解除观察条件 |
| A 跨窗口重新触发 | 4 | 4 | 6 | 四条告警进入新事件轮次；关系不等于分组合并 |

高峰阶段目标为 3 组，实际 9 组，条数压缩率 **0%**，按预先定义的对象退化事件真值计算的可合并记录对召回为 **0/12**，未达到 95% 目标。全部 12 对预期同事件候选都已被召回，缺口不是这些正例未进入候选。原文、成员唯一性、存储回读和 3 条 critical 保留检查通过，跨对象误合并 0。因为没有预测合并对，不声称分组 precision 为 100%。

三次有候选的阶段实际模型调用均成功，候选完成 1+23+6 对，没有失败或截断报告。重新触发阶段的 6 条模型关系都是 propagates_to；证据检查判为 4 条 contradicted、2 条 unverified，没有任何已证实传播或因果。不同阶段输入和观测不同，不能据此量化模型随机性；但这些结果说明合法格式的关系并不等于正确关系。

原有 25 条生产生命周期记录前后相同，正式主服务和 Skill 服务均 healthy。三个本轮容器已按实验所有权标记删除；临时配置、集群配置、Compose 和平台配置副本已移除，凭据没有进入归档。没有部署算法变更，也未调整实验预期以通过验收。

## 暴露的实现缺口

当前保守分组以告警名称等身份字段区分记录，因此不同阈值规则不会自动归并；LLM 关系层负责提出假设，也不会自动把这些组变成一个事件。这次实验明确验证了这一限制。

下一步应优先设计跨规则的事件归并层：同一指标、对象和事件窗口的嵌套阈值可以依据规则结构判断冗余，同时保留最高严重度与全部规则引用；跨指标同因归并需要更强证据，不能仅凭同对象或同时触发。应继续用本套固定正反例复验，不能直接把所有模型关系应用为自动合并。

## 目标与预先标准

验证多条不同规则描述同一受控退化事件时，现有系统是否能够压成事件组；同时验证不同对象不被误合并、critical 不丢失，以及恢复后重触发能否进入新事件轮次。分组压缩、模型关系提议、证据支持与确认根因分别统计，不能互相代替。

实验开始前写入 plan.json：三个延迟阈值为 100、200、300 ms，分组时间窗为 30 秒；最大阶段预期 9 条原始告警、目标 3 个事件组，预期可合并记录对召回至少 95%；原文和 critical 保留率 100%，跨对象误合并 0。

3 个目标事件来自独立的实验阶段/对象定义，不向压缩器输入事件真值，不根据模型输出改写规则或评分标准。这里的“同一事件”是预先定义的对象退化轮次，不代表模型已经证明共同根因。

## 真实触发方式与隔离

远端 snail 运行三个不同端口的 HTTP 监听对象，测量实际请求处理时间，返回真实 HTTP 200 或 503。它们属于同一个临时 exporter 进程，不伪称三个独立部署的业务服务。请求延迟由服务实际 sleep 产生，指标使用 perf_counter 测量，不直接把期望值写入指标。

独立 Prometheus 每秒抓取与评估，指标越过阈值后真正生成 firing 告警。候选扫描服务使用已部署镜像 agenticsre:metricui-20260917 和独立数据目录，启动时加载当前有效模型配置，调用真实 `/api/alerts/scan`，保存结果再从扫描读取接口回读。没有向扫描接口导入构造告警数组。

- 对象 A：请求延迟依次为 150、250、350 ms；最后阶段同时返回 503。
- 对象 B：独立请求产生 350 ms 延迟及 503，用作相同规则、不同对象的反例。
- 对象 C：低延迟但返回 503，只触发独立 critical 告警。
- 高峰阶段 A/B 各三条延迟阈值告警加一条失败告警，C 一条 critical，共 9 条。
- 恢复所有对象后执行两次完整扫描，两次间隔超过 30 秒；再等待超过分组窗口，重新触发 A，检查事件轮次。

这是远端受控故障实验，使用真实请求、指标、Prometheus 告警和模型，不是自然生产事故样本。服务延迟和失败由同一阶段控制，不以此声称验证了真实依赖故障的因果传播。

初始历史不足允许指标取证为 unknown；高峰前持续运行至少 35 秒，要求九组都有合格历史。原文保留检查包含全部规则名、对象、严重度与成员唯一性，以及存储回读完全一致。
