## 数据与真值边界

22,624 条样本来自既有六组固定构造器，标签表示通知、模板或指标观测的合并兼容性。生产基线与候选使用完全相同的输入和外置标签。这是开发回归数据，不能改称新的独立验收留出集。

实时实验在新建、带所有权标记的隔离命名空间中运行三个 HTTP 服务。请求产生真实的延迟和 HTTP 503，经探针指标、独立 Prometheus 规则、实际 Jaeger 采集及候选 Web API 完成扫描与存储回读。单故障、多故障等设置只供实验驱动及评分器使用，未作为模型答案注入。本轮关闭 LLM，测量的是规则与证据约束下的归组行为。

八个场景沿用已知开发用例，在本次运行中重新产生实际请求和遥测；不是八个自然事故，也不是独立故障家族留出集。缺失 Trace 时的标签表示必须保守保留的边界，不等于“已经证明两个不同根因”。健康空集和全单例数据的 pair precision/recall 记为 `null`，不计为 100% 准确率。

实验使用 10 秒滚动窗口、明确的窗口契约和 Trace 覆盖证明。这些接入条件是本次归并结果的前提，不能将结果外推到没有相应证据的普通告警。

所有脚本执行、pytest、容器运行及集群实验均在 snail；本机只编辑、打包和下载核验。Web 验证容器限制为 2 CPU / 4 GiB，监听回环地址，使用独立数据和日志目录。

## 可执行验收检查

[评分器](../../eval/alert_acceptance_gate.py) 重新检查样本数量、误合并/漏合并计数、原文分区、高危保留、峰值样本、两组输入摘要，以及实时扫描的原始对象身份和完整成员关系。脚本摘要中的 `passed=true` 不能覆盖具体失败。

工程材料缺失记为 `blocked`，观察到失败记为 `failed`；生产标签、客户阈值、完整 RCA/成本以及正式版本发布分别保留待验收项。当前评分器是本轮工程证据检查器，不接收一个外部“生产准确率数字”就自动批准正式验收。完整业务评分需要后续独立数据和冻结协议。

退出码 `1` 表示存在工程失败，`2` 表示仍有待验收项；后者不能改写为已通过正式验收。多个实时实验目录并存时必须显式指定实验，禁止默认挑选成功的一轮。

首版契约将“同 Pod 独立请求”的输入数固定为 4，这是把历史观测值误写为不变量。实际探针交替产生慢成功请求与快失败请求，10 秒窗口中均值可能跨越 100、200、300 ms 的不同阈值，原有实验脚本本就允许 2～4 条告警，且必须有延迟和错误两类、保持两组。本轮观察到 3→2 与 4→2 后，按这个已有协议形成 `contract-v2.json`，保留原契约、原评分器和首版失败判定。修正后的标签不放宽两类请求不得混并的约束；新增反例检查允许的三种条数、范围外条数及强制错误归并。本次修订发生在看到运行数据之后，因此不能宣称完全预注册的独立留出验收。

## 正式效果验收仍需的数据

应按 incident / campaign 建立独立数据清单，并把同事故的重复导出、改写、翻译及相邻窗口固定在同一数据划分。至少需要原始告警及来源时间、实体与事故轮次、通知/模板归组标签、候选关联与事故成员标签、根因实体或多根因集合、关键证据引用，以及标签来源与人工复核记录。未知关系保留未知，不能直接当负例。

在执行前约定误合并代价、关键证据保留要求、根因评分口径及样本量、质量非劣界限、并发负载与延迟目标。固定同一模型、工具、知识时点和预算，比较原始证据与压缩证据的完整诊断，统计失败、超时、延期、全部调用及实际供应商用量；跨任务缓存不作为基础告警验收前置条件。
