# 告警审核跨扫描复用观测验证（2026-10-16）

## 当前交付

本轮在[预算利用与恢复候选](alert-review-resume-20261016.md)基础上，为持久告警任务接入审核观测记录。每次实际拟执行的审核批次，在调用前保存输入和运行条件指纹，完成 checkpoint 后保存结果类别；下一作业遇到相同条件时只计数，仍执行当前模型审核。

**这不是已启用的跨扫描缓存。** `reuse_allowed` 固定为 `false`，`reused_pairs` 固定为 0，没有读取旧模型答复代替本次审核的路径。当前交付用于积累[缓存接入条件](../research/alert-review-cache-readiness-20261016.md)所缺的批次级观测证据。生产没有更新，本轮没有 commit、push 或真实模型调用。

## 记录及匹配规则

新增 `agents/alert_review_observations.py` 和 SQLite `review_observations` 表。新增表只记录 job/批次位置、随机记录 ID、时间、结果类别、指纹与计数，不复制原始告警、提示全文或模型答复。既有 prepared 快照和 checkpoint 继续保存原本的证据。checkpoint 的 `observation_id` 连接到对应尝试，重试不会覆盖前次观测。

指纹包含完整有序 messages、system 提示、当前批次相关组的全部原始成员与分组状态、来源、模型名称、服务地址、temperature、实际预留的输出上限、`thinking=False`、客户端类型，以及 8 个相关实现文件的内容摘要。组内没有进入提示样本的原始字段也参与指纹；因此不能通过截断样本或忽略数值获得相等判断。

所有模型名、服务地址、版本声明和证据内容仅保存 SHA256；不会读取 API key 作为身份字段。`AGENTICSRE_ALERT_REVIEW_MODEL_REVISION` 可由运行环境提供非敏感的模型部署 revision 声明，未设置时记录 `model_revision_missing`。这个值是运维声明，不是供应商不可变模型版本的自动验证；本轮没有修改生产环境配置。

匹配仅搜索**同一任务库、不同 job、相同批次与运行条件、此前完成且未出现引用拒绝**的记录。300 秒从前次请求观测开始时间计算，是测量窗口，不是已批准的缓存有效期；读取不会刷新前次时间，未完成和未来时间记录不构成成功匹配。模型、服务、temperature 或实体身份不完整时不做相等匹配。

结果类别分别为 `relations`、`empty`、`rejected`、`failed`、`incomplete`。`relations` 仅表示提出了通过当前引用约束的未验证关系；`empty` 仅表示返回空关系数组；二者分别计数，不改写为因果已证实或已证明无关。失败、含拒绝引用或未完成记录不作为后续成功匹配来源。当前解析器尚未暴露供应商 finish reason，观测结果也不能证明答复没有被供应商截断。

## 接入与失败行为

持久任务 GET 响应增加 `review_observation` 汇总；发布结果的 `semantic.review_observation` 保存当次汇总。字段包括观测尝试数、各结果类别数量、此前非空/空答复的相同请求数、对应候选对数，以及尚不能复用的原因。计数描述的是观测当时的状态，不是当前有效缓存数。同步扫描接口尚未接入该观测表。

旧任务不推断或回填缺失的历史版本。成功 checkpoint 恢复仍沿用原机制，不重新调用模型或增加观测尝试。若重试失败批次时模型配置改变，则新增不同指纹的记录，保存前次配置的证据。

观测写入失败时仅增加 `observation_errors`，不把异常文本写入结果，也不阻断本来可以继续的审核；观测表查询不可用时返回 `status=unavailable`。新表写锁等待上限为 100 ms。观测和提示处理的耗时包含在作业截止时间内，若调用前已过期，则不再向模型发出请求。调用前的预算预留仍是保守上限，不能当供应商实际请求数或计费。

单作业新增记录数受既有模型调用预算约束，上限为 100 次；历史记录随持久作业累积。本轮尚未增加跨作业历史清理策略，正式长期采集前还需确定留存与归档规则。

## 受控对照及开销

基线为上一轮恢复候选 r3，观测候选为本轮 r1。两组各执行 30 个串行持久作业，每作业使用相同 4 条合成告警和 3 对候选，模型替身固定返回具有合法双方引用的未验证关系；每组在独立目录先执行 1 次预热作业，预热不进入统计。全量回归结束后再执行该对照，避免与本轮测试并行争用资源。

| 指标 | 基线 | 观测候选 |
|---|---:|---:|
| 测量作业数 / 模型替身调用数 | 30 / 30 | 30 / 30 |
| 每作业保留原始告警 / 完成候选对 | 4 / 3 | 4 / 3 |
| 此前成功的相同非空请求 | 未记录 | 29 |
| 上述重复请求包含候选对 | 未记录 | 87 |
| 实际跨扫描复用候选对 | 0 | 0 |
| 完整作业中位耗时 | 80.471 ms | 94.312 ms |
| 完整作业 p95 耗时 | 96.848 ms | 113.624 ms |

这次小样本测量中，中位耗时增加 13.841 ms，p95 增加 16.776 ms，包含持久作业、SQL 和文件 I/O。两组在同一远程主机上顺序执行，没有随机交错或置信区间；不能把差值当成稳定性能保证。首次预热作业分别为 91.849 ms 和 166.987 ms，包含首次导入/指纹工作，单次数据不用于冷启动结论。

这些完全重复的合成输入只验证计数与调用路径：29 次重复不代表真实生产命中率，更不能承诺节省 29 次模型调用。观测版仍调用 30 次，所有关系保持 `unverified`。供应商延迟、实际 token、计费和诊断准确率均未测量。

另用实际候选 ASGI 路由读取两个合成持久作业，验证空关系重复单独计为 `prior_empty_requests=1`，两次模型调用均执行；job/summary 中汇总一致，原文分页仍返回全部 2 条告警。该验证使用进程内 TestClient，没有连接正式生产 API。
