# 缩零调查中的 HPA 观测与候选复核

一次真实缩零调查中，模型提出需要区分手工操作和自动扩缩容；同时独立审核把 Deployment 副本为零当作排除 Service 选择器不匹配和网络策略问题的直接反证。当前零副本只能说明当时没有所需副本，不能证明这些机制在其他时刻不存在。

事件采集在结构化工作负载观测确认 Deployment 为零副本时，额外只读查询同命名空间 HPA，记录当前按名称引用该 Deployment 的 HPA 身份与配置；调用失败、分页、格式或身份不完整时记录未知，不构造“没有 HPA”的事实。HPA 的目标引用按名称关联，并非 UID 级证明；Deployment 和 HPA 查询也不是原子快照。当前配置不证明历史配置、缩容执行者或缩容原因，审计信息不足时继续要求复核。

对独立审核，若针对选择器错配、网络策略或 Pod 状态的反驳只引用零副本观测，则将审核意见保留为 `uncertain`，并记录原因；有独立类型化反证的情形不以该规则否定。此规则仅覆盖有限机制描述和指定观测类型，不是通用语义蕴含验证器，不授权自动恢复。

真实非生产环境的只读预检中，目标 Deployment 的当前 HPA 名称匹配结果与独立 Kubernetes API 查询一致；该预检不是故障注入，也不能推断历史。远端隔离环境执行 130 项相关测试通过，另有 4 条既有依赖弃用警告。测试包含采集失败、分页、对象身份冲突以及事件采集集成。

后续进行一次非生产真实缩零：实际自动诊断记录了 4 条同目标的重复 HPA 采集观测，均显示当前无匹配 HPA；它们属于一次故障，不是独立样本。诊断对象 UID 与独立目标一致，但独立审核未完成、模型预算耗尽，自动恢复门禁保持关闭。控制器回退后，三个窗口各 10 组目标与对照业务检查成功；该回退不是自主自愈。最终代码随后增加了非原子时间标记，并通过上述回归及真实只读预检；这次故障运行的候选快照尚无该标记。
