# 经请求集合重建验证的窗口归并

## 问题与方法

持续负载下，单请求 Trace 标签不断变化，曾使指标证据不可用；改为稳定 Pod 窗口指标后，同指标阈值压缩达到 9→5，但延迟和错误率缺少跨指标归并证据。直接把同 Pod、同时异常的两条指标合并会误伤已验证的“慢但成功”与“快速失败”独立请求反例。

新增 `agents/alert_window_merge.py`。先执行既有同指标阈值归并，再对显式启用窗口协议的两类测量建立证明：读取同一求值时刻的窗口截止时间和请求总数，查询实际 Jaeger 请求，用当前 Kubernetes Pod UID 绑定，重建窗口平均延迟和错误率。只有窗口内已观察请求数与独立计数一致、每个请求均为 HTTP 5xx 且超过所有已触发延迟阈值、重算均值误差不超过 0.01 ms、错误率严格为 1 时，才把两类测量归为同一批异常请求的观测。

归并不等于根因确认。结果 `causal_confirmed=false`，延迟与错误率以 composite 保留各自单位、规则和原始时序，不能相加或混成一条指标。原始告警、critical、原分组、请求 Span 和测量证据引用全部保留。前端显示请求数量、窗口与证据边界，模型取得两份独立指标摘要。

## 显式接入协议

只支持完整实时扫描、同集群/namespace/Pod/标签维度、唯一健康 firing 规则及 ready 的简单比较测量。规则需具有以下注解：

```yaml
agenticsre_window_contract: pod_request_window_v1
agenticsre_window_field: mean_duration_ms # 或 error_ratio
agenticsre_window_seconds: "10"
agenticsre_window_count_metric: request_window_count
agenticsre_window_end_metric: request_window_end_seconds
agenticsre_window_operation: "measured GET /probe"
```

伴随指标名必须是简单合法 Prometheus 指标名，由采集器绑定相同 namespace、pod、job、instance 等全部时序维度。计数和截止时间必须对应同一批请求完成时间，且与两份窗口测量来自同一求值锚点；当前协议限定 Jaeger service 名称等于 Pod 实体名称，operation 与注解匹配。窗口范围为 `(截止时间−窗口长度, 截止时间]`，计入请求结束时间。

仅允许 namespace、pod、job、instance、cluster_id 这些已限定含义的测量维度。路由、租户等请求分区维度尚未逐项映射到 Trace，出现时拒绝归并。仅计入对应 service/operation 的 `span.kind=server` 请求，客户端或内部 Span 不得补足请求数。计数协议必须覆盖该 Pod 和操作的全部服务端请求。

采集从当前实际 Prometheus 后端和已配置 Jaeger 后端进行，不接受注解指定任意 URL。窗口长度 1–60 秒，请求数 2–200；单次最多验证三个候选实体，Jaeger 查询最多 201 条，达到上限则拒绝归并。最近样本和窗口截止时间必须满足两秒新鲜度检查。因此当前协议适用于本次一秒抓取的实验，不能直接宣称适配所有抓取周期和生产埋点。

不是通用 PromQL 推断，也不把代表性 Trace 当作完整窗口。没有这些元数据的现网规则保持既有行为。本次未修改正式业务规则以制造条件。

## 拒绝条件与状态

导入/人工编辑/降级数据、不同实体或维度、缺指标、缺 Trace、数量不匹配、重复 Span、响应截断、旧 Pod UID、窗口过期、均值不一致、错误率不为 1、存在健康请求或慢请求与错误请求不重叠，均不能取得窗口归并授权。完整请求覆盖与全部联合异常是保守前提，不将部分采样外推为完整事故。

新结果包含 `window_evidence` 和 `window_compression`。分组历史使用签名版本 5，签名纳入窗口协议，避免沿用不同定义的历史基线。人工拆分或合并后，窗口证明和自动归并状态失效。

## 验证口径

初版新增十九项单元测试，包含阈值后窗口归并、原文和最高严重度保留、模型独立测量、证据包、人工拆分失效与十余种拒绝条件。远端初版全量回归 811 passed / 110.16 秒；补充签名与人工编辑处理后回归 811 passed / 106.05 秒。随后复核增加未映射请求分区、不同服务和非服务端 Span 的三个拒绝测试，最终版本远端全量回归 **815 passed / 110.55 秒**，包含 22 项窗口测试和 1 项探针原子记录测试。存在既有弃用警告。

实际实验入口为 `eval/window_alert_acceptance.py`。使用实际请求、实际 Prometheus 告警、真实 Jaeger 和实时扫描 API，不上传预制告警。设置 `AGENTICSRE_RUN_TRACE_ALERT_EXPERIMENT=1`、`AGENTICSRE_RUN_WINDOW_EXPERIMENT=1`，以 `AGENTICSRE_EXPERIMENT_ROOT` 和 `AGENTICSRE_EXPERIMENT_IMAGE` 指定隔离候选版本；追加 `AGENTICSRE_WINDOW_BOUNDARIES=1` 运行同 Pod 独立请求、缺 Trace、负载突增反例。

目标为正例单点 4→1、多点 9→3；同 Pod 不重叠请求必须仍为两组；缺 Trace 必须退回阈值归并 9→5；负载突增在证据完整时目标 9→3。所有目标还要求原文、critical、实体边界和存储回读正确。

初版实测 `5f46adf8`：1,583 个真实请求、12 次扫描，正例两次 4→1、两次 9→3，复发两次 4→1，正常及恢复为零告警。多点每次分别重建 A/B 各 11 个实际请求，计数、平均延迟及错误率均匹配。全部保留断言通过，正式生命周期记录不变，实验资源已清理。该轮在服务端 Span 和额外请求分区约束补充前执行，作为初版证据保留，不能替代最终版本实测。

初版边界运行 `d11573d0` 在突增阶段未通过 9→3 目标，实际为 9→4；一个 Pod 因 `mean duration reconstruction mismatch` 拒绝窗口归并。原文保留，实验 namespace 和容器已清理，该失败不计为通过。

随后查出探针的可复现时序缺陷：先记录 Span 的处理结束时间，再等待 OTLP 导出完成，最后才把该请求加入指标窗口。并发抓取期间，已结束处理的请求可能仍缺席窗口。新增远端阻塞导出测试，修复前窗口计数为 0、断言失败（`probe-red.log`）；修复后，将 Span 结束时间与窗口成员入队放进同一个锁内、先完成原子记录再导出，测试通过（`probe-green.log`，1 passed / 0.60 秒）。窗口采样还按结束时间显式过滤，避免并发顺序或边界残留造成集合不一致。没有放宽计数一致性或 0.01 ms 的重算门槛。最终版本已重新执行包含突增场景的完整实际验收，结果见下。


## 最终版本实际验收

实验 `cb10b710` 使用最终候选镜像，在远端 snail 上运行实际 HTTP 请求、Prometheus 规则求值、Jaeger 采集和实时扫描 API。共 **2,723 次请求、16 次扫描、424.29 秒**，八阶段均通过。每阶段持续施加负载后连续扫描两次，无重试挑选结果。

| 场景 | 实际请求/秒 | 两次扫描结果 | 结论 |
|---|---:|---|---|
| 健康负载 | 5.64 | 0→0、0→0 | 无误报 |
| 单点异常 | 4.89 | 4→1、4→1 | 75% 压缩 |
| 多点独立异常 | 4.13 | 9→3、9→3 | 66.67% 压缩，实体隔离 |

| 关闭 Trace 导出 | 4.18 | 9→5、9→5 | 44.44%，安全退回阈值归并 |
| 负载突增 | 16.51 | 9→3、9→3 | 66.67% 压缩 |
| 异常复发 | 4.90 | 4→1、4→1 | 75% 压缩 |
| 最终恢复 | 5.65 | 0→0、0→0 | 告警清零 |

请求集合与计数、均值和错误率重建匹配，原文、最高严重度、独立实体和存储回读断言全部通过。缺 Trace 和独立请求场景没有获得窗口归并授权。模型共调用 8 次，模型提案不构成窗口归并凭据。正式生命周期未改变，实验 namespace、容器和临时配置副本已清理。

该结果证明显式窗口协议下的受控实际负载场景达到本次目标。它不代表自然生产事故的压缩率，也不证明跨服务因果传播、根因准确率或 1000× 压缩目标。原业务规则没有窗口协议时仍使用已有方法。
