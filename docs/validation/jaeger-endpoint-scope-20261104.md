# 链路后端作用域与酒店业务只读预检

当用户显式配置 Jaeger 地址时，旧自动发现逻辑先读取该地址的服务列表；如果不含特定社交应用服务名，便扫描其他后端并优先选择含这些名称的实例。即使已配置的酒店后端健康，也可能被替换成另一个应用的后端；配置地址不可用时也可能静默跨作用域回退。远程隔离回归对这两种情况均在修改前复现。

现在显式配置的地址始终作为目标；后端不可用时返回工具错误，不以其他应用的数据冒充所配置的来源。只有未配置地址时保留既有自动发现流程。依赖旧隐式跨后端回退的部署需要修正配置；此修改不证明自动发现所选后端属于调用方期望的租户。

在非生产酒店应用的只读预检中，12 次业务请求均成功返回非空结果，12 条请求通过各自携带的 Trace ID 在酒店链路存储中找到对应链路，均涉及 frontend、search、geo、rate、profile 和 reservation。实际 JaegerTool 对配置的酒店后端成功读取其中一条对应链路。12 条样本只用于可行性预检，不代表正式性能测量或瓶颈因果证明。

该环境的预检链路进程属性没有 `k8s.namespace.name`；TraceAgent 的精确链路路径因此未返回同命名空间 Span 证据，按设计保持未验证，而不是把缺失属性当作目标命名空间。需要可信、可核对的资源归属数据后才能完成对象级关联。本轮远程相关回归 144 项通过。
