# 告警压缩首版：实现范围与远端验收

## 结论与范围

本次实现的是保守的重复告警分组、可追溯证据包、人工调整和多智能体 RCA 接入，**不是原架构图全部方法的实现**。自动分组不等价于因果关联，也不抑制或删除原始告警。

| 原设计方法 | 本次状态 | 实际边界 |
|---|---|---|
| 统一事件与语义解析 | 部分实现 | 统一集群、命名空间、实体、来源、类型、时间、严重性和原文；尚无本体解析或通用症状/条件/影响抽取 |
| 符号压缩与异常排名 | 部分实现 | 相同对象、类型、消息、来源、生命周期状态的重复通知聚合；未实现指标去重、日志模板聚类、频率偏移排名 |
| 语义候选召回 | 未实现原设计 | 目前只筛选同对象、时间相邻的至多 20 对分组；尚无 Embedding Top-N 或跨对象语义召回 |
| LLM 关联建议 | 首版接口已验证 | 实际模型返回 1 条引用两侧样本的待验证关联；两个分组保持独立；尚未评估大样本关系准确率 |
| 事故证据包 | 已实现首版 | 保留所有原文；诊断输入提供首条、最高严重性代表、末条、严重性变化、时间范围及原始记录引用 |
| SCAG 多层图和六类关系 | 未实现 | 现有 RCA 图能力不能算作本次 SCAG 实现 |
| 结构、统计、时间三重验证 | 未实现 | 当前集群/对象/时间约束只是分组边界，不是因果验证 |
| 假设—验证 RCA | 接入现有系统 | 按服务器端分组版本生成证据包，进入已有多智能体调查；没有另建图中完整诊断状态机 |
| 人工拆分、合并 | 已实现首版 | 记录原因和历史版本，拒绝过期修改、跨集群/命名空间或超时间窗合并；尚未从反馈学习分组策略 |
| 持续演化、数字孪生、红队治理 | 未新增 | 本次故障注入是验收实验，不是数字孪生或持续学习系统 |

因此，不能以本次重复通知回放压缩率宣称完整语义压缩准确率、根因准确率或“1000 倍压缩”已达标。

## 使用入口与数据路径

页面入口：**通算告警 → 智能压缩**。支持展开原文、选中成员拆出、选中多个事件组合并、证据包诊断。人工调整必须填写原因。

API：

- `GET /api/alerts/scan`：采集并保存扫描结果，可指定集群和命名空间。
- `POST /api/alerts/compress`：接收 `alerts`、集群、命名空间、时间窗，默认只做确定性分组；`semantic: true` 请求可选关联建议。
- `GET /api/alerts/compression/{scan_id}`：读取完整原文、分组及调整历史。
- `POST /api/alerts/compression/{scan_id}/edit`：提交 `revision`、`action`、`group_ids`、`alert_ids` 和 `reason`。
- `POST /api/rca/run`：提交 `alert_group: {scan_id, group_id, revision}`。服务端读取证据包，拒绝过期版本与请求范围不一致。

扫描保存于持久化数据目录 `data/alert_compression/`。本次已检查发布重启后，100 条记录、1 个分组、版本 3 和 2 次修改历史仍可读取。文件原子替换，人工编辑使用进程间锁和版本检查。证据包的文本样本和引用列表有长度上限，并附截断/总数信息；完整原文仍留在扫描记录中。尚无自动过期清理策略。

默认时间窗 300 秒，可设置为 1–3600 秒；单批最多 10000 条。时间窗按组最早时间约束，避免相邻告警无限串联。缺少集群、实体或有效时间的记录单独保留；Pod、Deployment、Service 缺少命名空间也不自动合并。

## 远端验证方法

所有运行验收位于 `snail`，本地仅编辑、打包和通过 SSH 隧道访问远端页面。

1. 基于上一版本镜像启动隔离测试容器，挂载本次源代码，使用 `--network none` 运行完整回归。
2. 运行 `scripts/evaluate_alert_compression.py`：12 组独立重复通知，每组 100 条，加 8 条稀有关键告警。独立标签用于计算告警对精确率、召回率、误合并及保留情况。
3. 运行 `tests/e2e/test_live_alert_compression.py`：在带所有权标签的独占命名空间创建真实镜像拉取故障，将一条真实观测事件模拟重复投递 100 次；调用实际压缩、持久化、拆分、合并和 RCA API；用相同故障依次比较原始输入与证据包输入。
4. 使用浏览器经 SSH 隧道操作远端页面，验证实际拆分、合并与原文转义。
5. 比较两个发布容器的源码 SHA、健康状态，以及 AgenticOps 容器 ID 和启动时间。

## 验收中发现并修复的问题

1. 浏览器仍缓存旧 `app.js?v=130`：更新为 `v=131`，并增加语义关联未完成的页面提示。
2. 原扫描串行采集在 8 秒总预算内无法完成：改为各来源并行、独立 20 秒限时，成功来源保留，失败来源明确提示；外层采集预算至少 25 秒。
3. 原外层压缩预算 12 秒短于内部模型等待预算：外层现在至少为语义等待预算加 5 秒。
4. 真实模型返回 JSON 数组，原适配器要求对象：现在兼容数组和带 `relations` 的对象，仍逐条校验候选组及两侧原始证据引用；无合法结构的响应不能记为成功。

用户授权增加模型预算后，配置调整为：语义关联 60 秒；RCA 总预算 900 秒；单次 RCA 模型调用 120 秒；协作复核 90 秒。语义预算可通过 `alert.semantic_timeout_s` 调整，运行时约束为 1–180 秒。此项增大的是等待时间，没有扩大语义候选范围或实现缺失的算法。
