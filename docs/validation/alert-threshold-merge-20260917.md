# 同指标嵌套阈值归并与真实复验

## 本轮实现

新增 `agents/alert_thresholds.py`，在实时指标采集完成后、最终语义提议与图检查前执行。仅接受 live_scan 中来自实际唯一 firing 规则、状态 ready 的单指标选择器比较证据。对象、命名空间、集群、告警状态、原始维度标签、比较方向、选择器、实际查询、序列标签、采样窗口、步长和数值历史必须一致；阈值须不同，整组原始时间跨度不得超过分组窗口。

不将显式测量注解、复杂表达式、未取得完整历史或导入数据作为自动归并依据。不归并不同指标、不同对象、不同维度、不同方向或跨时间窗告警。规则名和严重度可以不同；最高严重度、全部原始记录与规则引用保留。该结构关系不等于根因确认。

新组重新计算分组计数、召回和关联图；指标证据绑定到新组并保留每条原规则、原分组与证据引用。证据包与前端新增归并依据。对归并快照使用新的历史签名版本，防止直接把多规则合计与旧单规则基线比较；在扫描流程中重新应用匹配版本的历史基线，历史不足时明确 warming_up。

## 固定实验的实际结果

沿用上一轮阈值实验，不改变原先“九条归为三个跨指标事件”的目标。新增嵌套阈值子目标单独记录，不能取代原目标。

远端实际实验目录 `thresholdmerge-20260917/4523ff6b`，命名空间标签 `agenticsre-threshold-4523ff6b`；使用真实 HTTP 请求、测量延迟、503 响应、独立 Prometheus 和实际扫描 API，非告警 JSON 注入。

| 阶段 | 改动前 | 改动后 | 说明 |
| --- | --- | --- | --- |
| 单阈值 | 1 → 1 | 1 → 1 | 不制造压缩 |
| 双阈值的初始阶段 | 2 → 2 | 2 → 2 | 历史尚不足，不自动归并 |
| A/B 多阈值及 503 + 独立 critical | 9 → 9 | **9 → 5** | 条数减少 **44.44%**，两组三级延迟阈值分别归并 |
| 恢复后跨窗口重新触发 A | 4 → 4 | **4 → 2** | 条数减少 **50%**，延迟与 HTTP 失败仍分开 |

九条原始告警全部保留、成员唯一、存储回读一致；三条 critical 保留，无跨对象合并。九组原始指标证据映射至五个新组；模型完成归并后全部六对检索候选，无失败。再次触发完成一对候选，四条原告警均进入新的事件轮次。两次恢复扫描确实无 firing。

嵌套阈值子目标通过。**原三事件目标仍未通过**：实际五组，对原先跨指标事件真值的配对召回为 50%，未达到 95%。缺口是跨指标同事件归并，本轮不因同对象、同步触发或 LLM 假设就自动消除这个差异。

正式服务原有 25 条生命周期记录在实验前后相同。实验三个容器和配置副本已清理；没有修改正式 Prometheus 规则。
