# 自愈知识发布审核验证

## 行为变化

此前保存策略或恢复历史会立即改变生效知识，只限制后续自愈动作的执行。本次将知识发布和动作执行分开：

1. 编辑与历史恢复先创建 `pending` 草稿，生效库及其版本不变；草稿持久化后重启仍保持待审核。
2. 审核界面展示修改前后内容。通过审核才发布；驳回不改变生效库。
3. 审核绑定草稿 ID、内容 SHA-256 和生效库的基线版本。过期版本、错误哈希、重复审批返回冲突，不覆盖新内容。
4. 发布、草稿状态更新、版本历史写入在同一文件锁和原子替换中完成；写入失败时仍保留原状态。
5. 发布后仍是待验证策略，保留审批要求、禁止自动恢复；发布本身不执行集群操作。

新增 `GET /api/heal/recipe-drafts` 和 `POST /api/heal/recipe-drafts/{draft_id}/decision`。
原有 PUT/restore 仍返回 `status=ok`，但增加 `publication_status=pending` 和 `draft`，不再返回已发布策略；调用方必须完成审核后才能认为修改已生效。
同一策略只允许一个待审核草稿，过期草稿需驳回后重新提交；全库最多 100 个待审核草稿，另保留最近 100 个已处理草稿。

## 身份与权限范围

沿用系统现有登录中间件。启用登录时，审核记录使用服务端会话账户或 API token 身份，客户端填写的名称不能覆盖它。
未启用登录时，审核名称仅作操作记录，标记为 `operator_label`，不代表认证身份。
这不是双人复核或完整 RBAC：尚未强制编辑者与审核者分离，也未新增角色体系。

## 远端验证

所有运行与浏览器验证均在 snail，旧镜像复现保存立即发布、不返回草稿的旧行为。
专项测试覆盖草稿隔离、发布精确内容、审核记录、驳回、重复审批、错误哈希、过期基线、写入失败、历史恢复审批及认证账户绑定。
最终 28 项专项测试通过；远端全量 **944 passed / 209.47 秒**，32940 条既有依赖/AST 等警告。加入账户绑定前的中间版本为 943 passed / 206.66 秒，最终版本另行完成全量验证。

真实 HTTP/浏览器完成编辑、审核通过、驳回、恢复修改前后并分别审核；独立 Skill Runtime 在审核前读取旧策略，审核后才使用新动作。
两个并发提交分别返回 200/409，两个并发审批也返回 200/409；重启后草稿仍待审核、生效内容未变化，随后审核发布成功。
桌面和 390px 移动端无脚本错误、无横向溢出。测试容器均清理，未注入生产故障。

另以隔离服务启用真实 HTTP 登录：未登录访问返回 401，登录后提交与账户不同的审核名称，最终记录仍绑定服务端账户并标记 `authenticated_session`。未修改生产登录配置。
