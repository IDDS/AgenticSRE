# 补证阶段的报告证据约束

根因报告在首次生成之后可能由补证阶段重新生成。此前首次报告提示包含身份和证据边界，但普通补证提示没有这些具体约束，且 JSON 示例将根因对象的 `kind` 固定为 `Pod`；告警补证路径使用另一套提示。因此首次提示不能约束补证模型的最终输出。

补证两条路径现在均提示区分对象 UID、独立验证对象关联、将同时出现的状态与已证实因果区分开，并在证据不足时保留机制待验证；普通路径的对象类型示例改为由观测决定。模型可能不遵循提示，独立审核、证据校验和自动动作门禁仍然必要，这项修改不证明因果结论正确。

远程新增的两条回归先在原实现上失败，修改后连同相关身份绑定、告警溯源、补证和审核测试共 198 项通过。测试验证模型调用收到的合同，不能代替真实模型和现场故障验证。

同一非生产服务进行了修订后的真实缩零复测，检测上界为 0.846867 秒，注入开始后 119.650 秒返回 UID 与独立目标一致的 Deployment 候选。17 次模型调用完整，调用记录显示补证阶段执行；候选审核有记录且覆盖全部候选。模型撤回“被显式设置”的说法，但仍把两个同时观测到的状态表述为直接因果，并将两次相同观测概括为整个窗口内稳定：前者需要关系与因果证据，后者不能仅凭两个采样点证明。诊断仍因调查缺口要求复核，自动恢复门禁关闭。

故障期间业务异常已观察到，独立看门狗就绪，控制器回退后目标与对照业务连续三个窗口各 10 组检查成功。控制器回退不是自主自愈；同一故障机制的单次复测不能证明模型总会遵循提示、总体准确率或正式验收通过。运行结束后 SSH 一度超时，恢复连接后取回了诊断详情和模型调用记录。
