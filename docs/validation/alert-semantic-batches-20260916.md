# 告警候选关系的完整分批处理

发布进展：本文改动已随 `0f90dd7` 部署，详见 [异步任务与部署验收](alert-jobs-deployment-20260916.md)。下文保留各轮测试当时的状态。

## 改动

本轮继续补齐原设计的语义关系验证链路。默认不再把向量召回候选截为 200 对；模型以每批最多 20 对顺序处理全部已召回候选。20 是单次上下文大小，不再是整次扫描总量。每批拥有独立超时，失败后继续后续批次，记录失败位置和数量。取消请求会传播取消信号，不再启动下一批。

API 验收发现第二处隐藏截断：`recall_context` 会把上游候选重新限制为 200 对，且仅匹配前 256 组的 Trace/变更上下文。本轮移除该模块的组、候选、已收集链接及变更目标的二次截断，并拒绝生成组自身的关联。

`semantic.completed_pairs` 表示所属批次已得到合法关系数组响应的候选数，允许模型返回空数组；不表示这些候选已证明存在关系。`failed_pairs`、`batches`、`coverage_complete` 和 `coverage_scope=retrieved_candidate_pairs` 一同报告。上游显式截断时不标为完整覆盖。

模型的证据引用仅能来自当前批次给定的候选两端。其他批次或虚构的引用无法通过检查。所有接受的关系仍为 unverified，原始分组、原文、高危级别和因果验证边界不变。

## 验证方法与边界

全部测试在远端 `snail` 运行。隔离镜像 `agenticsre:semantic-batches-20260916`，独立数据目录和 18086 端口；生产版本尚未替换。

新增回归覆盖 45 对候选分为 20/20/5 三批、第二批失败仍处理尾批、跨批次伪造引用拒绝、上游截断状态、取消传播、默认超过 200 对以及排名 256 之后的 Trace 关联。API 压力测试明确检查返回候选数与实际召回数一致，避免仅凭单元测试宣称链路修复完成。

真实模型使用受控的 12 个独立对象、45 对候选，验证三次调用均完成；原文一致、组数仍为 12。该样本没有提供共同根因证据，模型返回零关联不能用于证明正例召回能力或因果识别准确率。

## 最终候选实测

最终候选完整回归 **639 passed，105.50 秒**，相对上一轮 633 项新增 6 项回归用例。现有依赖弃用警告仍存在。本轮隔离容器已清理，生产主服务与 Skill runtime 仍为原镜像且 healthy，未将本候选部署到生产。

- 10,000 条重复通知保留 100 组，485 对候选完整返回。
- 10,000 条独立对象保留 10,000 组，向量覆盖 10,000/10,000，49,985 对候选完整返回；26.450 秒，响应 61,917,953 字节。此压力请求关闭 LLM，不能声称已调用模型验证全部 49,985 对。
- 并发真实模型请求：12 组、45 对候选，20/20/5 三批全部完成，6.973 秒，接受零关系，原文一致。
- 万组扫描的历史读取响应与创建响应逐字节相同，验证存储和读取契约未变。
- 同一轮 46 次健康接口请求全部成功，最大 1.686 秒、平均 0.171 秒；这不是稳定 P95 或生产 SLA。

取消截断后暴露了同步图构建、结果落盘和大响应编码的事件循环阻塞，初版健康请求超过 10 秒而失败。将这些步骤移到后台线程，压缩创建及历史读取接口直接返回已编码 JSON，避免 FastAPI 在主循环重复递归编码。上述并发结果来自修复后的同一镜像。初版超时证据保留，未降低健康检查阈值。响应体仍较大，不能将消除阻塞等同于完成分页和异步任务。

## 尚未完成的工作

- 当前覆盖是全部“已经召回的候选”，不是穷尽所有可能关系。Top-N 和大范围近似向量检索仍存在召回边界。
- Trace、变更的上游采集仍有自身限制及截断状态；本轮没有宣称全部观测源完整采集。
- 大规模真实模型处理仍是同步 HTTP 请求中的顺序批次。取消总量截断后，万组场景可能产生数千次调用；尚需异步任务、持久化进度与中断恢复，才能适合长时运行。
- 需要真实多源故障正例、人工标注与传播路径验收，不能由“全部候选均提交模型”推断原架构完全实现。

费用与 Token 总预算不作为本轮验收约束；每次请求保留输出长度与响应时限，以适配模型接口并识别失败。
