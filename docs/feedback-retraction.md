# 反馈撤销与后续消费隔离

2026-10-22，接续候选审核。本轮提供反馈撤销、直接派生规则隔离和明确归因的规则票据隔离。原诊断、专家原文和学习收据保留。修订通过撤销旧意见、显式提交新反馈完成，没有原地改写或自动重新训练。

## 权威状态与并发

反馈账本同一条记录同时保存feedback_state、feedback_seq和feedback_history。撤销在feedback.lock下重读、校验版本并原子替换账本；规则召回与审核直接读取这份权威状态，JSON规则和Chroma均不依赖第二次传播写入。相同事件和内容返回原撤销记录，改写事件内容、旧版本或重复新事件返回409。落盘失败返回503，不声称完成。

`POST /api/knowledge/feedback/{feedback_id}/retract`接受revision、reviewer、reason、event_id。GET反馈返回feedback_revision及撤销历史。feedback_revision绑定原请求和撤销序号，不随模型完成变化，因此可以撤销仍在处理的反馈。模型调用期间不持有账本锁；迟到的学习结果保存前合并当前撤销状态，不能覆盖撤销历史。晚到或重复提取的新规则仍受相同source_feedback_id门禁约束。

这保证撤销完成后开始的新召回不使用受影响规则。已经组装的上下文、正在执行的模型调用和历史调查不被追溯改写。本轮没有分布式消息撤回或强制中止正在运行的调查。

## 规则及票数

source_feedback_id关联的规则，在来源撤销、缺失或学习结果未确认时不能启用和消费。直接派生来源不能通过普通编辑去掉；原审批重放也不改变实际准入。规则的原status及历史保留，API实际状态为source_blocked，附source_block_reason。这使来源撤销不必逐条改写Chroma，新增、编辑及其他进程读取均遵循同一门禁。

新显式规则投票把反馈ID与当前规则版本一起归因。反馈撤销后，受这些票数影响的规则先隔离；原正负票和历史保留，不执行无法可靠核对的减票。旧版反馈收据中已确认投出的票，也按原rule_id/revision隔离；无法从历史恢复的来源不伪造。人工编辑新版本后当前票数归零、旧票进入lifetime，再经新审核可复用，但直接派生规则仍受原来源撤销约束。

本轮没有任意深度的知识依赖图。无source_feedback_id的旧知识、未记录来源的人工复制或模型隐含引用，无法自动恢复其血缘并递归撤销；应保留候选隔离并另行审查。source_blocked数量单独报告；平均quality_score仅统计当前可消费规则，不能把隔离规则的旧高分当作当前收益。

## 统计与配置

撤销标签不参与新的诊断统计。同一事故的较新反馈撤销后，不静默回退到旧标签；显式提交新的有效反馈后再形成当前样本。统计仍是模型与专家文本的比较，independent_truth_verified=false。生成数保留历史实际写入语义，不因撤销假装规则从未生成，也不表示当前启用量。

所有共享规则库的Web、Skill Runtime、MCP及工作进程必须使用同一持久反馈目录。默认`./data/expert_feedback`；可用`AGENTICSRE_FEEDBACK_DIR`指定共享挂载位置。目录不能指向临时副本。显式构造其他反馈目录时，撤销接口拒绝与消费策略目录不一致的配置。存在来源引用却缺少账本条目时关闭消费；账本损坏或不可读时反馈API返回503，检索报告不可用或返回空结果，不放行依赖知识。无来源引用的可信导入仍遵循原人工审核兼容边界。

读取缓存使用路径、inode、mtime_ns及大小；每次决策重新检查文件身份，原子替换后不沿用旧撤销状态。多主机仅在确实共享同一账本和文件锁语义时适用，没有跨独立副本一致性保证。

撤销依据必填。启用登录时服务端绑定会话用户名或api-token，覆盖请求标签；未登录部署记录operator_label，不声称身份已验证。未新增细粒度授权。

## 验证边界

证据保存于`outputs/feedback-retraction-20261022/`，应用测试、真实Chroma和浏览器均在snail执行。模型输出及向量为受控离线夹具，不验证真实事故准确率、模型可用性恢复或独立学习收益。代码没有提交、推送或部署生产。
