# 诊断融合

本 Skill 负责在多个候选根因诊断之间进行融合与排序，输出唯一主根因及其置信度，供后续恢复决策使用。

## 适用场景

- 同一故障被多个诊断 Skill 命中，产生多个候选根因需要仲裁。
- 证据来自不同来源，需要交叉印证。
- 需要区分主诊断与辅助 Skill，避免风险门禁、恢复验证等辅助结论污染主根因。
- 需要为编排层提供统一的置信度与证据链摘要。

## 输入信号

- 候选诊断列表：每项包含 root_cause、confidence、evidence 和来源 Skill ID。
- 证据来源清单：至少 2 个独立来源方可进入融合。
- 各诊断的阶段标签与领域标签，用于识别主诊断与辅助结论。
- 历史相似案例的置信度基线，可选。

## 执行阶段

- `diagnose`: 对候选进行去重、证据交叉验证，按来源数量与一致性加权打分。

候选收集由上游检测和证据采集 Skill 完成；本 Skill 只产出融合诊断。恢复与恢复验证由下游专用 Skill 接管。

## 风险与门禁

- 风险等级 low，仅读取可观测性数据。
- `requires_approval=false`，`safe_auto_execute=true`。
- 至少需要 2 个独立证据来源方可给出主根因。
- 融合置信度低于 0.7 不进入 heal；低于 0.92 不允许自动恢复。
- 不覆盖 `generic.risk_gatekeeper` 的门禁判定，融合结论仍需通过风险门禁。

## 验证方式

- 检查输出是否为唯一主根因且携带证据引用与置信度。
- 校验融合置信度计算是否符合来源加权规则。
- 确认主根因未被辅助结论覆盖。
- 记录融合过程，便于事后回溯与专家反馈。
