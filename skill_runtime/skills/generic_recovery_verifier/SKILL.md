# 通用恢复验证

本 Skill 在恢复动作执行后进行验证，检查服务端点、发布状态、延迟、错误率与 LLM 指标是否回归正常。

## 适用场景

- 恢复动作执行完成，需要确认故障是否真正消除。
- 需要对比恢复前后的关键 SLA 指标。
- 需要判定是否触发回滚或二次恢复。
- 为编排层输出恢复是否成功的最终判定。

## 输入信号

- 目标服务、命名空间、Deployment 与端点标识。
- 恢复前基线指标。
- 发布或滚动更新状态。
- 验证时间窗口与成功判据阈值。

## 执行阶段

- `verify`: 综合端点可用性、rollout 状态、延迟与错误率给出通过或未通过结论。

恢复目标、执行记录和前后基线由上游传入。本 Skill 不执行新的恢复动作，只返回验证结论与失败项。

## 风险与门禁

- 风险等级 low，仅使用 `observability.read` 与 `k8s.read` 只读权限。
- `requires_approval=false`，`safe_auto_execute=true`。
- 至少 1 个指标来源即可判定。
- 仅读取状态与指标，不执行任何变更或回滚操作。

## 验证方式

- 检查是否给出明确的恢复成功或失败结论及依据。
- 校验前后指标对比是否使用一致的时间窗口。
- 确认端点、rollout、延迟、错误率与 LLM 指标均被覆盖。
- 对验证失败项输出后续处置建议。
